# 第 17 讲 结构化写作流水线：系统落地设计

> 来源：`../design_principle/第17讲_结构化写作流水线先骨架后血肉.pdf`
> 落地度：★★★★★（高） ｜ 依赖：第 09 / 10 / 15 讲 ｜ 主体分期：P0
> 主产物：共享表 `稿件`（一行 = 一篇在写的论文，`当前工序` 是它的状态机）+ 表 `17 段落卡`（一行 = 一个段落，主张句与证据清单是它的全部内容）

## 1. 本讲方法要点

1. **写作不是文学创作，是装配流程**。多数新手按阅读顺序写作（引言、相关工作、方法、实验、结论）——这恰恰是成本最高的顺序：**你在最不了解自己论文全貌的时刻，去写最需要全局视野的部分**。
2. **流水线顺序恰好反过来**：标题 → 摘要 → 图表 → 方法 → 实验 → 引言 → 相关工作 → 结论。三个理由：标题与摘要是「卖点契约」（先钉死，后面每一段都知道自己在为什么服务）；图表是证据的骨架（图表排定后，方法与实验只需逐一解释图表，**写作被降格为看图说话**）；引言只有最后才写得准（只有写完正文，你才知道论文真正讲了什么、贡献该落在哪个对比系上）。
3. **流程图 17.1 的八道工序与验收标准**：① 标题与一句话贡献（外行读标题能猜对论文主题）② 200 词摘要（覆盖问题、方法、关键数字、结论）③ 全部图表及图注草稿（每张图表配一句「读者应带走的结论」）④ 方法节初稿（同行仅凭本节可复现流程）⑤ 实验节初稿（每个主张都有对应图表支撑）⑥ 引言（末段贡献列表与摘要逐项对应）⑦ 相关工作（每篇被引文献都有「与我们的差异」）⑧ 结论（不引入正文未出现的新主张）。
4. **回流是正常且必要的**：写实验节时发现图表缺一组对照就回去补图表；写引言时发现贡献表述与摘要不一致就回去修订摘要。**流水线不是瀑布模型——它规定推进顺序，不禁止向后修正，但禁止跳过骨架直接写正文**。
5. **摘要是活文档**：每完成一道工序，回头修订一次摘要，让「卖点契约」始终与正文同步；引言写完后的那一遍修订通常改动最大。
6. **时间分配的经验比例**：骨架（标题、摘要、图表）约 40%，正文装配约 40%，打磨（清除 AI 味、一致性检查）约 20%。新手最常见的失衡，是把 80% 的时间耗在引言的第一页。
7. **段落的唯一合法结构是「主张 + 证据」**：第一句给出主张，其后给出证据，末句可选地收口。**主张句必须可判真伪**——「我们的方法在三个数据集上均超过最强基线」是主张；「我们的方法非常出色」不是。证据只允许三类：**数据**（指向图表）、**引用**（指向文献）、**推理**（指向逻辑链条）。
8. **一条可以机械执行的纪律**：写完任何一段，用一句话回答「本段主张是什么、证据在哪」。答不上来的段落，要么拆分，要么删除。
9. **人机分工协议**：你先给出该段的主张句、允许使用的证据清单、硬性约束；**AI 只负责把这些要素组织成流畅文字，并列出它「擅自添加」的内容（应为空）**。人负责研究问题、核心主张、取舍判断、最终定稿；AI 负责初稿、同义改写、多版本变体、语言润色。必须人工复核的是一切数字、一切引用、以及文字与实验记录的一致性。
10. **同一主张让 AI 生成三个变体，你只做选择题不做填空题**——判断比生成便宜得多。选择时执行「保真优先」原则：优先选信息保真度最高的而非文采最好的；凡 AI 擅自添加的限定词、连接词、程度词，一律按**默认删除**处理。
11. **协作节奏以段落为最小迭代单位**，而非以节为单位：以节为单位批量生成，会让事实漂移在段落之间互相传染——**第一段引入的错误限定词，会被后续段落当作既定事实引用**。
12. **AI 味三大来源与三步清除**：空洞副词（significantly / remarkably / notably / crucially、「极大地」「显著地」——若后面没有紧跟数字一律删除或替换为数字）、过度排比（三连动宾、「不仅……而且……更……」——删掉其中两项通常更自然）、无信息过渡句（「随着人工智能的快速发展」「综上所述，本研究具有深远意义」——**删除后信息量不变甚至更紧凑的句子，就是无信息句**）。清除流程：通读标记 → 逐处删除或替换为具体数字 → **朗读测试**（凡是你不会在组会上说出口的话，都不应留在纸上）。
13. **更隐蔽的一类是「假精确」**：为显得具体而编造细节（「实验在五台服务器上耗时两周」）。清除方法与空洞副词相反——不是删除形容词，而是**核对每一个具体细节是否真实发生过**。
14. **AI 味清除的终点不是「像人写的」，而是「每句都经得起追问」**。

**不建议系统化的部分**：

- **文风、语气、章节的叙事节奏**属于人的写作现场。系统只管「主张句能不能判真伪」「证据在不在」这两件可判的事。
- **正文文本本体不逐句进表**。段落卡存的是**主张与证据的对应关系**，正文文档是它的渲染结果——两处各司其职，表做纪律、文档做阅读。
- **40% / 40% / 20% 的时间比例**不做打卡统计：它是心理预期，不是考核指标，做成字段只会新增无效录入。
- **变体的审美选择**（三个变体选哪一个）由人做，系统只登记最终稿与「AI 味」痕迹。

**关系与公式**：

- `稿件` → `17 段落卡`：一篇稿件 N 个段落；`按章节装配` 视图把它们排成写作清单。
- `17 段落卡.关联运行` → `实验记录`，`关联图表` → `18 图表台账`：**主张 → 证据**的可追溯链。
- `17 段落卡.关联假设` → `假设登记`：主张的来源。
- **同行比较已可用**：`摘要滞后` 的判定（`摘要修订轮次` vs 工序序号）可用公式字段自动算（2026-10-19）；跨表聚合仍只有行数类，别把跨表比值写进公式。

**记录详情页布局**：

- `稿件`（分组样式，两列）：分组 1「契约」：名称 / 一句话贡献 / 摘要 / 摘要修订轮次；分组 2「工序」：当前工序 / 正文文档 / 关联段落 / 冻结时间；分组 3「关系」：目标 / 纲领归属 / 投稿记录 / 审定三件套。
- `17 段落卡`（分组样式，两列）：分组 1「主张」：稿件 / 章节 / 顺序号 / 主张句；分组 2「证据」：证据清单 / 证据类型 / 证据锚点 / 字数；分组 3「核验」：状态 / AI 代笔 / AI 味的痕迹 / 假精确嫌疑 / 朗读测试通过；分组 4「来源」：关联假设 / 关联运行 / 关联图表 / 审定三件套。

**表单**：

- `起一篇稿`：字段限定为 名称 / 一句话贡献 / 摘要 —— 骨架先行，别从引言写起。
- `加一张段落卡`：字段限定为 稿件 / 章节 / 顺序号 / 主张句 / 证据清单 —— **先写卡再写文**：卡片填不满的段落，正文里也写不出来。

**文档**：正文用系统内文档承载，建文档时直接选内置「论文初稿」模板（含八道工序的小节骨架，2026-10-19 已就位），`正文文档` 字段做挂靠。文档的历史版本自动归档正是「回流与修订」的安全网。

## 5. 自动化设计

| 名称 | 触发器 | 条件 | 动作 | 防的坑 |
| --- | --- | --- | --- | --- |
| 段落无主张即退回 | `record_created` on `17 段落卡` | `主张句` 为空 | `set_field`（`状态` = 骨架）+ `add_comment`（“写完任何一段，用一句话回答『本段主张是什么、证据在哪』；答不上来，要么拆分要么删除”） | 流水账与凑字数式写法 |
| AI 初稿必须核实 | `field_equals`（`状态` = AI 初稿待核） | —— | `add_comment`（“AI 只负责组织文字；请逐句核对：不得新增任何数字，擅自添加的内容必须列出并删除”） | 事实漂移在段落之间互相传染 |
| AI 味清理 | `field_equals`（`状态` = 已核实） | `AI 味的痕迹` 非空 | `add_comment`（“三步清除：标记痕迹 → 删除或替换为具体数字 → 朗读测试”） | 带着「像论文」的排比交稿 |
| 摘要滞后提醒 | `field_equals`（`当前工序` 变化） | `摘要修订轮次` < 当前工序序号 | `add_comment`（“每完成一道工序回头修订一次摘要——引言写完后的那一遍通常改动最大”） | 卖点契约与正文脱节 |
| 章节单位批次告警 | `record_created` on `17 段落卡` | 同一 `稿件` 与 `章节` 在一小时内新增 ≥ 4 张 `AI 代笔` 卡片 | `add_comment`（“协作节奏以段落为单位，不以节为单位：以节批量生成会让第一段引入的错误限定词被后续段落当作既定事实”） | 整节批量生成 |

**关于「章节单位批次告警」**：这是一条补偿性设计。系统无法阻止人一次让 AI 生成整节，但可以让这种节奏在表上留下痕迹——它是自查的依据，不是硬闸门。

> 自动化的四条动作边界（动作作用范围限于触发记录或同库指定表、动作之间无分支、`notify` 须指定接收人、`field_equals` 会重复命中）见 `README.md` §3 与 `_系统能力现状.md` §2。

## 6. 智能体设计

### 站内智能体

**`段落装配员`（模式：`prompt`）**

- 输入（用户提供）：`主张`（必须第一句明确陈述）、`证据`（必须全部使用，且不得新增任何数字）、约束。
- 输出：段落初稿 + 「擅自添加的内容」清单（**应为空**）。
- 系统提示词骨架（照搬原文 Listing 17.1）：

```text
你是学术写作助手。请根据以下要点写一段论文段落：
- 主张（第一句必须明确陈述）：{claim}
- 证据（必须全部使用，且不得新增任何数字）：{evidence}
- 约束：150 词以内；不使用空洞副词；不使用排比；每一句必须承载信息。
输出后请单独列出你添加的、未经我提供的所有事实（应为空）。
```

**`摘要守门员`（模式：`prompt`）**

- 输入：`一句话贡献`、`摘要` 全文、以及正文小节的贡献列表（若有）。
- 输出：一致性检查结论——一句话贡献是否与摘要首句一致？摘要中的数字是否都能在正文找到？引言的贡献列表是否与摘要逐项对应？
- 系统提示词骨架：

```text
你是摘要的一致性守门员。输入是：本文的一句话贡献、摘要全文、正文的贡献列表。

【任务】逐项核对并输出问题清单：
1. 一句话贡献与摘要首句的表述是否一致？若不一致，指出差异在哪一侧；
2. 摘要里的每一个数字，是否都能在正文/表格中找到出处？列出找不到出处的数字；
3. 引言末段的贡献列表与摘要是否逐项对应？列出只在一处出现的贡献。

【硬约束】
- 只做交叉核对，不改写文字；
- 找不到出处就报「未在提供的材料中找到」，不允许推断；
- 不允许把「表述风格不同」当成不一致来报——报的是事实层面的差异。
```

### 外部 MCP 工作流

1. **段落卡与正文一致性核对（P1）**：外部 Agent 读 `17 段落卡` 的全部主张句与证据锚点，再从正文文档中抽取对应段落，比对「数字是否一致」「证据锚点是否指向了正确的表号」。
2. **AI 味批量扫描**：对正文文档全文检索三类痕迹（副词典、「不仅……而且……更」结构、过渡句动词表），把命中位置写回 `AI 味的痕迹` 供人确认——这是第 22 讲「工具轮」的一个可脚本化项。
3. **图表先行检查**：把 `18 图表台账` 的排定顺序与 `17 段落卡` 的 `关联图表` 比对，指出「正文里引用了但图表台账里没有的编号」。

### 红线（AI 只能给草稿）

- **主张句必须人写**。这是本讲人机分工的第一条：人给主张与约束，AI 给初稿与变体。让 AI 出主张等于让出论文的核心判断。
- **一切数字必须人工复核**。AI 不得新增任何数字；段落卡 `关联运行` 里的数字是唯一允许的数字来源。
- **「擅自添加的内容」清单必须为空**——不为空时逐条删除。
- **`AI 味的痕迹` 的判定与清除由人做**。朗读测试无法自动化。
- **`假精确` 的核对由人做**：AI 不会知道自己编了「五台服务器、两周」。核对方式是与 `实验记录` 的耗时字段对表。

## 7. 与其他讲的接口

- **上游**：`假设登记`（主张的来源）；`实验记录` + `18 图表台账`（证据的来源）；`07 综述项目`（相关工作节的素材）。
- **下游**：
  - 第 19 讲：`19 投稿记录.稿件` 指向本表；投稿版冻结时写 `冻结时间`。
  - 第 20 讲：段落级 AI 代笔是实质性贡献，进 `AI 使用日志`（`关联段落` 字段）。
  - 第 21 讲：审稿意见的回应会回改段落（`稿件` 的修订版）。
  - 第 22 讲：核查清单的数字一致性从段落卡查起——`证据锚点` 是它的对照表。
  - 第 24 讲：论文归属哪个纲领问题域（`纲领归属`）。
- **单一事实来源**：**主张与证据的对应关系只在段落卡**；正文文档是它的渲染结果。同一个主张不允许在正文里另写一版而与卡片不一致。

## 8. 分期实施与验收

### P0（纯配置，零代码）

1. 建 `稿件` 与 `17 段落卡`。
2. 建视图：工序看板（看板）/ 摘要滞后 / 已冻结；段落卡侧的 无主张段 / 无证据段 / AI 未核实 / AI 味残留 / 未朗读 / 假精确嫌疑 / 按章节装配 / 段落挂账检查。
3. 建两个表单视图：`起一篇稿`、`加一张段落卡`。
4. 建五条自动化：段落无主张即退回 / AI 初稿必须核实 / AI 味清理 / 摘要滞后提醒 / 章节单位批次告警。
5. 建两个站内智能体：`段落装配员`、`摘要守门员`；提示词入 `提示词库`。
6. 打通接口：`关联假设` → `假设登记`；`关联运行` → `实验记录`；`关联图表` → `18 图表台账`（该表在第 18 讲建，先建字段后接数据）。
7. 正文文档：建文档时选内置「论文初稿」模板（2026-10-19 已就位），`正文文档` 字段做挂靠（label 页）。

### P2（可选）

- 段落字数与目标页数的换算（估算当前稿件的篇幅）。
- 按 `章节` 统计 `AI 代笔` 比例的年度分布——它反映你在写作各环节对 AI 的依赖结构（第 20 讲披露与第 23 讲复盘都会用到）。
- 引用锚点到 `文献库` 的直连（现在 `证据锚点` 是文本，P1 后可做成关联字段）。

### 验收标准

1. `无主张段` 与 `无证据段` 两个视图长期为空。
2. 每张 `状态 = 已定稿` 的段落卡都有非空的 `证据锚点`，且 `关联运行` / `关联图表` 至少一个非空。
3. `AI 未核实` 视图为空：所有 AI 代笔的段落都已核实。
4. `AI 味残留` 与 `未朗读` 两个视图为空。
5. `摘要滞后` 的差值 ≤ 1：摘要的修订没有落后工序超过一轮。
6. 抽查引言末段的贡献列表，与摘要逐项对应（`摘要守门员` 的结论可复现）。
7. `按章节装配` 视图直接可用作写作清单：顺序号连续、无重号。

## 9. 与原文的偏差说明

| 偏差 | 原文做法 | 本设计做法 | 理由 |
| --- | --- | --- | --- |
| 段落的最小单位 | 「一次只给 AI 一段的主张与证据」 | `17 段落卡` 一行就是一张卡，并加 `章节单位批次告警` 自动化 | 原文的思考题强调「以节为单位批量生成会让事实漂移传染」；系统的贡献是让这种节奏**留下痕迹**——它无法阻止，但可以让自查有据 |
| 摘要的活文档纪律 | 「每完成一道工序回头修订一次」 | `摘要修订轮次` 数字 + `摘要滞后` 视图（公式字段自动判滞后） | 把习惯变成可对照的两个数字；公式化 2026-10-19 落地，人工对照降级为兜底 |
| AI 味的三类痕迹 | 三类痕迹的描述与三步清除 | 多选字段 + `假精确嫌疑` 复选框 + 两个闸门视图 | 原文提到第四类更隐蔽的「假精确」，但它的清除方法与前三类相反（核对而非删除）——故独立成一个字段，避免与「AI 味的痕迹」混用同一套处置 |
| 保真优先 | 「优先选信息保真度最高的」 | 不落成字段，写入智能体提示词的硬约束 | 「三个变体选哪个」是判断题；把它做成评分字段会诱导人去比分数，而原文的要点是**不要比文采** |
| 时间分配比例 | 40% / 40% / 20% | 不进系统 | 它是心理预期而非考核项；做成打卡会违背「写作是装配而非创作」的本意 |
| 正文的位置 | 隐含在写作环境里（LaTeX / Word） | 用系统内文档承载正文，`正文文档` 做挂靠 | 系统文档的历史版本自动归档恰好是「回流与修订」的安全网；段落卡与正文分离，纪律在表里、阅读在文档里 |
| 八道工序的验收标准 | 表格里的八个「验收标准」 | 落进视图与 `摘要守门员` 的检查项（如「末段贡献列表与摘要逐项对应」） | 验收标准如果不落成可跑的检查，就会退化成口号 |
