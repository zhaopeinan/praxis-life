# 系统能力现状（设计底座）

> 本文件是 24 讲设计文档的共同底座。所有「可落地」判断以本文件列出的能力为准；未列出的能力一律视为不存在——设计中若确需使用，必须在对应文档的「需要新增的能力」一节显式说明。
>
> 依据：源码核对（`src/types.ts`、`src/store.ts`、`src/server.ts`、`src/mcp-catalog.ts`、`src/templates.ts`、`src/limits.ts`、`web/src/`）。核对时间：2026-10-18；同日增补自动化相对日期与跨表 `create_record`（上一轮 P1 第一批已落地）。

## 1. 数据模型

`Base（空间）→ Table（数据表）→ Field（字段）/ View（视图）/ Record（记录）`，记录带评论、历史、关注与通知。

### 1.1 字段类型（28 种）

文本、多行文本、数字、单选、多选、日期、复选框、超链接、邮箱、电话、人员、评分、进度、货币、自动编号、创建时间、修改时间、创建人、公式、关联、双向关联、查找引用、按钮、附件、条码、地理位置、签字、群组。

设计与实现要点：

- **自动编号**支持前缀，可用于生成 `H-`、`exp-`、`L-` 这类业务编号；
- **按钮**字段支持三种点击动作：改字段值（set_field）、打开链接（open_url）、写评论（add_comment）；
- **关联 / 双向关联 / 查找引用**都是空间内表间关系，可在不同表之间建立证据链；
- **公式**支持跨表聚合：`TABLEROWS` / `TABLESUM` / `TABLECOUNT`；
- 字段类型创建后可变（受兼容矩阵约束），系统字段类型（自动编号/公式/查找引用等）不可变。

### 1.2 视图（6 类）与视图配置

| 视图 | 用途 |
| --- | --- |
| grid 表格 | 主工作视图 |
| kanban 看板 | 按状态分列推进 |
| calendar 日历 | 时间排程（复习、截止、复盘） |
| gallery 画册 | 附件/图表浏览 |
| form 表单 | 快速录入（入库收件箱等） |
| gantt 甘特 | 项目排期、依赖与进度 |

可配置项：过滤器（eq / neq / contains / not_contains / gt / gte / lt / lte / is_empty / is_not_empty，多条件 and/or）、排序、分组（单视图最多 3 层）、隐藏字段、行高、颜色规则（按条件给行/单元格着色）、日历与甘特绑定的日期字段、甘特依赖字段与进度字段、**视图保护**（public / locked / personal）。

公开分享（view / form）后端保留、前端入口已下线。

### 1.3 记录交互

评论（增删列）、变更历史（`list_record_history`，用于留痕）、关注与取消关注、通知中心（前端入口已下线，后端与 MCP 保留）、单记录分享链接、**记录详情页布局**（单栏/多栏/分组三种样式，1–3 列，字段顺序可自定义）。

## 2. 自动化

**触发器 6 类**：`record_created`、`record_updated`（可指定字段）、`field_equals`、`button`、`webhook`（带 secret）、`schedule`（cron）。
其中**前端自动化编辑器只列出 4 类**（`record_created` / `button` / `webhook` / `schedule`）；`record_updated` 与 `field_equals` 需经 MCP / REST 配置。

**动作 9 类**：`set_field`、`create_record`、`add_comment`、`notify`（站内通知，可指定接收人）、`http_request`、`send_email`、`feishu_bot`（飞书机器人）、`feishu_digest`（到期摘要）、`run_agent`（调用站内 LLM 智能体）。
其中**前端只列出 7 类**（`set_field` / `add_comment` / `http_request` / `send_email` / `feishu_bot` / `feishu_digest` / `run_agent`）；`create_record` 与 `notify` 需经 MCP / REST 配置。

**动作语义（源码核对，设计时不得越界）**

- `set_field` 只能改**触发记录自身**的字段（且不能是系统字段），改不了别的记录、也改不了别的表。日期字段取值支持相对日期：`today`、`today+N`、`today-N`、`week_start`、`week_end`、`month_start`、`month_end`、`now`、`now±Nh`（写入记录、按钮动作同样可用），「今天 + 90 天重检」「冷静期 + 3 天」不必再靠人工填写。
- `create_record` 默认建在触发器绑定的那张表里，也可用 `tableId`（**同一空间**内的表 id 或表名）指定目标表，字段值支持 `{字段名}` / `{recordId}` 插值带出当前记录内容；跨空间建档仍只有三条路：`run_agent`（智能体工具 `create_record` 接受任意 `tableId`）、`http_request` 打 REST、人工补录。
- **条件（`conditions`）** 在动作前按 AND 统一求值，判定与视图过滤器同源；比较值同样支持上面的相对日期 token，所以「未来 2 天内」「超过 90 天未动」「本周」可以直接写成条件（例：未来 2 天 = `截止日期 >= today` 且 `截止日期 <= today+2`；三个月未动 = `重检日期 < today-90`）。日期按 `YYYY-MM-DD` 文本比较，**空值小于任何日期**，要排除空值请追加 `is_not_empty`。
- `schedule` 触发的自动化绑定在某张表上：`run_agent` 与 `feishu_digest` 不依赖记录；**其余动作都以该表的第一条记录为上下文，且表内一条记录都没有时整条自动化被跳过**。
- 动作之间**没有条件分支**，也不读取上一动作的输出。「查一批 → 按结果决定推不推、推什么」不可实现。正确的拆法：智能体负责查与写（评论 / 记录），推送只发一句固定提醒（告诉你去哪张表的哪个视图看）。
- `notify` 的接收人必须**显式指定**——`schedule` 触发时执行身份是 system，不指定就写进一个没人看的收件人。且**通知中心前端入口已下线**，通知的实际查看途径是 MCP / REST；要在界面上被看见，用 `add_comment`（记录内可见）或 `feishu_bot`（飞书）。
- `field_equals` 是「当前值等于」而非「值刚变为」：记录在字段保持该值期间的**任何一次更新都会重新命中**。它适合配提醒类动作（重复一次无害），不适合配会累积副作用的动作（如 `create_record`）。

**cron 语法（准确枚举）**：`every:N`（每 N 分钟）、`hourly`、纯数字 `N`（每 N 分钟）、`daily:HH:MM`、`weekly:D:HH:MM`（D：0=周日 … 6=周六）、简化 5 段 `m h * * *`（分与时只接受具体值或 `*`）。

**运行记录**：每次运行有状态（ok / failed / skipped）与逐动作结果摘要；可手动试跑；失败在运行记录中可见。

## 3. 工作流（审批）

节点链：`trigger → condition* → approval* → action*`。审批节点支持：审批人列表、any/all 会签策略、超时小时数与催办、加签（加签后强制 all）、代理审批、转交；配套审计事件与 SLA 概览（待批 / 超时 / 临期）。

> **注意**：工作流前端入口已下线（线上未配置过），后端接口与 MCP 工具保留。需要审批的场景必须通过 MCP/REST 配置。设计文档中一律标注为 P1，并说明这一点。

## 4. 仪表盘

图表 5 类：bar / pie / count / line / donut；支持切片器（按字段过滤）。前端有独立仪表盘页。

## 5. 文档（Markdown 长文）

- 文件夹结构（doc / folder）；
- 内置文档模板 3 个：**实验前思考 / 实验后复盘 / 研究笔记**；
- **文档 ↔ 记录挂靠**：一篇文档可挂到多条记录，每条挂靠可带 label（如「实验前思考」「复盘」）；
- **历史版本自动归档与回滚**（`list_document_revisions` / `restore_document_revision`）；
- 正文 Markdown 渲染，支持代码块与数学公式渲染。

## 6. LLM 智能体（站内）

- **模式**：`tools`（多轮工具调用）/ `prompt`（单次生成文本，不调工具）；
- **工具 6 个**（按触发者身份鉴权）：`list_tables`、`get_table_schema`、`query_records`（只读）、`create_record`、`update_record`、`add_comment`；
- **入口**：表内对话（chat）、定时自动化动作 `run_agent`（schedule）、手动试跑（manual）、API、失败重试；
- **Provider**：OpenAI 兼容 Chat Completions（baseUrl / model / temperature / apiKey）；
- **运行日志**：每次运行记录输入、输出、逐步工具调用（参数、结果、耗时、状态），失败可重试。

## 7. MCP（外部 Agent 接入）

- **两种形态**：本机 stdio 版（`src/mcp.ts`，直连同一个库）与 HTTP 版（`/api/mcp/tools`）；
- **工具约 120 个**，分数据面与控制面：表/字段/视图/记录 CRUD、CSV 导入导出、评论与历史、自动化（含手动试跑与运行记录）、ACL、成员、工作流、仪表盘、同步任务、插件钩子与市场、附件上传（base64，≤ 8MB）、文档（模板 / 挂靠 / 历史版本）、通知、日历订阅、公开分享，以及从模板建库（requirements / engineering / todos / **research**）；
- **Agent 身份**：`dwa_` 前缀令牌，按空间授权（owner / editor / viewer），管理员创建、轮换、禁用。Cursor / Claude Code 等外部 Agent 通过它操作同一份记录。

## 8. 权限

- 系统角色：admin / member；空间角色：owner / editor / viewer；
- 行级规则：`all` / `allow_ids` / `created_by` / `person_in` / `field_equals` / `field_in`；列级规则：按人隐藏字段；
- 公开分享（只读视图 / 表单提交）、单记录分享。

> **注意**：ACL 前端入口已下线，需要时走 MCP 配置；标记为 P1。

## 9. 同步、插件与其他

- **同步任务**：跨表字段映射、全量/增量、冲突策略（跨表同步前端入口已下线，走 MCP）；
- **插件钩子**：`record_created` / `record_updated` / `record_deleted` / `workflow_ran` → webhook 或本地 log；插件市场为雏形（webhook / log 两类），无沙箱；
- **ICS 日历订阅**（只读 feed，可接系统日历）；
- **空间级 Zip 导出**（tables JSON/CSV + documents Markdown + attachments + manifest）、单表 CSV 导入导出；
- **使用度量**：按天聚合接口 / Agent 调用、记录写入、文档写入、自动化运行；
- **备份**：命令行与接口（`/api/system/backup`）。
- **上限（节选）**：300 表/空间、300 字段/表、200 视图/表、分组 ≤ 3/视图、过滤 ≤ 50/视图、附件 ≤ 100/单元格、关联 ≤ 500/单元格、文本 ≤ 10 万字、单次 MCP 上传 ≤ 8MB（base64）、字段改类型即时转换上限 2 万行。

## 10. 科研相关现成资产

- **建库模板「科研管理」**：论文（状态/优先级/截稿/看板/日历）+ 任务（挂靠论文，读文献/实验/写作分类）+ 投稿记录（结果状态/审稿中视图），已带飞书新记录通知与每日截稿摘要自动化；
- **文档模板**：实验前思考 / 实验后复盘 / 研究笔记；
- **智能体工具集**天然覆盖「查表 → 建记录 → 改记录 → 写评论」这条自动整理链路。

## 11. 设计红线（24 讲文档共同遵守）

1. **只用本文件列出的能力**。不确定的不写；确需新增的，写进「需要新增的能力」，并给出落点文件（如 `src/store.ts`、`src/server.ts`、`web/src/`）。
2. **AI 产出默认落草稿**。一切 AI 生成的摘要、链接、分类、回应初稿，先进入「待审定」状态，人工核验后才允许写入正式字段（对应第 6、8、20、22 讲的核查纪律）。
3. **关键证据要留痕**。记录变更历史 + 文档版本 + 创建时间天然提供「不能事后涂改」的证据；需要更强防篡改（如预期结果卡锁定）时，标为 P1 增强并说明做法。
4. **已下线前端入口的能力**（工作流审批、ACL、公开分享、通知中心、跨表同步）必须注明：配置途径为 MCP / REST，前端不可见。
