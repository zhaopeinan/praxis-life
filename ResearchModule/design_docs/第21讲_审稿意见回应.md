# 第 21 讲 审稿意见回应：系统落地设计

> 来源：`../design_principle/第21讲_审稿意见回应把评审变成资产.pdf`
> 落地度：★★★★★（高） ｜ 依赖：第 19 / 20 讲 ｜ 主体分期：P0
> 主产物：两张表——`21 审稿意见`（一行 = 一条意见，四段回应与坐标挂在同一行）、`21 转投决策`（一行 = 一次拒稿后的决策，含冷静期）

## 1. 本讲方法要点

1. **回应不是辩论赛，是工程任务**。新手最常见的错误是把所有意见当成同一种东西——要么全盘接受改到面目全非，要么逐条反驳战到两败俱伤。**回应的第一步不是动笔，而是给每条意见贴类型标签**。
2. **四类意见的成因、成本与策略完全不同**：
   - **误解型**（「作者未讨论 X」其实已讨论）：成因九成在作者——你的表述不够清楚，而不是审稿人粗心。策略是**双落地**：在回应信中澄清，**同时在正文中改写导致误解的段落**。只在回应信里解释而不改正文，等于让未来的读者继续误解。
   - **补实验型**（「应增加在 Y 上的实验」）：先做一个判断——**该实验是否影响主结论**？能负担的，做（补实验通常直接提高论文质量）；负担不起的，用已有证据加局限性讨论正面回应，说明成本与收益的权衡，**而不是装作没看见**。
   - **方法性质疑型**（「方法缺乏依据 / 假设不成立」）：最硬的一类，**唯一可能真正威胁论文存活的一类**。需要的是**证据链而非修辞**：补充消融、理论论证、权威先例，**三者至少居一**。确实站不住时，承认局限并收缩主张的强度，比硬撑更能赢得尊重。
   - **文字型**（措辞、术语、引用遗漏、图表格式、语言润色）：成本最低，原则是**全部照改并简短致谢**，不要在文字型意见上展示任何辩才——**在这里节省的每一句反驳，都是为方法性质疑型意见攒下的信用**。
3. **分类建议以会议形式完成**：全体作者聚在一起逐条朗读意见并投票归类。**争议最大的条目往往正是最危险的条目**——它被误归类为误解型，而实际是方法性质疑型。给每条意见打标签的同时标注负责人与预计工作量，回应工程即刻有了甘特图。
4. **四段结构（每条意见的回应）**：**感谢**（感谢指出这一问题）→ **重述**（用一句话复述核心关切，表明你准确理解了它）→ **行动**（我们做了什么：补充的实验、修改的论证、改写的段落）→ **定位**（第 X 节第 Y 段、表 Z、修改稿第 N 页，修改处以蓝色标出）。
5. **四段结构的力量在于可核查性**：审稿人不必重读全文，按你给出的坐标即可验证。**重述一段尤其不可省略**——它把「你觉得他在说什么」显性化，误解在此处就会被发现，而不是留到下一轮。
6. **逐条回应表的纪律**：意见原文**逐字引用，不改写**（一旦你开始改写审稿人的话，「稻草人回应」就不远了）；三列结构为「意见原文 / 回应 / 修改位置」。
7. **回应信与修改稿同步冻结**：先完成全部修改，再校对回应表中的每个页码与图表编号——**任何对不上号的坐标都是对审稿人时间的浪费**。
8. **对拒绝采纳的意见同样认真回应**：说明理由、给出证据、提出折中——「我们理解这一关切，基于以下三点理由未做改动」是合法且时有必要的回应，**沉默才是**。
9. **AI 起草的边界钉死在三处**：**事实核查**（AI 不知道你实际做了什么，它只会把回应写得「像做了」——一切技术陈述必须逐句对照你的修改记录）；**语气校准**（AI 容易在两个方向失控：过度谦卑与隐性对抗；终稿前做朗读测试——凡你不会在学术会议上当面对人说的话，删掉）；**接受或拒绝意见的判断永远属于人**。
10. **团队协作加一条**：回应信定稿前，由一位**未参与执笔的作者**做「对抗性通读」，专门寻找语气失衡与逻辑跳跃——执笔人对自己写的礼貌是免疫的。
11. **被拒后先做唯一正确的事：什么都不做**。设定 **48 到 72 小时的冷静期**，期间不回复编辑、不讨论申诉、不做转投决定。情绪化决策只有两种：**立即申诉**（成功率极低且消耗与编辑的关系）与**一字不改立刻转投**（你可能把稿子送到同一位审稿人手里——领域比你想象的小）。
12. **冷静期结束后，把拒稿意见当免费的专家评审处理**：逐条过一遍分类学，把方法性质疑型与补实验型意见全部纳入修改计划。**哪怕决定转投，这些修改也让下一站的命中率显著提高**。
13. **转投三问，按顺序**：① 意见是否含有真知灼见——若有，先修改再谈去向；② 修改后论文是否仍达原目标的档次——若揭示的是硬伤，**诚实下调目标比硬冲更省时间**；③ 新目标与论文的匹配度——用第 19 讲的选刊框架重新走一遍，而不是选「下一个名气最大的」。**三个问题都答完，转投决策通常自动浮现**。
14. **拒稿是分布中的常态事件**：多产研究者的拒稿次数通常多于低产者，他们只是恢复得更快。被三次拒稿拖延一年的论文，损失的不只是时间，还有抢先权与团队士气。

## 2. 可落地性判定

| 能力点 | 落地形态 | 依托的现有能力 | 优先级 |
| --- | --- | --- | --- |
| 意见分类学 | `类型` 单选（四类）+ `未分类` 闸门视图 | 单选、过滤 | P0 |
| 按类型分优先级 | `方法性质疑` 视图 + `方法性质疑即上报` 自动化 | 过滤、field_equals、notify | P0 |
| 误解型双落地 | `正文已改写` 复选框 + `误解型未改正文` 视图 | 复选框、过滤 | P0 |
| 原文逐字引用 | `意见原文` 多行 + 回应信模板里的三列结构 | 多行、文档 | P0 |
| 四段结构 | 四个独立字段（回应·感谢/重述/行动/定位） | 多行 ×4 | P0 |
| 重述不可省略 | `重述缺失` 闸门视图 | 过滤（is_empty） | P0 |
| 坐标可核查 | `回应·定位` + `定位坐标` + `坐标不全` 视图 | 文本、过滤 | P0 |
| 证据链类型 | `证据链类型` 多选（补充消融/理论论证/权威先例）+ `主张收缩` 复选框 | 多选、复选框 | P0 |
| AI 起草的边界 | `AI 起草` / `事实核查` / `语气通读` 三个复选框 | 复选框 | P0 |
| 回应工程甘特图 | `负责人` 成员 + `工作量` 评分 + 甘特视图 | 成员、评分、gantt | P0 |
| 同步冻结 | `状态` 含「已冻结」+ `待冻结` 视图 | 单选、过滤 | P0 |
| 冷静期 | `冷静期结束日` 日期 + `冷静期内` 视图 + `冷静期提醒` 自动化 | 日期、过滤、record_created | P0 |
| 转投三问 | `21 转投决策` 的三个单值字段 | 单选、多行 | P0 |
| 意见吸收检查 | `纳入修改的条目` 关联 + `未吸收意见` 视图 | 关联、过滤 | P0 |
| 审稿意见进入月复盘 | `21 审稿意见` 作为年度回顾原料 | 第 23 讲接口 | P1 |

**不建议系统化的部分**：

- **与编辑的沟通策略、申诉与否的判断**属于人际与策略。系统只在 `情绪化动作` 字段留下事后记录——**它的位置是「复盘时看到自己踩过什么坑」，不是「决策前给你建议」**。
- **「争议最大的条目往往最危险」这个会议判断**不做成字段。分类会议的价值在于把全体作者拉到同一个房间里朗读；投票结果可以进 `类型` 字段，但「谁反对谁赞成」不需要留痕，留痕会让下一次会议变成表态。
- **语气与措辞的最终判断**不进系统。系统只保证「事实核查」「语气通读」两个动作发生过（复选框），不评价语气本身。
- **回应信本体的排版**（修改处蓝色标出、页码校对）留在文档里做——它是渲染产物，不是数据。

| 纳入修改的条目 | 关联 → `21 审稿意见`（多值） | **拒稿意见是免费评审，先吸收再上路** |

| 执行日期 | 日期 | —— |

**视图建议**：

| 视图名 | 表 | 类型 | 配置要点 |
| --- | --- | --- | --- |
| 未分类 | `21 审稿意见` | grid | 过滤：`类型` 为空——分类之前不动笔 |
| 误解型未改正文 | `21 审稿意见` | grid | 过滤：`类型 = 误解型` 且 `正文已改写` 未勾选——**悬空回应的集中视图** |
| 方法性质疑 | `21 审稿意见` | grid | 过滤：`类型 = 方法性质疑型`——优先级最高的一类 |
| 重述缺失 | `21 审稿意见` | grid | 过滤：`回应·重述` 为空 |
| 坐标不全 | `21 审稿意见` | grid | 过滤：`回应·定位` 为空 |
| 待冻结 | `21 审稿意见` | grid | 过滤：`状态 ≠ 已冻结` |
| 冷静期内 | `21 转投决策` | grid | 过滤：今天 < `冷静期结束日`——**此视图存在的唯一目的是让你别动手** |
| 未吸收意见 | `21 转投决策` | grid | 过滤：`纳入修改的条目` 为空 |

**关系与公式**：

- `21 审稿意见.投稿记录` → `19 投稿记录`：一轮审稿的 N 条意见挂在同一次投稿下；按 `来源` 分组即还原「审稿人 1 的十七条意见」的原始形态。
- `21 转投决策.纳入修改的条目` → `21 审稿意见`（多值）：**跨投稿的引用**——被拒那次的意见，在转投后的修改中仍要被逐条勾选，这就是「意见被吸收」的可核查证据。
- `21 转投决策.新目标` → `19 投稿目标`：转投不是另起炉灶，而是重走三维评估。
- **不使用跨表聚合**：「本轮意见的冻结进度」用 `待冻结` 视图表达；冻结是一个动作而非一个数值。

**样例 3（一次「悬空回应」的排查）**

某轮审稿共 17 条意见，其中 3 条判为误解型。两周后检查：

- `误解型未改正文` 视图里躺着 1 条——**只在回应信里解释了，正文没动**；
- 自动化留言：「只在回应信里解释而不改正文，等于让未来的读者继续误解」；
- 处置：回改正文段落（同时更新 `17 段落卡` 的对应卡片），回来后勾选 `正文已改写`，视图重新为空。

这条视图的价值在于：**悬空回应在提交前没有任何症状**——回应信读起来完整、修改稿也交出去了，只有下一位读者会重复踩同一个坑。

## 4. 视图与交互设计

**主视图与筛选口径**：

- `方法性质疑` 是最高优先级视图：它决定论文的存活，其他条目的回应顺序都应排在它之后。
- 三条「缺件」视图（`未分类` / `重述缺失` / `坐标不全`）分别对应流程上的三道坎——**分类之前不动笔、不重述不回应、没坐标不算回应完**。
- `误解型未改正文` 与 `待冻结` 是两个「看似完成了」的陷阱视图：前者是只改了信没改稿，后者是 Letter 写完了但坐标还没校对。

**看板与甘特怎么配**：

- 按 `状态` 的分列看板（待分类 → 待回应 → 已回应 → 已冻结）用于团队会议时逐条推进。
- **甘特视图挂 `负责人` 与 `工作量`**：原文说「标注负责人与预计工作量，回应工程即刻有了甘特图」——这是本讲唯一明确点名甘特的场景。用一个以 `工作量` 为进度字段、以截止日（回复期限）为时间轴的甘特视图即可。

**记录详情页布局**：

- `21 审稿意见`（分组样式，两列）：分组 1「意见」：编号 / 投稿记录 / 来源 / 意见原文 / 类型 / 影响主结论；分组 2「回应四段」：回应·感谢 / 回应·重述 / 回应·行动 / 回应·定位；分组 3「证据」：正文已改写 / 定位坐标 / 证据链类型 / 主张收缩；分组 4「工程」：负责人 / 工作量 / 状态 / AI 起草 / 事实核查 / 语气通读 / 审定三件套。
- `21 转投决策`（分组样式，两列）：分组 1「事发」：原投稿记录 / 拒稿日期 / 冷静期结束日 / 情绪化动作；分组 2「三问」：三问·意见含真知灼见 / 三问·修改后仍达原目标档次 / 三问·新目标匹配度 / 真知灼见；分组 3「去向」：目标调整 / 新目标 / 纳入修改的条目 / 决定 / 执行日期。

**表单**：

- `录一条意见`：字段限定为 投稿记录 / 来源 / 意见原文 —— **录入时只抄原文，不写回应**；分类与回应分开进行。
- `记一次转投`：字段限定为 原投稿记录 / 拒稿日期 —— 冷静期结束日由自动化填。

**文档**：

- 《回应信》：四段结构模板 + 逐条回应表（意见原文逐字引用 / 回应 / 修改位置 三列）。文档头部注释写清两条纪律：原文逐字引用、回应信与修改稿同步冻结。
- 《逐条回应表》：**P0 直接用 `21 审稿意见` 的视图替代**——按 `来源` 分组、隐藏「工程」字段，它就是一张现成的逐条回应表；文档形式只在需要导出给编辑时生成。

## 5. 自动化设计

| 名称 | 触发器 | 条件 | 动作 | 防的坑 |
| --- | --- | --- | --- | --- |
| 方法性质疑即上报 | `field_equals`（`类型` = 方法性质疑型） | —— | `notify`（高优先级）+ `add_comment`（“唯一可能真正威胁论文存活的一类：需要证据链而非修辞——补充消融、理论论证、权威先例，至少居一”） | 把最硬的一类混在十七条里一起处理 |
| 误解型双落地 | `field_equals`（`类型` = 误解型） | `正文已改写` 未勾选 | `add_comment`（“只在回应信里解释而不改正文，等于让未来的读者继续误解”） | 悬空回应 |
| 冷静期提醒 | `record_created` on `21 转投决策` | —— | `add_comment`（“先做唯一正确的事：什么都不做——立刻写下 `冷静期结束日` = 今天 + 3 天，期间不回复编辑、不讨论申诉、不做转投决定”） | 情绪化决策：立即申诉或一字不改转投 |

**关于「方法性质疑即上报」的通知对象**：`notify` 可指定接收人——合作者多时建议通知全体作者（这一类的判断需要集体的证据链，不是单一执笔人能决定的）。**未指定接收人的 `notify` 在 `schedule` 触发时会写进一个没人看的收件人**（执行身份是 system），所以凡配 `notify` 必须显式选人。

**关于「冷静期结束日」的落地方式**：`set_field` 自 2026-10-18 起支持 `today+3` 这类相对取值，`冷静期结束日` 可直接由动作写入，「评论提醒人工填写」降级为兜底。

> 自动化的四条动作边界（动作作用范围限于触发记录或同库指定表、动作之间无分支、`notify` 须指定接收人、`field_equals` 会重复命中）见 `README.md` §3 与 `_系统能力现状.md` §2。

## 6. 智能体设计

### 站内智能体

**`回应信起草员`（模式：`prompt`）**

- 输入（用户提供）：意见原文、我的分类、**我实际做的修改（只准使用这些事实，不得新增）**、修改位置。
- 输出：四段结构初稿 + 一个「我可能在回应里暗示了但你没做过的事」清单（**应为空**）。
- 系统提示词骨架（照搬原文 Listing 21.1 并补两条硬约束，存进 `提示词库`）：

```text
你是学术回应信写作助手。针对以下审稿意见起草回应：
- 意见原文：{comment}
- 我的分类：{误解型/补实验型/方法性质疑型/文字型}
- 我实际做的修改（只准使用这些事实，不得新增）：{actions}
- 修改位置：{location}

要求：按「感谢–重述–行动–定位」四段；专业、克制；不使用对抗性措辞；感谢不超过一句。

【硬约束】
- 你对我实际做了什么一无所知：只允许使用 {actions} 里的事实，不得补充任何实验、数据或
  结论，也不得把回应写得「像做了」；
- 输出后单独列出：你的文字里有哪些表述暗示了一个未被 {actions} 覆盖的动作（应为空）；
- 重述段必须是你对意见核心关切的一句话复述，不得省略、不得美化；
- 若 {actions} 不足以回应 {comment}，直接说「信息不足，无法起草」，不要编。
```

**`语气提示员`（模式：`prompt`）——可选**

- 输入：回应信全文。
- 输出：逐句标记两个方向的失控——过度谦卑（三段感谢稀释专业感）与隐性对抗（「with all due respect」式的礼貌冒犯），并给出删除建议。
- 定位：它是朗读测试的辅助，不是替代——**最终语气由非执笔作者通读决定**。

### 外部 MCP 工作流

1. **坐标校对（P1）**：外部 Agent 读 `21 审稿意见` 中所有 `回应·定位` 与 `定位坐标`，与修改稿的实际节/段/页/表编号比对，输出「对不上号的坐标」清单——这是「回应信与修改稿同步冻结」的机械部分，人只需处理异常。
2. **拒稿意见吸收检查（与第 19 讲共用）**：比对 `21 转投决策.纳入修改的条目` 与 `21 审稿意见` 中分类为方法性质疑型/补实验型的条目，指出「判为真问题却没纳入修改」的漏项。
3. **意见模式统计（P1）**：跨多轮投稿统计四类意见的分布——**如果「误解型」在你的投稿里总是占三成以上，问题不在审稿人，在你的表述**。这是第 23 讲月复盘的一条输入。

### 红线（AI 只能给草稿）

- **事实核查由人做**：AI 起草中的一切技术陈述必须逐句对照修改记录。AI 不知道你实际做了什么——**它只会把回应写得「像做了」**。
- **最终语气由人定**：朗读测试无法自动化；定稿前由非执笔作者做对抗性通读。
- **接受或拒绝意见的判断永远属于人**：AI 不知道你的实验预算、不知道论文的战略目标，它给的「建议全部接受」式回应是风险最小的文风，却不一定是正确的决策。
- **`主张收缩` 的判定由人做**：站不住时收缩是战略选择，不是文字工作。
- **`情绪化动作` 的填写必须诚实**：`立即申诉` 与 `一字不改转投` 这两项只有如实记录才有价值——它是给未来的自己看的。

## 7. 与其他讲的接口

- **上游**：
  - `19 投稿记录`（第 19 讲）：意见挂在一次投稿之下。
  - `20 AI 使用日志`（第 20 讲）：回应信若由 AI 起草，是一条「实质性贡献」记录——**披露声明里可能要写到它**。
  - `17 段落卡`（第 17 讲）：误解型意见的回改落在具体段落卡上。
- **下游**：
  - `17 稿件`（第 17 讲）：修订版稿件；回应完成后 `稿件.当前工序` 回到 ⑨核查。
  - `19 投稿目标`：转投重走三维评估。
  - `23 复盘记录`（第 23 讲）：审稿意见里的模式进月复盘——**重复出现的意见类型是系统性问题，不是运气问题**。
  - `22 核查清单`（第 22 讲）：大修重投时清单完整重跑；意见提到的问题类型用于迭代 `核查模板`。
- **单一事实来源**：**意见与回应历史只在本表**；回应信文档是它的渲染产物。同一条意见不允许在回应信里另写一版而与 `回应·行动` 不一致。

- 拒稿率的年度统计与「恢复速度」指标（从拒稿到转投执行的天数）——它是第 24 讲反脆弱结构的一个观测点。

### 验收标准

1. `未分类` 视图为空：所有意见在动笔前都完成了分类。
2. `误解型未改正文` 视图为空：**没有悬空回应**。
3. `重述缺失` 与 `坐标不全` 两个视图为空：每条回应四段齐备。
4. 每条 `类型 = 方法性质疑型` 的意见，`证据链类型` 至少勾选一项，或 `主张收缩` 已勾选。
5. 每条 `AI 起草` 的回应，`事实核查` 与 `语气通读` 均已勾选。
6. `冷静期内` 视图中的记录无 `决定` 内容——冷静期被执行了，不是只被记录。
7. 转投决策的 `纳入修改的条目` 覆盖所有分类为方法性质疑型与补实验型的意见（`未吸收意见` 视图为空）。
8. 抽查一次冻结前的校对：回应表中的每个页码/图表编号与修改稿一致。

## 9. 与原文的偏差说明

| 偏差 | 原文做法 | 本设计做法 | 理由 |
| --- | --- | --- | --- |
| 逐条回应表的载体 | 文档（三列表） | 表 + 视图，文档只在导出时生成 | 文档形式只能靠人逐条看；做成表之后，**「重述缺失」「坐标不全」「误解型未改正文」三个常见漏洞各有一个视图捞它们** |
| 四段结构 | 四段文字 | 四个独立字段 | 合成一个字段时，缺了哪一段看不出来；拆开后，`重述缺失` 视图才有了判据 |
| 意见分类 | 会议投票归类 | 会议保留，结果落 `类型` 字段 | 分类动作必须留在会上（争议最大的条目最危险），但分类结论必须可查——否则下一轮审稿时无法统计「误解型占比」 |
| 冷静期 | 「48 到 72 小时」 | 自动设 3 天（72 小时）并加 `冷静期内` 视图 | 原文给的是区间；系统需要确定的默认值。取区间上限，因为「不做决定」的成本远低于「做错决定」 |
| 情绪化决策 | 描述两种错误决策 | `情绪化动作` 多选事后记录 | 原文的警告是事前性的；系统能做的唯一诚实的事是**事后记录你踩没踩**——它服务的对象是下一次的你 |
| 「稻草人回应」 | 「一旦改写审稿人的话，稻草人回应就不远了」 | 写进字段说明与《回应信》模板头部 | 这是一条关于手部动作的纪律，无法用字段强制；唯一能强制执行的是「原文逐字引用」这条，已在模板里钉死 |
| 甘特图 | 「标注负责人与预计工作量，回应工程即刻有了甘特图」 | 甘特视图（进度 = `工作量`，时间轴 = 回复期限） | 原文点名了甘特；系统的甘特视图正好对应——这是 24 讲里少数几处原文与现有能力一一对上的地方 |
| 转投三问 | 三个问题按顺序回答 | 三个单值字段 + `决定` 多行 | 三问的「按顺序」不做强制（没有能力做依赖式表单），但三问的答案必须各占一格——**空着的那一问就是你还没想清楚的那一问** |
