# 第 11 讲 消融实验设计：系统落地设计

> 来源：`../design_principle/第11讲_消融实验设计.pdf`
> 落地度：★★★★☆（高） ｜ 依赖：第 09 / 10 讲 ｜ 主体分期：P0
> 主产物：表 `11 消融计划`（一行 = 一个消融变体，含机器可读的机制解释）+ 表 `11 联合消融`（2×2 交互项的判定记录）

## 1. 本讲方法要点

1. **消融是一棵树，自上而下三层**：主干层·为什么有效（拿走核心机制还剩多少）→ 组件层·哪个部件重要（逐组件移除）→ 超参层·有多稳（扰动关键超参）。执行顺序自上而下。
2. **预算紧张时砍超参层密度、保主干层**。「主干层未做」是最高优先级告警：没有主干层消融的论文，机制主张是一句空话。
3. **按「信息量/成本比」排序**：信息量 = 该实验失败时对论文主结论的杀伤力。信息量高而成本低的先做。
4. **AI 排序有两处必须人工复核**：成本估计（AI 不知道你的排队时间与集群配额）与依赖关系（AI 看不出「组件乙的实现依赖组件甲的输出」这类真实依赖）。
5. **组件耦合有三种机制**：冗余（两个组件做同一件事，去掉其一不掉幅）、依赖（乙在甲之上，去掉甲则乙无意义）、拮抗（两个同时用反而差）。任何一种都导致**掉幅不可加**。
6. **全体移除实验是便宜的耦合诊断**：所有组件同时去掉跑一次；若总掉幅与逐个掉幅之和明显对不上，再去做 2×2 联合消融。
7. **2×2 联合消融测交互项**：含甲含乙 / 含甲去乙 / 去甲含乙 / 去甲去乙四格，比较「单独掉幅和」与「总掉幅」判定耦合类型。
8. **消融表四条规范**：完整模型在表中且位置固定（置顶）；每行只改一处；报 ∆ 列；与主表同协议（同数据、同评测、同种子档）。

## 2. 可落地性判定

| 能力点 | 落地形态 | 依托的现有能力 | 优先级 |

| 排序（信息量/成本） | `信息量评估`（AI 草稿）+ `信息量成本比排序`（人定稿）双字段 | 评分、多行文本 | P0 |
| 主干层保护 | `主干未做` 视图（最高优先级告警） | 过滤、颜色规则 | P0 |
| 耦合诊断 | 「全体移除优先」自动化 + `11 联合消融` | `record_created` + `add_comment`、关联 | P0 |
| 机制解释留痕 | `机制解释` 必填自动化（完成后）| `field_equals` + `add_comment` | P0 |
| 与主表协议一致 | `关联实验单元` 指向 `10 实验矩阵` | 关联字段 | P0 |
| 消融表规范检查 | 第 18 讲 `18 图表台账` 的 `消融表规范` 字段承接 | 跨讲接口 | P0 |
| AI 排序 | 站内智能体 `消融排序员`（tools） | `query_records` + `add_comment` | P0 |

**不建议系统化的部分**：

- **三种耦合机制的最终判断**。判定需要读代码与实现（「乙的输出是否被甲消费」），系统只提供 2×2 的数字骨架与 `判定` 字段，不自动判定。
- **超参扫描的具体设计**。扫哪些值、扫几档，依赖对模型的直觉，系统只登记结果。
- **消融数字的计算**。∆ 由人从运行结果回填；系统不做减法之外的统计。

## 3. 数据模型设计

空间：`科研方法`。表：`11 消融计划`（一行 = 一个消融变体）。

| 总掉幅 | 数字 | 完整模型 − 去甲去乙 |
| 判定 | 单选 | 近似可加 / 冗余 / 依赖 / 拮抗 |
| 判定依据 | 多行文本 | 数字对比 + 实现层面的原因 |
| 关联全体移除实验 | 关联 → `11 消融计划`（单值） | 全体移除那行 |

**建议视图**：见第 4 节。

**关系与公式**：

- `假设登记` → `11 消融计划`：一条假设一棵消融树。
- 自关联三处：`被移除/被扰动的对象`、`依赖组件`、`冗余嫌疑对`——树、依赖图与嫌疑对都靠自关联表达。
- `11 消融计划` → `11 联合消融`：联合消融引用两行组件。
- **不使用跨表聚合**：`单独掉幅和` 与 `总掉幅` 两个数字由人从运行结果计算后填入（表内不做多记录间的减法）。

### 3.2 记录样例

**样例 1（一棵三层消融树的四行——H-03 的组件：时间衰减打分 与 生效版本强制引用）**

| 字段 | 全体移除（主干层） | −时间衰减（组件层） | −强制引用（组件层） | 窗口 0.05→0.1（超参层） |
| --- | --- | --- | --- | --- |
| 变体名 | 全体移除 | −时间衰减 | −强制引用 | 衰减系数 0.05→0.1 |
| 改动说明 | 检索打分与引用约束同时关闭 | 移除检索打分中的时间衰减项 | 移除生成时的生效版本强制引用 | 只扰动衰减系数 |
| 预估成本 | 5 GPU 小时 | 5 | 5 | 5 |
| 信息量评估 | 主结论的「机制成立」全靠它——最高 | 次高：主干成立后，分摊归因 | 次高 | 低：只看稳定性 |
| 排序 / 决策 | 5 ／ 必做 | 4 ／ 必做 | 4 ／ 必做 | 2 ／ 预算不足时砍掉 |
| 结果指标 | EM 42.0 | 47.9 | 47.1 | 50.3（vs 完整 51.2） |
| ∆ | −9.2 | −3.3 | −4.1 | −0.9 |
| 机制解释 | 「全部时效机制贡献 +9.2，机制主张成立」 | 「时间衰减贡献 3.3 点——对应方法故事第 2 句『检索端的版本感知』」 | 「强制引用贡献 4.1 点——对应方法故事第 3 句『生成端的引用约束』」 | 「系数在 ±0.05 内稳定（掉幅 < 1 点），超参不敏感」 |

**样例 2（一张联合消融卡——判定为「冗余」）**

| 字段 | 值 |
| --- | --- |
| 名称 | 时间衰减 × 强制引用 联合消融 |
| 含甲含乙 / 含甲去乙 / 去甲含乙 / 去甲去乙 | 51.2 ／ 47.1 ／ 47.9 ／ 44.0 |
| 单独掉幅和 | 4.1 + 3.3 = 7.4 |
| 总掉幅 | 51.2 − 44.0 = 7.2 |
| 判定 | 近似可加 |
| 判定依据 | 7.4 vs 7.2，差值 0.2 在种子噪声内（5 种子 std ≈ 0.35）——两端机制基本正交，论文可以线性陈述「检索端 + 生成端」的贡献拆分 |
| 关联全体移除实验 | 全体移除行（∆ = −9.2 与 7.2 的差异来自全体移除时评测子集不同，已在 `判定依据` 备注） |

两张样例说明什么算「填得好」：**每一行的 `机制解释` 都能指回方法故事里的某一句话**——消融数字不是战绩，是叙事证据；样例 2 的 `判定依据` 里明说了「差值落在噪声内」，**没有把 0.2 的差距说成「有交互作用」**。

## 4. 视图与交互设计

| 视图名 | 类型 | 配置要点 |
| --- | --- | --- |
| 消融树 | grid | 按 `层级` 分组，从主干到超参自上而下排列；组内按 `信息量成本比排序` 降序——本讲主工作视图 |
| 排序待定 | grid | 过滤：`信息量成本比排序` 为空 |
| 主干未做 | grid | 过滤：`层级 = 主干层` 且 `状态 ≠ 已完成`；颜色规则：红色——**最高优先级告警** |
| 无机制解释 | grid | 过滤：`状态 = 已完成` 且 `机制解释` 为空 |
| 不可加清单（在 `11 联合消融` 上） | grid | 过滤：`判定 ≠ 近似可加`——它决定论文里组件贡献能不能线性陈述 |
| 砍掉登记（在 `11 消融计划` 上） | grid | 过滤：`存取决策 = 预算不足时砍掉`——被砍的部分要在论文局限里交代 |

**记录详情页布局**：

- `11 消融计划`（分组样式，两列）：分组 1「变体定义」：变体编号 / 假设 / 层级 / 变体名 / 改动说明 / 被移除/被扰动的对象；分组 2「排序」：预估成本 / 信息量评估 / 信息量成本比排序 / 存取决策；分组 3「结果」：状态 / 结果指标 / 与完整模型差值 ∆ / 机制解释；分组 4「关系」：依赖组件 / 冗余嫌疑对 / 关联实验单元。
- `11 联合消融`（分组样式，两列）：分组 1「四格」：名称 / 组件甲 / 组件乙 / 四个指标数字（单列）；分组 2「判定」：单独掉幅和 / 总掉幅 / 判定 / 判定依据 / 关联全体移除实验。

**表单**：新增表单视图 `加一个变体`，字段限定为 假设 / 层级 / 变体名 / 改动说明 / 预估成本 五项——布树时快速铺行。机制解释与排序不进表单。

## 5. 自动化设计

| 名称 | 触发器 | 条件 | 动作 | 防的坑 |
| --- | --- | --- | --- | --- |
| 全体移除优先 | `record_created` on `11 消融计划` | `层级 = 组件层` | `add_comment`（“先跑一次『全体移除』做耦合诊断：总掉幅与逐个掉幅之和明显对不上，再进 2×2 联合消融”） | 逐组件消完半年才想起耦合 |
| 完成即要机制解释 | `field_equals`（`状态` = 已完成） | `机制解释` 为空 | `add_comment`（“消融数字必须配一句机制解释，否则它只是数字”） | 消融表变成数字陈列 |
| 主干未做即告警 | `schedule weekly:1:09:00`（绑定 `11 消融计划`） | —— | `run_agent`（查 `主干未做` 视图，逐条 `add_comment`：“主干层消融未做：论文的机制主张目前没有证据”）+ `notify`（固定文案，**指定接收人**） | 主干层被推到「以后再说」 |

**关于周一的说明**：`weekly:1:09:00` 即每周一 09:00——主干告警放在周初，便于本周排期时被看见。**「非空才推」不可写成条件**：动作之间没有条件分支、也读不到智能体的输出，改为「固定推一句提醒 + 智能体逐条留言」，视图为空时留言自然为空。

> 自动化的四条动作边界（动作只作用于触发记录、动作之间无分支、`notify` 须指定接收人、`field_equals` 会重复命中）见 `README.md` §3 与 `_系统能力现状.md` §2。

## 6. 智能体设计

### 站内智能体

**`消融排序员`（模式：`tools`）**

- 工具：`query_records`（读 `11 消融计划` 与 `09 红队审查` 的替代解释）+ `add_comment`。
- 输入（用户提供）：方法描述、组件清单、各变体预估成本、论文主结论一句话。
- 输出：按信息量/成本比排序的建议；并指出可能存在依赖或冗余关系的组件对（各给一条理由）。**成本估计与依赖关系两处必须人工复核后再定稿排名。**
- 系统提示词骨架：

```text
你是消融实验的排序员。目标：用最少的 GPU 小时，最大化论文主结论的防御力。

【任务】对给定组件清单与成本估计：
1. 给每个变体一个信息量/成本比的排序建议，信息量的定义是「该实验失败时对主结论的杀伤力」；
2. 指出可能存在「依赖」或「冗余」关系的组件对，每对给一句实现层面的理由；
3. 标出你的两个不确定处：成本估计是否可信、依赖判断是否只是猜测。

【硬约束】
- 你只能给建议，最终排名由人定稿；把「需人工复核」标在排序表头部；
- 不允许因为「实验便宜」就把它排到信息量高的实验前面；
- 涉及具体 GPU 小时数一律引用我给的数字，不许自己估。
```

### 外部 MCP 工作流

1. **耦合诊断材料准备**：外部 Agent 按 `11 消融计划` 的组件清单，扫描代码仓库找出组件间的调用关系（「乙的输入是否来自甲的输出」），写入 `依赖组件` 草稿供人确认。
2. **∆ 汇总**：从 `实验记录`（第 15 讲）拉取各变体的主指标，计算与完整模型的差值，写回 `与完整模型差值 ∆`（标注计算依据）。

### 红线（AI 只能给草稿）

- **`信息量成本比排序` 由人定稿**。AI 的排序建议与人的定稿分开记录（`信息量评估` 是草稿字段，排序是定稿字段），呼应红线 2。
- **`机制解释` 必须人写**。这是方法故事的连接句，AI 写的机制解释会滑向「验证了方法的有效性」这类空话。
- **耦合 `判定` 由人填**。数字是骨架，判定要读实现。

## 7. 与其他讲的接口

- **上游**：`假设登记`（每个因果断言都要有一行消融数据——假设的「机制」要素是消融树的主干）；`10 实验矩阵`（消融变体也是矩阵行，`关联实验单元` 双向链接）。
- **下游**：
  - 第 18 讲：`18 图表台账` 的消融表承载四条规范检查；本表的每一行回填为消融表的一行。
  - 第 17 讲：`机制解释` 直接变成方法节与实验节的证据句（`17 段落卡` 的证据锚点）。
  - 第 22 讲：核查清单的统计区检查消融表与主表同协议。
- **单一事实来源**：**消融数字与机制解释只在本表**。论文消融表的每一行回填自这里，不允许手工另填一套数字。

## 8. 分期实施与验收

### P0（纯配置，零代码）

1. 建 `11 消融计划`（自动编号 `ab-`）与 `11 联合消融`。
2. 建视图：消融树 / 排序待定 / 主干未做 / 无机制解释 / 砍掉登记（本表）；不可加清单（联合消融）。
3. 建表单视图 `加一个变体`。
4. 建三条自动化：全体移除优先 / 完成即要机制解释 / 主干未做即告警。
5. 建站内智能体 `消融排序员`，提示词入 `提示词库`。
6. 与第 10 讲打通：`关联实验单元` 关联字段启用。

### P1（少量增强）

| 需求 | 说明 | 建议落点 |
| --- | --- | --- |
| ∆ 自动计算 | 现为人工从运行结果回填 | 脚本从 `实验记录` 拉取计算 |

### P2（可选）

- 消融树导出为论文消融表 LaTeX 骨架（配合第 18 讲）。
- 「被砍掉的消融」年度汇总：哪些层级的实验总在预算紧张时被砍——它是实验预算配置的复盘材料。

### 验收标准

1. `主干未做` 视图在论文进入写作工序前清零。
2. 每条 `状态 = 已完成` 的变体都有 `机制解释`，且解释能指回方法故事的具体句子。
3. 组件层存在时，`全体移除` 行一定存在且先于逐组件行完成。
4. `不可加清单` 里的每一条都有 `判定依据`（数字对比 + 实现原因）。
5. 每行消融的 `关联实验单元` 非空——消融数字与运行记录可互相追溯。
6. 论文消融表抽查两行，数字与本表一致（第 18 讲一致性检查的一部分）。

## 9. 与原文的偏差说明

| 偏差 | 原文做法 | 本设计做法 | 理由 |
| --- | --- | --- | --- |
| 信息量/成本比排序 | 一句方法（按比值排） | 一列可排序评分；`信息量评估`（AI 草稿）与 `信息量成本比排序`（人定稿）分字段 | 呼应红线 2：AI 排序的两处（成本、依赖）必须人工复核——用字段结构把「谁定了稿」钉死 |
| 耦合判定 | 三种机制的定性描述 | `11 联合消融` 的四格数字骨架 + `判定` 单选 + `判定依据` | 系统提供骨架与登记，判定留给读实现的人——这正是不建议系统化部分的边界 |
| 全体移除实验 | 经验技巧 | 「组件层新增即提醒」自动化 | 它便宜且关键，值得一条常驻提醒 |
| 被砍掉的实验 | 未规定 | `存取决策 = 预算不足时砍掉` + `砍掉登记` 视图 | 被砍的部分不是消失，而是变成论文局限与预算复盘的素材 |
| 消融表的四条规范 | 表格规范（写作层） | 拆到第 18 讲 `18 图表台账.消融表规范` 字段承接 | 「消融表的版式」属于图表规范；本表只保证数字与机制解释的质量 |
