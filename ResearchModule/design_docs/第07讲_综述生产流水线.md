# 第 07 讲 综述生产流水线：从五十篇到骨架：系统落地设计

> 来源：`../design_principle/第07讲_综述生产流水线从五十篇到骨架.pdf`
> 落地度：★★★★☆（高） ｜ 依赖：第 06 讲 ｜ 主体分期：P0
> 主产物：表 `07 综述项目`（工序状态机）+ 表 `07 聚类方案`（分类学的候选与仲裁记录）+ 表 `07 对照条目`（以表成文的原料，一行 = 一篇文献在一个分类里的一行）

## 1. 本讲方法要点

1. **四道工序不可颠倒**：①AI 聚类 → ②人工仲裁分类学 → ③逐篇填对照表 → ④以表驱动成文。每道工序有产物，产物不达标不进入下一道。
2. **分类的判据要落在方法机制上，而不是结果上**。「效果更好的工作」不是类别，「靠检索打分控制生成范围的工作」才是。判据必须能一句话判定一篇新论文的归属。
3. **每篇论文有且只有一个主归属**，无法归类的单列「交叉工作」。为了整齐而把类别数量做均衡，是综述失真的常见起点。
4. **对照表的列即维度**：核心假设、关键数字、已知局限——每多一列，正文就多一个可比较的维度；空格不是留白，是还没重读的信号。
5. **以表驱动成文**：按列组织段落（一段讲一个维度怎么演化），按行引用文献（每个论断落到具体行）。表立住了，文自然立住。
6. **四个探针识别空洞综述**：判据探针（分类有没有可操作判据）、比较探针（有没有真的横向比较）、张力探针（有没有指出尚未解决的矛盾）、删除探针（删掉任何一节，论证是否受损——不受损的就是废话）。
7. **一轮诚实修复通常砍掉三分之一**。修复的动作包括：补对照表列、补比较句、补「尚未解决」清单、删并空洞节。砍掉三分之一不是失败，是成文的正常代价。
8. **原料门槛**：综述的原料是 ≥40 篇已过第一遍判决的文献。原料不足时先回第 05–06 讲补检索与精读，不允许用 20 篇硬写五十篇的综述。

## 2. 可落地性判定

| 能力点 | 落地形态 | 依托的现有能力 | 优先级 |
| --- | --- | --- | --- |
| 工序状态机 | 表 `07 综述项目`，`本轮工序` 单选六段 | 单选、看板视图 | P0 |
| 分类学候选与仲裁 | 表 `07 聚类方案`（一方案一行）+ 采纳标记 | 关联、复选框、审定三件套 | P0 |
| 对照表 | 表 `07 对照条目`，一行 = 一篇文献的一段 | 关联 `文献库`、多行文本 | P0 |
| 「空格即重读信号」 | 自动化 + `空格清单` 视图 | `record_created` + `add_comment` + 过滤 | P0 |
| 原料门槛 | `原料篇数` 数字 + `原料不足警示` 自动化 | `field_equals` + `notify` | P0 |
| AI 聚类（两种方案） | 站内智能体 `聚类归纳员`（tools） | `query_records` + `add_comment` | P0 |
| 四探针自查 | `探针·判据/比较/张力/删除` 四个单选 + 视图 | 单选、过滤 | P0 |
| 分类学说明文档 | 文档挂靠（label「分类学说明」） | 文档 ↔ 记录挂靠 | P0 |
| 四探针诊断 | 站内智能体 `四探针诊断员`（prompt） | `prompt` 模式 | P0 |

**不建议系统化的部分**：

- **「以表驱动成文」的行文本身**。段落语气、过渡句属于写作现场；系统只保证表格立住。综述正文可以是系统内文档，也可以是外部 LaTeX——两种都接受。
- **分类的最终仲裁**。AI 给候选方案，人做仲裁——哪套分类学成立是学术判断，不进系统自动决策。
- **「这篇归哪类」的逐篇裁定**。占用人工时间最多，但这正是读文献的回报所在；系统只提供 `归属判据命中项` 字段记录你的判定依据。

## 3. 数据模型设计

### 3.1 表结构

空间：`科研方法`。表：`07 综述项目`（一行 = 一篇综述/一个开题）。

| 字段 | 类型 | 选项 / 说明 |

| 综述项目 | 关联 → `07 综述项目`（单值） | —— |

| 核心假设 | 多行文本 | 对照表第 1 列 |
| 关键数字 | 文本 | 对照表第 2 列（带数据集与基线） |

| 数据集 | 文本 | —— |
| 已知局限 | 多行文本 | 对照表第 3 列（从 `文献库.局限` 提炼） |
| 写作引用位置 | 文本 | 如「3.2 节第二段」 |

**建议视图**：见第 4 节。

**关系与公式**：

- `文献库` → `07 对照条目`：一篇文献可以在多篇综述中各占一行（不同综述的类别体系不同）。
- `07 综述项目` → `07 聚类方案` / `07 对照条目`：一对多。
- **不使用跨表聚合**：「已填行数 / 原料篇数」的完整率交给仪表盘；表内只放 `原料篇数` 这个事实字段。

**样例 2（聚类方案两份：AI 的与仲裁后的）**

| 字段 | 方案 A（AI 聚类） | 方案 B（人工仲裁后采纳） |
| --- | --- | --- |
| 分类维度 | 方法范式 | 问题设定 |
| 类别清单与判据 | 三派：段式索引派 / 打分融合派 / 生成约束派（判据：方法节的首个技术动作） | 两类问题：①「检索端时效」（文档版本管理）②「生成端时效」（引用与版本对齐）；判据：错答的第一个失效环节在哪 |
| 难以归类清单 | 4 篇（跨两派机制的组合方法） | 4 篇 → 单列「交叉工作」（皆同时处理两端时效） |
| 是否平衡过 | 否 | 否 |
| 生成方式 / 状态 | AI 聚类 / 已否决 | 人工拟定 / 已采纳 |
| 否决理由（备注或审定意见） | —— | 方案 A 的判据落在技术实现而非问题，读者视角偏工程；改为按「失效环节」分类后，张力探针更容易发现「两端都做、但没人做端间耦合」的空白 |

**样例 3（对照条目两行）**

| 字段 | 行 1 | 行 2 |
| --- | --- | --- |
| 文献 | Freshness-Aware Retrieval（第 06 讲样例 1） | Wang et al. 2025 生成端引用对齐（**需核实**） |
| 主归属类别 | 打分融合（段式索引 + 时间衰减打分） | 生成约束 |
| 归属判据命中项 | 方法第一动作：给检索文档打时效分 | 方法第一动作：生成时强制引生效版本 |
| 核心假设 | 相关性打分应包含时效项 | 错答的根因在生成端而非检索端 |
| 关键数字 | EM 44.1 → 51.2（问答集 A，BM25 基线） | 引用准确率 71% → 84%（同一问答集） |
| 已知局限 | 假定生效日期元数据完整（30% 文档缺失即失效） | 未处理同一文档多次修订的回溯 |
| 写作引用位置 | 3.2 节第二段 | 3.3 节第一段 |

三张样例说明什么算「填得好」：**方案 B 的 `难以归类清单` 变成了「交叉工作」而不是硬塞**；对照条目的 `已知局限` 列直接来自第 06 讲的手写局限——**上游字段的质量在这里兑现**。

## 4. 视图与交互设计

| 视图名 | 类型 | 配置要点 |
| --- | --- | --- |
| 工序看板 | kanban | 按 `本轮工序` 分列——本讲主工作视图（①AI 聚类 → … → 完成） |
| 未过探针 | grid | 过滤：四个探针任一 = 不通过 |
| 对照表（在 `07 对照条目` 上） | grid | 按 `主归属类别` 分组；列取 文献 / 核心假设 / 关键数字 / 已知局限——**可直接复制进论文** |
| 空格清单（同表） | grid | 过滤：`核心假设` 或 `关键数字` 或 `已知局限` 为空——**空格即重读信号** |
| 稀疏类别（同表） | grid | 按 `主归属类别` 分组后看哪类的 `关键数字` 稀疏（肉眼或仪表盘） |
| 交叉工作（同表） | grid | 过滤：`是否交叉工作` 勾选 |
| 分类方案对比（在 `07 聚类方案` 上） | grid | 按 `生成方式` 分组，看 AI 方案与人工方案的差异 |

**仪表盘 `综述进度`**：count（各工序项目数）；bar（按主归属类别的条目数——看类别是否均衡、交叉工作占比）；line（对照条目按周新增——填表是在推进还是停滞）。

**记录详情页布局**：

- `07 综述项目`（分组样式）：分组 1「定位」：名称 / 用途 / 关联稿件 / 主轴维度；分组 2「原料」：原料篇数 / 类别数 / 交叉工作数 / 分类学说明；分组 3「工序与探针」：本轮工序 / 四个探针 / 删减比例 / 状态。
- `07 对照条目`（分组样式）：分组 1「归属」：综述项目 / 文献 / 主归属类别 / 归属判据命中项 / 是否交叉工作；分组 2「对照列」：核心假设 / 关键数字 / 对比基线 / 数据集 / 已知局限（单列）；分组 3「写作」：写作引用位置 / 备注。

**表单**：新增表单视图 `填一页对照表`，字段限定为 综述项目 / 文献 / 主归属类别 / 归属判据命中项 四项——用于批量录入的主键部分；三个对照列留空，强制在详情页对照原文填写（空格的产生就该被看见）。

## 5. 自动化设计

| 名称 | 触发器 | 条件 | 动作 | 防的坑 |
| --- | --- | --- | --- | --- |
| 空格即重读信号 | `record_created` on `07 对照条目` | `核心假设` 为空 或 `关键数字` 为空 | `add_comment`（“此行有空格，按流水线纪律须回原文补齐，不留白”） | 空格被「以后再补」吃掉 |
| 原料不足警示 | `record_updated`（`原料篇数`） | `原料篇数` < 40 | `notify`（“原料不足 40 篇，先回第 5–6 讲补检索与精读”） | 用 20 篇硬写综述 |
| 探针不通过即回修 | `field_equals`（任一探针） | 任一探针 = 不通过 | `add_comment`（“探针不通过：对照修复路径——补对照表列 / 补比较句 / 补尚未解决清单 / 删并空洞节”） | 探针变成走过场 |

**关于「任一探针」的实现说明**：`field_equals` 一次只监听一个字段，四条探针需要配四条自动化（或改用 `record_updated` + 智能体巡检）。P0 采用四条独立自动化的形式，命名分别加探针后缀。

> 自动化的四条动作边界（动作作用范围限于触发记录或同库指定表、动作之间无分支、`notify` 须指定接收人、`field_equals` 会重复命中）见 `README.md` §3 与 `_系统能力现状.md` §2。

## 6. 智能体设计

### 站内智能体

**`聚类归纳员`（模式：`tools`）**

- 工具：`query_records`（拉取本项目关联的 `文献库` 条目：问题 / 假设 / 方法 / 关键数字）+ `add_comment`。
- 输出**两种互不相同的分类方案**：方案 A 按方法范式、方案 B 按问题设定；每类给一句可操作判据；列出难以归类的论文及原因。**禁止为了整齐而平衡各类数量**。
- 结果写入 `07 聚类方案`（`审定状态 = 待审定`），人工仲裁后标记采纳。
- 系统提示词骨架：

```text
你是文献聚类的归纳员。你的产出是「候选分类学」，不是最终分类。

【任务】基于给定的文献卡片，输出两套互不相同的分类方案：
- 方案 A：按方法范式分类；
- 方案 B：按问题设定分类。
每套方案包含：类别清单（每类一句可操作判据，判据必须能在不读全文的情况下判定一篇新论文的归属）、难以归类的论文清单及原因。
另外：指出你认为「两套方案都会放错位置」的论文，说明理由。

【硬约束】
- 禁止为了让各类数量好看而调整归属——不均衡本身是发现（可能某一类就是主流）；
- 判据不允许落在结果上（如「效果更好的方法」），必须落在方法机制或问题定义上；
- 你只提名，不裁决；每套方案标注「需人工仲裁」。
```

**`四探针诊断员`（模式：`prompt`）**

- 输入：综述正文（或分节文本）。
- 输出：逐节跑四个探针——判据探针（每个类别的判据可操作吗）、比较探针（有没有横向比较句，还是逐篇罗列）、张力探针（有没有指出尚未解决的矛盾）、删除探针（删掉这一节，论证是否受损）；每节给出修复路径（补对照表列 / 补比较句 / 补「尚未解决」清单 / 删并空洞节）。
- 输出写入项目记录评论，`删减比例` 由人在修复后回填。

### 外部 MCP 工作流

1. **对照表批量预填**：外部 Agent 读 `文献库` 五元组，把 `核心假设` / `已知局限` 起草为 `07 对照条目` 草稿（`审定状态 = 待审定`），人对照原文修订。
2. **分类一致性抽查**：对已填条目随机抽 10 行，用 `query_records` 复核「归属判据命中项」与主归属类别是否自洽。

### 红线（AI 只能给草稿）

- **分类学的采纳与否决由人仲裁**。AI 只能给两套候选。
- **`主归属类别` 的逐篇裁定由人执行**（`归属判据命中项` 是人写下的判据适用证据）。
- **四探针的通过判据由人填**。AI 诊断是修复清单的来源，不是结论。

## 7. 与其他讲的接口

- **上游**：`文献库`（第 06 讲，`阅读级别 ≥ 泛读` 且过幻觉隔离的条目）；`02 差异假设`（差异算子直接进 Related Work 的「空白陈述」段落）。
- **下游**：
  - `稿件`（第 17 讲）：综述成文直接作为论文章节骨架。
  - `08 主题索引`（第 08 讲）：分类学与主题索引互为交叉验证（分类学是横切，索引是纵切）。
  - 第 22 讲：核查清单的参考文献区检查综述引用完整性。
- **单一事实来源**：**分类学只在 `07 聚类方案` 与分类学说明文档里**。论文正文里的分类表述从本表回填；不在正文草稿里另立一套类别名。

## 8. 分期实施与验收

### P0（纯配置，零代码）

1. 建三张表：`07 综述项目` / `07 聚类方案` / `07 对照条目`。
2. 建视图：工序看板 / 未过探针（项目）；分类方案对比（聚类方案）；对照表 / 空格清单 / 稀疏类别 / 交叉工作（对照条目）。
3. 建表单视图 `填一页对照表`。
4. 建自动化：空格即重读信号 / 原料不足警示 / 四条探针自动化——`探针·判据不通过即回修` / `探针·比较不通过即回修` / `探针·张力不通过即回修` / `探针·删除不通过即回修`（`field_equals` 一次只监听一个字段，故拆成四条）。
5. 建两个智能体：`聚类归纳员` / `四探针诊断员`，提示词入 `提示词库`。
6. 建仪表盘 `综述进度`。
7. 分类学说明文档：P0 用系统文档 + 挂靠（label「分类学说明」）。

### P1（少量增强）

### P2（可选）

- 「张力清单」自动汇总：把各条目的 `已知局限` 做文本聚类，辅助「尚未解决」段落成文。

### 验收标准

1. 每条 `07 对照条目` 的三个对照列都非空（`空格清单` 在填表阶段之外保持为空）。
2. 每个综述项目的 `分类学说明` 文档存在，且每个类别都有一句可操作判据。
3. `难以归类清单` 的论文在对照条目里都以「交叉工作」身分存在，没有硬塞进某个类别。
4. 四个探针都有明确判定；`删减比例` 在完成修复后被回填（通常接近 1/3）。
5. AI 生成的两套聚类方案都在 `07 聚类方案` 里可查，且能看到「已被否决」的方案与理由——**否决记录是分类品味的训练材料**。
6. 对照表按 `主归属类别` 分组后，能直接复制进论文的 Related Work 表格且格式可用。

## 9. 与原文的偏差说明

| 偏差 | 原文做法 | 本设计做法 | 理由 |
| --- | --- | --- | --- |
| 对照表的载体 | 「一张纸」（表格文档） | 记录级表 `07 对照条目` | 空格可被筛选、稀疏可被统计、引用位置可被定位——原文想用肉眼完成的三个自查动作变成三个视图 |
| AI 聚类的产出 | 一轮聚类方案 | 强制两套互不相同的方案 + 否决记录留档 | 单方案容易让人「直接采用」；两套方案把仲裁这个动作逼出来 |
| 工序控制 | 文字描述的先后纪律 | `本轮工序` 单选 + 看板 | 工序状态可见，才不会在「①没做完」的时候偷偷干④ |
| 探针检查 | 成文后的自查清单 | 四个单选字段 + 自动化 + 诊断智能体 | 探针的判定结果需要成为可统计的记录（哪类探针最常不通过） |
| 分类学说明的位置 | 讲中提到 | 系统文档 + 挂靠记录 | 分类学的边界案例需要长文本承载，文档比字段合适；挂靠保证它与项目同源 |
