# 第 05 讲 检索系统：从关键词到语义：系统落地设计

> 来源：`../design_principle/第05讲_检索系统从关键词到语义.pdf`
> 落地度：★★★★★（高） ｜ 依赖：第 02 讲 ｜ 主体分期：P0
> 主产物：表 `05 检索式`（静态资产：可复用、可版本化）+ 表 `05 检索日志`（动态执行：一次检索一行）

## 1. 本讲方法要点

1. **关键词检索有三个结构性盲区**：同义分裂（同一概念有多种叫法，只用一个词必然漏检）、概念过新（术语尚未成型，关键词根本不存在）、跨域迁移（别的领域已解决的问题，在这里换了名字）。三个盲区都不是「多试几个词」能解决的。
2. **关键词保查准、语义保查全**，两者互补而非替代。三轮检索法：第一轮种子检索（关键词）→ 第二轮滚雪球（后向：种子论文的参考文献；前向：引用了种子论文的新工作）→ 第三轮 AI 语义扩展。
3. **前向滚雪球是发现「谁在场」的最快方式**。一个子领域的三五篇种子论文，前向引用列表基本勾勒出全部门派与最近的推进者。
4. **饱和判定**：新增关键论文连续一轮低于入库量的 5%，判定饱和。饱和不是「搜够了」，而是「多搜一轮的边际产出低于时间成本」。
5. **检索式宽窄两版并行维护**：宽式查全（用于扫描与饱和判定），窄式查准（用于定向跟踪与投稿前的补检）。两版都要版本化。
6. **布尔算符与字段限定是检索式的骨架**：OR 组同义词、AND 组概念、NOT 排噪声（如排除综述、预印本重复源）；字段限定（标题/摘要/关键词/全文）控制精度与召回。
7. **检索日志使检索可复盘、可抗辩、可增量更新**：时隔半年重跑检索，靠的不是记忆而是日志——写了什么式子、什么日期、命中多少、筛后多少、新增多少。
8. **语义检索的执行不在系统内**。系统登记检索的结果与日志，不替代 Google Scholar / Semantic Scholar / arXiv 本身——这条边界要写清楚，避免把系统当成检索引擎。

## 2. 可落地性判定

| 能力点 | 落地形态 | 依托的现有能力 | 优先级 |
| --- | --- | --- | --- |
| 检索式资产化 | 表 `05 检索式`，一行 = 一版式子 | 自动编号 `Q-`、多选、自关联 | P0 |
| 检索过程留档 | 表 `05 检索日志`，一行 = 一次执行 | 关联、数字字段、日期 | P0 |
| 饱和判定 | `新增率` 数字 + `是否达饱和` 复选框 + 视图 | `field_equals` + `add_comment` | P0 |
| 低效检索发现 | `低效检索` 视图（命中 > 1000） | 过滤 | P0 |
| 宽窄配对管理 | `替代版本` 自关联 + `版本类型` 单选 | 关联字段 | P0 |
| 词表扩展 | 站内智能体 `词表扩展员` + 强制挂复核 | `prompt` 模式、`复核记录` | P0 |
| 批量登记命中数 | 外部 MCP 把各库命中数批量写回 | MCP `create_record` / `update_record` | P1 |
| 新增率自动计算 | 现为人工填写（比值不在表内算） | P1 脚本或公式增强 | P1 |

**不建议系统化的部分**：

- **检索的执行本身**。系统不内置检索引擎；外部库（Scholar / Semantic Scholar / arXiv）的检索动作在站外发生，系统只登记结果。站内智能体也不联网。
- **「这一篇该不该入库」的初筛判断**。留 / 弃是研究者的核心训练（第 06 讲第一遍阅读的目标），系统只记录决定与原因。
- **数据库字段语法的校验**。不同库的字段限定语法不同（`TI=` vs `title:`），系统不做语法检查，只存原文。

## 3. 数据模型设计

### 3.1 表结构

空间：`科研方法`。表：`05 检索式`（一行 = 一版检索式）。

| 字段 | 类型 | 选项 / 说明 |
| --- | --- | --- |
| 编号 | 自动编号（前缀 `Q-`） | —— |
| 主题 | 文本 | 这条检索式服务什么主题/假设 |
| 版本类型 | 单选 | 宽式 / 窄式 |
| 数据库 | 单选 | 库A / 库B / 库C / 自定义（按常用库建选项：arXiv / Semantic Scholar / Google Scholar / 数据库） |
| 检索式原文 | 多行文本 | 可直接复制粘贴进网站的原文 |
| 字段限定 | 多选 | 标题 / 摘要 / 关键词 / 全文 |
| 布尔结构 | 多行文本 | 每个限定词的作用说明（「OR 组的同义词从哪来」也要写） |
| 版本号 | 数字 | 每次修改递增 |
| 替代版本 | 关联 → 本表（单值） | 宽式对应哪版窄式（或反之） |
| 状态 | 单选 | 在用 / 已收紧 / 已废弃 |

表：`05 检索日志`（一行 = 一次检索执行）。

| 字段 | 类型 | 选项 / 说明 |
| --- | --- | --- |
| 日期 | 日期 | 执行日 |
| 数据库 | 单选 | 同 `05 检索式.数据库` |
| 检索式 | 关联 → `05 检索式`（单值） | 用的哪版式子 |
| 轮次 | 单选 | 第一轮·种子 / 第二轮·后向滚雪球 / 第二轮·前向滚雪球 / 第三轮·语义扩展 |
| 命中数 | 数字 | 检索返回条数 |
| 筛后保留数 | 数字 | 标题摘要初筛后保留条数 |
| 新增入库数 | 数字 | 实际登记进 `文献库` 的条数 |
| 新增率 | 数字 | 人工填（新增入库数 / 上轮累计入库量）；比值不在表内算 |
| 是否达饱和 | 复选框 | 判据：`新增率 < 0.05` |
| 种子论文 | 关联 → `文献库`（多值） | 第二轮滚雪球的种子；第一轮留空 |
| 备注 | 多行文本 | 「同义词过多，v2 收紧」这类判定，写在这里 |

**建议视图**：见第 4 节。

**关系与公式**：

- `05 检索式` → `05 检索日志`：一对多；一次执行一行。
- `05 检索日志` → `文献库`（第 06 讲）：入库文献的 `检索来源` 反向关联到日志，形成「这篇从哪次检索来的」链。
- `替代版本` 是自关联：宽式 `Q-02` 与窄式 `Q-03` 互指。
- **不使用跨表聚合**：「本轮累计入库量」「相对上轮的比值」都不在表内算——`新增率` 人工填或 P1 脚本，饱和视图靠阈值筛选。

### 3.2 记录样例

**样例 1（宽窄两版检索式，来自同一条假设）**

| 字段 | 宽式 Q-04 | 窄式 Q-05 |
| --- | --- | --- |
| 主题 | G-07 时效性约束与检索增强 | 同上 |
| 数据库 | 库B（Semantic Scholar） | 库B |
| 检索式原文 | `("retrieval augmented" OR RAG) AND (temporal OR "effective date" OR "time-sensitive" OR freshness) AND (QA OR "question answering" OR compliance)` | 同前，加 `AND ("regulatory" OR "compliance")` 且字段限定收紧为标题+摘要 |

| 布尔结构 | OR 组同义词来自 `词表扩展员` 草稿（已核验 6 条）；NOT 未使用 | 窄式主要用于定向跟踪；同义词组减到 3 个 |

| 替代版本 | Q-05 | Q-04 |
| 状态 | 在用 | 在用 |

**样例 2（一条判定饱和的日志）**

| 字段 | 值 |
| --- | --- |
| 日期 | 2026-11-20 |
| 检索式 | Q-04（宽式 v2） |
| 轮次 | 第三轮·语义扩展 |
| 命中数 | 187 |
| 筛后保留数 | 41 |
| 新增入库数 | 2 |
| 新增率 | 0.021（上轮累计入库 96 篇） |
| 是否达饱和 | 勾选 |
| 备注 | 语义扩展轮新增均来自「freshness-aware retrieval」这一新表述；判定饱和，后续走增量跟踪（每周前向滚雪球），不重开全量 |

## 4. 视图与交互设计

| 视图名 | 类型 | 配置要点 |
| --- | --- | --- |
| 本轮进度 | grid | 按 `轮次` 分组，看每轮的命中数与新增数；这是检索作业的主视图 |
| 饱和判定 | grid | 过滤：`新增率 < 0.05`；默认隐藏（在 `05 检索日志` 上按需打开） |
| 低效检索 | grid | 过滤：`命中数 > 1000`；这些记录用于收紧式子，而不是逐条读完 |
| 语义扩展轮 | grid | 过滤：`轮次 = 第三轮·语义扩展`；与 `05 检索式` 对照，看语义扩展救回了哪些盲区 |
| 在用检索式 | grid（在 `05 检索式` 上） | 过滤：`状态 = 在用`；按 `主题` 分组，宽窄成对显示 |

**记录详情页布局**：

- `05 检索式`（分组样式，两列）：分组 1「定义」：编号 / 主题 / 版本类型 / 数据库 / 版本号 / 状态；分组 2「原文与结构」：检索式原文 / 字段限定 / 布尔结构（单列）；分组 3「配对」：替代版本。
- `05 检索日志`（分组样式，两列）：分组 1「执行」：日期 / 数据库 / 检索式 / 轮次；分组 2「数量」：命中数 / 筛后保留数 / 新增入库数 / 新增率 / 是否达饱和；分组 3「种子与备注」：种子论文 / 备注。

**表单**：新增表单视图 `登记一次检索`，字段限定为 日期 / 数据库 / 检索式 / 轮次 / 命中数 / 筛后保留数 六项——检索执行完当场登记，`新增入库数` 与 `新增率` 等入库完成后回详情页补。

## 5. 自动化设计

| 名称 | 触发器 | 条件 | 动作 | 防的坑 |
| --- | --- | --- | --- | --- |
| 饱和即收束 | `field_equals`（`是否达饱和` = 勾选） | —— | `add_comment`（“本轮新增率低于 5%，判定检索饱和；后续新增文献进入增量更新流程（前向滚雪球），不要重开全量检索”） | 饱和后反复重跑全量，时间黑洞 |
| 低效检索提醒 | `field_equals`（`命中数` > 1000） | —— | `add_comment`（“命中过千：先收紧字段限定或加 AND 组，再逐条筛”） | 逐条读千条命中的假勤奋 |
| 检索式未配对提醒 | `record_created` on `05 检索式` | `替代版本` 为空 | `add_comment`（“宽窄两版应成对维护：请补建或关联另一版”） | 只有一套式子，查全与查准二选一的盲区 |

**关于跨表动作的说明**：契约设想的「饱和时把对应 `05 检索式` 置为已废弃」涉及跨表写入，`set_field` 只能修改触发记录自身的字段。因此这条自动化降级为评论提示 + 人工处置（把式子状态改为「已收紧」而非「已废弃」通常在语义上更准确）。

> 自动化的四条动作边界（动作只作用于触发记录、动作之间无分支、`notify` 须指定接收人、`field_equals` 会重复命中）见 `README.md` §3 与 `_系统能力现状.md` §2。

## 6. 智能体设计

### 站内智能体

**`词表扩展员`（模式：`prompt`）**

- 输入：种子论文的标题与摘要（1–3 篇）。
- 输出三样：①同义表述清单（同一概念的不同叫法）；②相邻子领域清单（这个问题在别的领域叫什么）；③「若存在反对或替代路线，最可能叫什么」的猜测清单。
- 产出写入 `05 检索式.布尔结构` 草稿或评论，**并强制在 `复核记录`（第 04 讲）挂一条「AI 提供的词表须逐条回库验证」**——词表是检索的地基，不能让 AI 的猜测直接当钢筋。

```text
你是学术检索的词表扩展员，服务一个研究人员的关键词检索。

【任务】对给定种子论文，输出三份清单：
1. 同义表述：同一概念在该领域内可能出现的不同叫法（缩写、全称、变体写法），每条标注「我的把握程度：高/中/低」；
2. 相邻子领域：这个问题在其他领域可能叫什么（举出领域名与该领域的叫法）；
3. 替代路线：如果存在与这篇论文思路相反的路线，它最可能被命名为什么。

【硬约束】
- 你是提名者，不是确认者：清单里的每一项都标注「需回库检索验证」；
- 不允许宣称任何术语「已被广泛使用」；
- 把握程度为「低」的条目也要给出——宁可多给待验证项，不可漏掉盲区候选。
```

### 外部 MCP 工作流（P1，原文未要求，属于系统增益）

1. **批量登记命中数**：外部 Agent 执行各库检索，用 `create_record` 把命中数批量登记为 `05 检索日志` 草稿。
2. **前向滚雪球材料准备**：按种子论文 DOI 拉取引用列表（Semantic Scholar API），把「引用它的工作」标题批量写回日志备注草稿。

### 红线（AI 只能给草稿）

- **词表在进入 `检索式原文` 前必须逐条核验**（复核记录挂账）——检索式的可信度决定整条文献链的可信度。
- **`是否达饱和` 由人判定**。AI 可以算数，但「边际产出低于成本」的阈值判断是研究者的节奏。
- **入库筛选（留 / 弃）由人做**。这是第 06 讲第一遍阅读的训练场。

## 7. 与其他讲的接口

- **上游**：`02 差异假设`（`状态 = 待检索` 的假设 → 定向检索）；`01 问题矩阵`（待核实单元格的定向补检）。
- **下游**：
  - `文献库`（第 06 讲）：入库文献反向关联 `检索来源`。
  - 第 07 讲：综述的检索段落直接据本表成文（命中数、轮次、饱和判定都有原文记载）。
  - 第 08 讲：泛读登记的文献进入主题索引。
  - 第 19 讲：查「该刊近两年被引数」一类数据也走本表登记。
- **单一事实来源**：**检索式与命中数只在本表**。综述、开题报告里的「检索策略」章节从本表成文，不另记一份。

## 8. 分期实施与验收

### P0（纯配置，零代码）

1. 建 `05 检索式`（自动编号 `Q-`）与 `05 检索日志`。
2. 建四个视图：本轮进度 / 饱和判定 / 低效检索 / 语义扩展轮；在 `05 检索式` 上建 `在用检索式`。
3. 建三条自动化：饱和即收束 / 低效检索提醒 / 检索式未配对提醒。
4. 建站内智能体 `词表扩展员`，提示词入 `提示词库`。
5. 在 `文献库`（第 06 讲）建成后建立 `检索来源` 反向关联。

### P1（少量增强）

| 需求 | 说明 | 建议落点 |
| --- | --- | --- |
| `新增率` 自动计算 | 需「上轮累计入库量」，跨表聚合只有 `TABLECOUNT`，比值表达不了 | 脚本（文档约定）或公式增强（`src/store.ts`） |
| 检索式字段语义校验 | 不同库语法不同，暂存原文即可 | P2 或外部脚本 |
| 批量登记命中数 | 每次手工登记六项数值，可被 MCP 批量替代 | 外部 Agent 脚本 |

### P2（可选）

- 检索式质量档案：把每个式子的历史命中率、饱和轮次汇总成一条 line 图，看哪些同义词组总有贡献。
- 与 `08 主题索引` 联动：主题词表的变更自动提示相关检索式待更新。

### 验收标准

1. 每条 `在用` 检索式都有配对的另一版（`替代版本` 非空），宽窄成对。
2. 每篇 `文献库` 新记录都能通过 `检索来源` 指回一次检索日志（第一轮种子文献允许空）。
3. `饱和判定` 视图里的每条日志都能回答「相对哪一轮累计量算的 5%」。
4. `低效检索` 视图中的记录都发生过收紧动作（有后续版本的式子或备注里写了收紧方式）。
5. `语义扩展轮` 的记录能看到至少一条「关键词检索漏掉、语义扩展找回」的备注——若从未出现，语义轮在走过场。
6. `词表扩展员` 的每一次产出都能在 `复核记录` 里找到对应的核验条目。

## 9. 与原文的偏差说明

| 偏差 | 原文做法 | 本设计做法 | 理由 |
| --- | --- | --- | --- |
| 检索日志的粒度 | 一节「检索日志」喻示的记录习惯 | 拆成 `05 检索式`（静态资产）与 `05 检索日志`（动态执行）两张表 | 「半年后把旧检索式改个日期重跑」这个高频动作，在两张表下变成「复制一行 + 改日期」 |
| 饱和判定的落地 | 一条经验判据（新增 < 5%） | `新增率` 数值 + `是否达饱和` 复选 + 视图阈值 | 阈值是纪律、数值是事实，两者分开记录才能半年后复盘判据本身是否合理 |
| 语义检索的位置 | 作为第三轮检索方法 | 明确标注为系统外动作，系统只登记结果 | 能力边界：系统不内置检索与向量计算，写清楚避免读者误以为可以做语义搜索 |
