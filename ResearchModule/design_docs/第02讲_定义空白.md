# 第 02 讲 定义空白：系统落地设计

> 来源：`../design_principle/第02讲_定义空白.pdf`
> 落地度：★★★★☆（高） ｜ 依赖：第 01 讲 ｜ 主体分期：P0
> 主产物：表 `02 差异假设`（把「填补空白」升级为「定义空白」的立案台账）+ 表 `02 空白三问`（三问的判断记录，二问的负结果线索在这里累积）

## 1. 本讲方法要点

1. **填补空白是找到别人没做过的格；定义空白是把它写成一个可检索、可证伪、可抗辩的命题**。系统承载的永远是后者——格子只是候选面，命题才是研究单元。
2. **反向文献检索四步**：先写下你的假设（不许边查边改）→ 让 AI 找出最接近的已有工作 → 人工核验这些工作真实存在且确实最接近 → 写出差异算子。
3. **差异算子有三类要素：方法、设定、结论**。至少占两类才算立住；只占一类的，大概率是换皮。算子的句子格式是「在 X 上与 A 文不同；在 Y 上与 B 文不同；在 Z 上首次给出……」。
4. **空白可信度三问必须按顺序回答**：一问有没有人做过（事实问题）→ 二问为什么没做成（因果问题）→ 三问条件是否刚成熟（时机问题）。跳过二问的选题，最容易死在「别人试过，失败原因是结构性的」。
5. **三问是仪表盘，不是关卡**。它的作用是让你看见每条假设停在哪一问上；系统不阻止状态推进，只让未完成的部分可见。
6. **「没人做过」是某个检索时间的截面结论**，空白会被时间侵蚀。任何存活的假设都需要一个重检到期机制（默认 90 天），到点就按「新进预印本」重算边界。
7. **最接近工作的核验是人工动作**。AI 擅长找出「看起来最接近」的候选，但「确实最接近」这个判断要落到读过原文的人身上。

## 2. 可落地性判定

| 能力点 | 落地形态 | 依托的现有能力 | 优先级 |
| --- | --- | --- | --- |
| 立案台账 | 表 `02 差异假设`，一行 = 一条待立案的想法 | 自动编号 `G-`、关联、多选 | P0 |
| 三问逐问记录 | 表 `02 空白三问`，一行 = 一问 | 关联→差异假设、单选结论、多行依据 | P0 |
| 差异算子「至少两类」检查 | `差异维度数` 多选 + `差异单薄` 视图 | 多选、过滤 | P0 |
| 最接近工作登记 | `最接近工作` 关联→`文献库`（第 06 讲） | 关联字段、文献库 | P0 |
| 重检到期机制 | `下次重检时间` 日期 + 定时巡检 | `schedule daily:09:00` + `run_agent` | P0 |
| AI 找最接近工作（联网） | 外部 MCP：检索→写回 `最接近工作` 草稿 | MCP `query_records` / `update_record` | P0 |
| 假设的批判性预审 | 站内智能体 `魔鬼代言人` | `prompt` 模式 + 评论 | P0 |
| 三问通过后的节奏保护 | 「通过即提示 90 天重检」自动化 | `field_equals` + `add_comment` | P0 |
| 二问负结果线索汇总 | `负结果线索` 多行字段 + `未过二问` 视图 | 多行文本、过滤 | P0 |

**不建议系统化的部分**：

- **写假设的那一击**。核心假设第一版必须由人手写——AI 起草的假设会系统性地偏向「已有工作附近」，恰好破坏了本讲的目的。系统提供 `核心假设一句话` 字段，但不提供生成按钮。
- **「为什么没做成」的判断**。系统记录结论（通过/不通过/未知）与依据，不自动判定。二问的答案往往藏在失败论文的局限性讨论里，需要人读原文。
- **「条件是否刚成熟」的时机感**。这依赖对算力、数据、社区动向的综合判断，系统只留 `依据` 字段承载结论。

## 3. 数据模型设计

### 3.1 表结构

空间：`科研方法`。表：`02 差异假设`。

| 字段 | 类型 | 选项 / 说明 |
| --- | --- | --- |
| 编号 | 自动编号（前缀 `G-`） | 全书引用假设的统一编号 |
| 核心假设一句话 | 文本（标题字段） | 必须同时含方法、对象、约束三要素 |
| 方法要素 | 文本 | 与下一节的「一句话」互为检查 |
| 对象 | 文本 | 在什么数据/场景/人群上 |
| 约束 | 文本 | 在什么条件下成立 |
| 立案来源 | 关联 → `01 问题矩阵`（单值） | 从哪个交叉点立案 |
| 最接近工作 | 关联 → `文献库`（多值） | 人工核验通过后才建立关联 |
| 重叠区域 | 多行文本 | 与最接近工作重合的部分（可 AI 起稿） |
| 未覆盖部分 | 多行文本 | 差异所在（可 AI 起稿） |
| 差异算子 | 多行文本 | 定稿必须手写；「更高效」这类含混表述不接收 |
| 差异维度数 | 多选（方法 / 设定 / 结论） | 字段名沿用设计契约；填的是命中的维度，便于筛「只占一类」 |
| 三问状态 | 单选 | 未开始 / 部分完成 / 三问通过 / 三问否决 |
| 状态 | 单选 | 待检索 / 已检索 / 存活 / 并入他题 / 已证伪 / 已放弃 |
| 最近重检时间 | 日期 | 每次重检后更新 |
| 下次重检时间 | 日期 | 三问通过时置为今天 + 90 天 |
| 新进预印本 | 多行文本 | 重检时发现的新工作，每行一条 |
| 审定状态 | 单选 | 待审定 / 已审定 / 退回 |
| 审定人 | 成员 | —— |
| 审定时间 | 日期 | —— |

表：`02 空白三问`（一行 = 一问）。

| 字段 | 类型 | 选项 / 说明 |
| --- | --- | --- |
| 假设 | 关联 → `02 差异假设`（单值） | 一条假设最多三行 |
| 问序 | 单选 | 一问·有没有人做过 / 二问·为什么没做成 / 三问·条件是否刚成熟 |
| 结论 | 单选 | 通过 / 不通过 / 未知 |
| 依据 | 多行文本 | 结论的证据：出处、页码、原文摘句 |
| 检索式 | 关联 → `05 检索日志`（多值） | 第 05 讲建成后回填 |
| 负结果线索 | 多行文本 | 专为二问：类似思路的失败尝试、局限性讨论 |
| 回答人 | 成员 | —— |
| 日期 | 日期 | —— |

系统字段「创建人 / 创建时间 / 修改时间」自动保留，是「何时写下这条假设」的证据。

**建议视图**：见第 4 节。

**关系与公式**：

- `01 问题矩阵` → `02 差异假设`：一个交叉点可以孵出多条假设；`立案来源` 是这条关联的正向入口。
- `02 差异假设` → `02 空白三问`：一对多；三问的结论汇总成人读的 `三问状态`，但**不写跨表聚合公式**——状态由人推进，避免「三行都填了通过但人还没看过」的自动放行。
- `最接近工作` → `文献库`：与第 06 讲的幻觉隔离联动——文献未核验时，它不能被列为「最接近工作」。

### 3.2 记录样例

**样例 1（停在二问的假设——这是最需要被系统盯住的一类）**

| 字段 | 值 |
| --- | --- |
| 编号 | G-07 |
| 核心假设一句话 | 在金融合规问答上，用「生效日期感知」的检索增强微调约束生成范围，降低监管文本时效性错答 |
| 方法/对象/约束 | 生效日期感知检索 ／ 金融合规问答 ／ 单卡可训练、监管文本公开可得 |
| 最接近工作 | Zhang et al. 2024《Retrieval-Augmented Compliance QA》（DOI 核验中）、FinQA 相关两篇（需核实） |
| 差异算子 | 在**设定**上与 Zhang et al. 不同（他们不建模文档生效日期）；在**结论**上若成立，将给出「时效性错答率」这一新指标的基线 |
| 差异维度数 | 设定、结论 |
| 三问状态 | 部分完成（一问通过、二问待答） |
| 状态 | 已检索 |
| 下次重检时间 | 空（未过三问，不设重检） |

**样例 2（被二问否决——否决理由要写满，它是下一轮选题的资产）**

| 字段 | 值 |
| --- | --- |
| 编号 | G-11 |
| 核心假设一句话 | 用跨机构联合训练提升医疗文本去标识化效果 |
| 三问状态 | 三问否决 |
| 状态 | 已证伪 |
| 二问依据（见 `02 空白三问`） | 类似思路在 2021 年有至少两次尝试（两篇局限性讨论明确写了机构数据不出域），失败原因是**结构性**的：合规要求数据不得离开机构，跨机构联合训练的通信成本与合规成本在可预见期内不降 |
| 负结果线索 | 记录了两篇失败工作的局限段落摘句；下次遇到「联邦学习 + 敏感数据」类假设时先查这里 |

两张样例的差别说明什么算「填得好」：`差异算子` 写得像命题而不像愿望；`下次重检时间` 只在三问通过后才出现——**空着是诚实，不是遗漏**。

## 4. 视图与交互设计

| 视图名 | 类型 | 配置要点 |
| --- | --- | --- |
| 存活假设 | kanban | 按 `状态` 分列；存活列置前。这是本讲主工作视图 |
| 三问待答 | grid | 过滤：`三问状态 = 未开始` 或 `部分完成`；排序：创建时间升序；颜色规则：超过 14 天未推进 → 行标黄 |
| 重检到期 | grid | 过滤：`下次重检时间 ≤ 今天` 且 `状态 = 存活`；这是「空白被时间侵蚀」的哨兵 |
| 差异单薄 | grid | 过滤：`差异维度数` 只勾了 1 项（多选含任一但数量不足两项，用两条过滤条件表达）；排序：创建时间降序 |
| 未过二问 | grid（在 `02 空白三问` 上） | 过滤：`问序 = 二问` 且 `结论 ≠ 通过`。**这是最容易被跳过、也最致命的拦路石** |

**记录详情页布局**（分组样式，两列）：

- 分组 1「命题」：核心假设一句话 / 方法要素 / 对象 / 约束
- 分组 2「边界」：最接近工作 / 重叠区域 / 未覆盖部分 / 差异算子 / 差异维度数（此组单列排布）
- 分组 3「三问与状态」：三问状态 / 状态 / 最近重检时间 / 下次重检时间 / 新进预印本
- 分组 4「审定」：审定三件套

**表单**：新增表单视图 `立案`，字段限定为 核心假设一句话 / 方法要素 / 对象 / 约束 / 立案来源 五项——用于组会现场把一条口头想法立成记录。差异算子与三问不进表单，强制走详情页（这两个动作需要有「坐下来查文献」的仪式感）。

## 5. 自动化设计

| 名称 | 触发器 | 条件 | 动作 | 防的坑 |
| --- | --- | --- | --- | --- |
| 三问通过即给节奏 | `field_equals`（`三问状态` = 三问通过） | —— | `add_comment`（“请在今天填写 `最近重检时间`，并把 `下次重检时间` 置为今天 + 90 天；届时按新进预印本重算边界”）+ `notify` | 通过三问后放羊，空白在半年后已被别人填上 |
| 重检巡检 | `schedule daily:09:00` | —— | `run_agent`（查 `重检到期` 视图，逐条 `add_comment`：请就新增工作重算差异算子，**禁止自动改 `状态`**）→ 若 ≥3 条则 `feishu_bot` 汇总 | 「没人做过」被当作永久结论 |
| 立案来源回填 | `record_created` on `02 差异假设` | `立案来源` 为空 | `add_comment`（“若这条假设来自某个问题矩阵单元格，请建立关联——没有来源的假设无法被统计进选题命中率”） | 假设与问题地图脱节，第 24 讲无法做「簇」的检验 |

**关于日期动作的说明**：`下次重检时间` 采用「评论文本提醒 + 人工填写」而不是 `set_field` 直接写相对日期——现有 `set_field` 对「今天 + N 天」这类相对取值没有明确支持。若后续确认支持，可把第一条自动化升级为 `set_field`，标为 P1。

## 6. 智能体设计

### 站内智能体

**`魔鬼代言人`（模式：`prompt`）**

- 输入：核心假设一句话 + 最接近工作清单（用户把 `文献库` 中该假设关联条目的摘要粘贴进对话）。
- 输出：三块判定草稿——①重叠区域：这个想法与最接近工作重合了什么；②未覆盖部分：真正差异在哪，比人写的更挑剔；③最坏情况：如果这个想法已无空白，最可能的反证是什么。
- 结果写入 `重叠区域` / `未覆盖部分`（`审定状态` 保持 `待审定`），人工修改后改状态。
- 系统提示词骨架：

```text
你是这条研究假设的魔鬼代言人。你的职责不是帮助它成立，而是尽最大努力找出它不成立的理由。

【任务】对给定假设与最接近工作清单，输出三块内容：
1. 重叠区域：逐条列出与已有工作重合的部分，标注重合的工作编号；
2. 未覆盖部分：列出确实未被覆盖的部分；若你认为没有实质未覆盖部分，直接说「我认为这个想法已无空白」，并给出理由；
3. 反证路径：如果这个想法是错的，最可能通过哪个实验、哪篇文献被发现。

【硬约束】
- 你只输出草稿，不允许把任何内容写成结论口吻；
- 涉及具体文献的判断必须标注「需人工核实原文」；
- 不允许给出「这个方向值得做」这类鼓励性判断。
```

**`二问专审员`（模式：`prompt`）**

- 用途：对一条假设专攻二问——「如果这个方向没做成，最可能的原因是什么」。输入假设与相邻领域的失败案例描述，输出失败原因候选清单（数据不可得 / 指标不可定义 / 工程成本 / 合规约束 / 学术共同体不接受），每条附一个可验证的排查动作。
- 输出写入该假设二问记录的 `负结果线索`，供人逐一排查。

### 外部 MCP 工作流

1. **AI 找最接近工作**：外部 Agent 用 `query_records` 拉出 `状态 = 待检索` 的假设 → 联网检索（arXiv / Semantic Scholar）→ 用 `update_record` 把候选工作的标题、DOI 写回 `重叠区域` 草稿字段，**不直接建立 `最接近工作` 关联**。
2. **最接近工作的真实性核验**：逐条 DOI 解析（走第 22 讲脚本），核验通过后人工建立关联，并在 `复核记录`（第 04 讲）挂一条通过记录。

### 红线（AI 只能给草稿）

- **`核心假设一句话` 的第一版必须手写**。AI 只能在你写完之后提意见。
- **`差异算子` 定稿必须手写**。AI 起的草稿只能进 `重叠区域` / `未覆盖部分`。
- **三问的 `结论` 必须人填**。系统提示词中明确禁止智能体触碰 `02 空白三问` 的写入工具。

## 7. 与其他讲的接口

- **上游**：
  - `01 问题矩阵`：`个人匹配度 ≥ 中` 且已核实的单元格 → 立案（`立案来源` 关联）。
  - `文献库`（第 06 讲）：`最接近工作` 从此取值，且必须已过幻觉隔离。
- **下游**：
  - 第 03 讲：`状态 = 存活` 的假设 → 进入 `03 可行性冲刺`。
  - 第 05 讲：`状态 = 待检索` 的假设触发定向检索，检索记录回填 `02 空白三问.检索式`。
  - 第 09 讲：冲刺通过后立案为 `假设登记` 的 `H-` 编号，`来源` 字段指回本表。
  - 第 07 讲：`差异算子` 直接进入综述的 Related Work 铺垫段落。
- **单一事实来源**：**空白命题与差异算子只在本表维护**。研究计划书、组会 PPT 里的「与已有工作的差异」段落都从本表导出，不在别处另存可编辑副本。

## 8. 分期实施与验收

### P0（纯配置，零代码）

1. 建 `02 差异假设`（含字段表全部字段，自动编号前缀 `G-`）与 `02 空白三问`。
2. 建五个视图：存活假设 / 三问待答 / 重检到期 / 差异单薄 / 未过二问。
3. 建表单视图 `立案`。
4. 建三条自动化：三问通过即给节奏 / 重检巡检 / 立案来源回填。
5. 建站内智能体 `魔鬼代言人` 与 `二问专审员`，提示词入 `提示词库`（第 01 讲）。
6. 在 `文献库` 建好后补建 `最接近工作` 关联（第 06 讲 P0 的一部分）。

### P1（少量增强）

| 需求 | 说明 | 建议落点 |
| --- | --- | --- |
| `下次重检时间` 自动 = 今天 + 90 天 | 现在靠评论文本提醒人工填写 | `set_field` 支持相对日期取值（`src/store.ts` 自动化动作实现） |
| 差异维度「数量不足」的单条过滤 | 多选「只勾 1 项」需要两条过滤条件组合表达，配置繁琐 | 过滤器支持 `count_in` 一类语义，或视图保存模板 |
| 90 天周期可配置 | 不同领域侵蚀速度不同 | 自动化参数配置 |

### P2（可选）

- 用外部 MCP Agent 做「预印本哨兵」：每周按假设关键词扫描 arXiv，结果写入 `新进预印本` 草稿。
- 把 `02 空白三问` 的负结果线索汇总成一页「本领域失败原因清单」，作为选题训练的教材。

### 验收标准

1. 打开 `存活假设` 看板，能一眼说出有哪几条假设停在 `已检索`（即三问未过）。
2. 新建一条 `三问状态 = 三问通过` 的假设，**自动出现提示评论**要求填写重检日期。
3. `未过二问` 视图非空——说明二问确实在被回答，而不是被跳过。
4. 每条 `状态 = 存活` 的假设都有非空的 `差异算子`，且算子句里能指出至少两个要素（方法/设定/结论）的差异位置。
5. `重检到期` 视图中的记录都在一周内被处理过（有新的评论或更新的 `最近重检时间`）。
6. 在 `魔鬼代言人` 的输出里能看到明确的「我认为这个想法已无空白」这类否决性判断（若从未出现，说明它在敷衍）。

## 9. 与原文的偏差说明

| 偏差 | 原文做法 | 本设计做法 | 理由 |
| --- | --- | --- | --- |
| 三问的记录形式 | 一张检查表，问答写在假设旁边 | 独立表 `02 空白三问`，一问一行 | 使「停在哪一问」可筛选、二问的负结果线索可跨假设累积；一张表只能看不能查 |
| 三问的强制程度 | 建议按顺序回答 | 视图 + 颜色规则让未完成可见，但不设硬闸门 | 原文明确「三问是仪表盘不是关卡」；系统尊重这一点，只做可见性不做拦截 |
| 差异算子的检查 | 自然语言纪律「至少占两类」 | `差异维度数` 多选 + `差异单薄` 视图 | 把纪律变成可筛选的结构；只占一类的假设会在视图里自己浮出来 |
| 重检机制 | 提示空白会被时间侵蚀 | 90 天默认周期 + 定时巡检 + 新进预印本字段 | 原文未给周期，本设计取 90 天为默认值（可调），把「重检」从意识变成动作 |
| 最接近工作的来源 | 未规定 | 必须关联 `文献库` 且已过核验的条目 | 防止把 AI 幻觉出的「最接近工作」当成真的对手；与第 06 讲的幻觉隔离共用一道防线 |
