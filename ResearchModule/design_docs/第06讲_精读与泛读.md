# 第 06 讲 精读与泛读：三遍阅读法的人机分工：系统落地设计

> 来源：`../design_principle/第06讲_精读与泛读三遍阅读法的人机分工.pdf`
> 落地度：★★★★★（高） ｜ 依赖：第 05 讲 ｜ 主体分期：P0
> 主产物：共享表 `文献库`（全书的文献唯一事实来源，第 05 / 07 / 08 / 19 / 20 / 22 讲共用）+ 表 `06 复现检查`（第三遍阅读的检查台账）

## 1. 本讲方法要点

1. **泛读:精读 ≈ 4:1**。大量泛读是为了让少数精读有意义；反过来，没有精读的泛读只是收藏。
2. **三遍阅读法的人机分工**：第一遍由 AI 预读出题（读标题、摘要、结论，产出验证问题清单），人来判决去留；第二遍人机对照精读（AI 对照人写的五元组挑错）；第三遍由人做复现性检查。
3. **第一遍的目标是淘汰，不是理解**。十分钟扫读，读不懂就弃读——读不懂通常意味着前置文献还没读，而不是这篇不够好。淘汰理由必须写下来，它是后续检索调优的输入。
4. **五元组卡片（问题 / 假设 / 方法 / 证据 / 局限），半页以内**。卡片是给未来的自己读的，不是给原作者看的。
5. **`证据` 只写带定位的数字**（哪个表、第几页、哪个数据集）；**`局限` 必须手写**——AI 写的局限永远是「计算成本较高」这类泛泛之词，而「局限」的品味是研究者的核心资产。
6. **幻觉有三种形态**：无中生有（引用不存在的文献）、张冠李戴（把 A 的结论记到 B 头上）、数字漂移（85.6 记成 85.3）。对应三条核查纪律：引用落定位、数字回表核、未核实项隔离。
7. **隔离要靠状态机，不靠自觉**：AI 起草的条目先进 `待审定` 状态并被降级为「未读」，人工核验来源后才允许升为精读、进入综述与论文引用。
8. **第三遍复现性检查按需触发**：这篇将进入论文对比表或复现计划时，检查五件事——代码公开吗（能跑吗）、数据公开吗、超参与训练细节完整吗、关键数字对得上吗（回表核）、基线强吗。检查结论回写 `文献库`，成为论文局限章节与审稿回应的弹药。

## 2. 可落地性判定

| --- | --- | --- | --- |
| 文献唯一台账 | 共享表 `文献库`，一篇一行 | 自动编号、关联、多选、附件 | P0 |
| 三遍分级 | `阅读级别` 单选（未读/泛读/精读/已复现/弃读） | 单选、看板 | P0 |

| 淘汰理由留档 | `淘汰理由` 必填（弃读时）+ `弃读归档` 视图 | 过滤、颜色规则 | P0 |
| 复现性检查 | 表 `06 复现检查`，一文献可多轮 | 关联、单选 | P0 |
| AI 预读出题 | 站内智能体 `预读出题机` | `prompt` 模式 + 评论 | P0 |
| 批量入库 | 外部 MCP 把检索结果写为 `文献库` 草稿 | MCP `create_record` | P0 |
| 每周清理未核实项 | 定时巡检 + 通知 | `schedule weekly:5:17:00` + `run_agent` | P0 |
| DOI 批量核验 | 外部脚本（第 22 讲脚本清单） | MCP + 脚本 | P1 |

**不建议系统化的部分**：

- **「十分钟扫读」的时间纪律**与**「五分钟读不懂就回头泛读前置文献」的止损判断**。这是阅读现场的自我训练，不建字段、不做计时器。
- **精读本身**。系统承载卡片与核查状态，不承载「读懂」这件事。
- **PDF 的全文解析**。系统附件只存 PDF，不做全文索引；「按正文内容搜索文献」超出能力边界。

### 3.2 记录样例

**样例 1（一篇完整精读——对照 G-07 的检索链路）**

| 字段 | 值 |
| --- | --- |
| 标题 | Freshness-Aware Retrieval for Regulatory Question Answering（**需核实：题名与作者以实际检索为准**） |
| 作者 / 年份 / 发表处 | 待核 ／ 2025 ／ arXiv |
| 阅读级别 | 精读 |
| 问题 | 监管问答中检索到的文档版本与生效日期错位，导致答非所问 |
| 假设 | 若在检索打分中引入「生效日期衰减」项，时效性错答率显著下降 |
| 方法 | ①文档集按生效日期分段索引；②打分 = 语义相似度 × 时间衰减因子；③生成时强制引用生效版本（3 个步骤，公式见其 §3.2 式 4） |
| 证据 | 监管问答集 A 上 EM 从 44.1 → 51.2（其表 3 第 2 行）；错答率 18.7% → 11.3%（其表 4） |
| 关键数字 | 表 3 第 2 行：EM +7.1（相对其 BM25 基线） |
| 局限（**手写**） | 假定生效日期元数据完整——真实监管库中 30% 文档缺该字段；未处理「同一文档多次修订」的引用回溯 |
| 可复用部件 | 时间衰减打分函数（其附录 A 伪代码）；问答集 A 的评测脚本 |
| 怀疑点 | 表 4 的错答率定义未说明人工标注口径 |
| 复现结论 | 部分可复现（代码未公开，数据公开） |
| AI 起草栏位 | 问题、方法 |
| 人力核实 | 勾选（证据栏两个数字均已回表核对） |
| 检索来源 | Q-04 第三轮·语义扩展（2026-11-20） |

**样例 2（一篇善终的弃读）**

| 字段 | 值 |
| --- | --- |
| 标题 | A Survey on Temporal Knowledge Graphs（**需核实**） |
| 阅读级别 | 弃读 |
| 淘汰理由 | 领域是时序知识图谱推理，与本课题的「文档时效性」只是共享「时间」一词；读完摘要与引言即判定，未进入五元组 |

两张样例说明什么算「填得好」：**`证据` 栏的数字带表号定位，`局限` 栏写的是具体的机制缺陷而不是「计算成本高」**——前者让 `人力核实` 可以真的去核，后者让第 07 讲的对照表有真维度可用；弃读样例的 `淘汰理由` 写清了「为什么像但不同」，它是下次检索的边界知识。

## 5. 自动化设计

| 名称 | 触发器 | 条件 | 动作 | 防的坑 |
| --- | --- | --- | --- | --- |
| 精读即要求定位 | `field_equals`（`阅读级别` = 精读） | —— | `add_comment`（“请确认：`证据` 栏每个数字都带定位（页码/表号）；`局限` 栏由你手写，不得由 AI 代劳”） | 精读退化成「读摘要 + 抄摘要」 |
| 幻觉隔离 | `record_created` on `文献库` | `审定状态 = 待审定` | `set_field`（`阅读级别` = 未读，强制降级）+ `add_comment`（“此条尚未核验来源，禁止进入综述与论文引用；核验后手动升为精读”） | AI 起草的条目直接进正文引用 |
| 每周清理未核实项 | `schedule weekly:5:17:00`（绑定 `文献库`） | —— | `run_agent`（查 `未核实项` 视图，逐条 `add_comment`：“本周内完成核验或退回”）+ `notify`（固定文案，**指定接收人**；清单在视图里看，不在推送里复述） | 未核实项无限期挂着 |
| 弃读缺理由 | `field_equals`（`阅读级别` = 弃读） | `淘汰理由` 为空 | `add_comment`（“淘汰理由是一笔资产：写清为什么像但不同，它是下次检索的边界知识”） | 弃读不留痕，白读 |

**关于 `weekly:5:17:00` 的说明**：cron 的 `D` 取值 0=周日 … 6=周六，`5` 即周五；每周五 17:00 巡检符合「每周统一清理一次」的节奏。推送只发固定提醒，具体哪几条待清理由智能体写在记录评论里——动作读不到智能体的输出，清单也不该在推送里复述。

> 自动化的四条动作边界（动作作用范围限于触发记录或同库指定表、动作之间无分支、`notify` 须指定接收人、`field_equals` 会重复命中）见 `README.md` §3 与 `_系统能力现状.md` §2。

## 6. 智能体设计

### 站内智能体

**`预读出题机`（模式：`prompt`）**

- 输入：标题 / 摘要 / 结论（第一遍扫描时的三段材料）。
- 输出四样：①六个精读必答问题（覆盖问题定义、方法机制、证据链、局限）；②作者声称的三点贡献，**区分「声称」与「已被其证据支持」**；③结论依赖的前提假设；④该文可能的三个弱点位置（供第二遍带着问题读）。
- 规则：不确定的地方写明「不确定」；一切具体数字标注「需回原文第 X 节核对」；产出写入评论，人裁定后进 `文献库`。

```text
你是文献精读的出题员。你拿到的是标题、摘要与结论——仅此三段，不要假装读过全文。

【任务】输出四块内容：
1. 精读必答问题 6 个：覆盖该文的问题定义、方法机制、证据强度、潜在局限，问题要能直接拿着去读原文；
2. 作者声称的贡献（最多 3 点），每点标注「摘要声明 / 结论声明」，并标注你是否能仅凭这三段判断它「已被证据支持」——不能就写「无法判断」；
3. 该文结论依赖的前提假设（列出你能看出的，标注「需核验」）；
4. 可能的弱点位置：带着这些问题去读时，最值得警惕的三处。

【硬约束】
- 不给出「值得精读 / 不值得精读」的结论——去留由人判决；
- 不允许编造方法细节；你没看到的就说没看到；
- 所有数字一律标注「需回原文核对」。
```

### 外部 MCP 工作流

1. **批量入库**：外部 Agent 用 `query_records` 确认查重（DOI/标题）→ `create_record` 把检索结果写为 `文献库` 草稿（`审定状态 = 待审定`，触发幻觉隔离）。
2. **DOI 批量核验**：对 `未核实项` 里的条目批量 DOI 解析（第 22 讲脚本），核验通过者 `update_record` 填写 `发表处` 与 `年份`，但**不修改 `阅读级别`**。

### 红线（AI 只能给草稿）

- **`局限` 字段禁止 AI 写入**（`AI 起草栏位` 的选项里没有它，系统提示词里也要写明）。设计文档、字段配置、提示词三处都要钉住这条。
- **`阅读级别` 的升格由人执行**。从「未读」到「精读」意味着有人读过原文了——这个语义不能被自动化代表。
- **`人力核实` 只能由人勾选**，它代表「我，一个人，回原文核过」。

## 7. 与其他讲的接口

- **上游**：`05 检索日志`（`检索来源`）；`02 差异假设`（为某条假设的定向精读队列）。
- **下游**：
  - 第 07 讲：五元组卡片是综述聚类的原料（`阅读级别 ≥ 泛读`）。
  - 第 08 讲：`泛读登记` 与 `主题` 字段喂养主题索引；`关联关系` 字段承接关系网络。
  - 第 19 讲：参考文献里的中青年作者 → `19 审稿人候选`。
  - 第 20 讲：`引用核验` 的文献元数据从这里取值。
  - 第 22 讲：核查清单的参考文献区与图像区交叉检查引用。
  - 第 02 讲：`最接近工作` 只能关联「已过幻觉隔离」的条目。
- **单一事实来源**：**一篇文献只在本表一行**。综述、引用列表、核验记录都关联到它；不允许在别处另存摘要或元数据副本。

### 验收标准

1. `未核实项` 视图在日常工作中保持接近空——它非空且超期，说明核查纪律在失守。
2. 每篇 `阅读级别 = 精读` 的文献都有非空 `局限`（手写）与勾选的 `人力核实`。
3. `证据` 栏的数字抽查三条，都能按定位在原文表格里找到——找不到即幻觉泄漏，回查 `复核记录`。
4. AI 起草的条目在核验前全部处于 `未读`（幻觉隔离生效），且该条在 `复核记录`（第 04 讲）有对应条目。
5. `弃读归档` 里的每条都有 `淘汰理由`，且理由能区分「领域不同」与「质量不足」。
6. `复现候选` 队列随时间被消费（`复现结论` 从「未检查」向结论迁移），`不可复现清单` 逐步积累。
7. 仪表盘上泛读:精读的比例接近 4:1 而不是 1:20（后者说明没做泛读筛选）。

## 9. 与原文的偏差说明

| 偏差 | 原文做法 | 本设计做法 | 理由 |
| --- | --- | --- | --- |
| 卡片与条目的关系 | 第 6 讲讲五元组卡片，第 8 讲讲五字段条目，二者高度重叠 | 合并为一张 `文献库`：五元组（问题/假设/方法/证据/局限）+ 五字段（关键数字/可复用部件/怀疑点/关联关系/主题）做字段并集，用 `阅读级别` 区分深度 | 同一篇文献出现两条互相矛盾的记录，是「单一事实来源」红线最直接的破坏方式 |
| 幻觉隔离的执行 | 核查三纪律（自觉执行） | 状态机：AI 起草 → `待审定` + 自动降级为「未读」 → 核验后人工升格 | 纪律会被赶进度吃掉；字段与自动化不会 |
| 局限的归属 | 强调五元组里局限最难写 | `AI 起草栏位` 的选项中物理排除 `局限`；字段说明与提示词双重声明 | 用界面结构保护最容易退化的那一步 |
| 第三遍检查的组织 | 讲为阅读法的第三遍 | 独立表 `06 复现检查`，按需触发、可多轮 | 「按需触发」意味着它需要自己的队列（`复现候选` 视图）与结论库（`不可复现清单`） |
| 淘汰理由 | 第一遍的输出物 | 弃读时必填 + 归档视图 | 淘汰理由的分布是检索质量的证据，必须成为结构而不是记忆 |
