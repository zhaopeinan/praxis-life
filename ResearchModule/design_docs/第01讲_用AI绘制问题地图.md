# 第 01 讲 用 AI 绘制问题地图：系统落地设计

> 来源：`../design_principle/第01讲_用AI绘制问题地图.pdf`
> 落地度：★★★★★（高） ｜ 依赖：无（全书入口） ｜ 主体分期：P0
> 主产物：`01 问题矩阵`（把模糊主题变成可比较、可排序的研究单元）+ 共享表 `提示词库`（全书提示词的唯一存档）

## 1. 本讲方法要点

1. **二维问题矩阵**是把网状、雾状的主题转化为可比较研究单元的工具：横轴取「方法/技术路线」，纵轴取「场景/约束」。
2. **坐标轴选取原则**：横轴尽量互斥，纵轴尽量穷尽。互斥性决定单元格能不能清晰定位，穷尽性决定会不会在后期发现「还有一个更大的空白」。
3. 矩阵的每个单元格必须是**可核查的事实项**，而不是一句话的感受：代表工作、公开数据集、常用指标、主要瓶颈。单元格背后要能追溯到至少一篇真实论文或一个真实数据集；只能凭感觉填的，列入「待核实」而不是直接采纳。
4. **提示词三段式**：角色（Role）→ 约束（Constraints）→ 输出格式（Format）。角色越具体，AI 调用相关知识越精准；约束的本质是缩小搜索空间；统一输出格式是为了后续能筛选排序。
5. 规模控制：坐标轴数量控制在 **4×4 以内**，超过则单元格填充质量明显下降，宁可分两次生成。
6. **要求 AI 在不确定的单元格标注「待核实」，而不是强行填满**——空格比错格更有价值。
7. **三条纠偏策略**，针对 LLM 的 popularity bias 与时间截面偏差：强制时间切片（要求列出近三个月的新兴子方向）、引入冷门维度（低资源语言、极端天气、长尾故障）、反共识指令（给出与主流相反但有文献支撑的角度）。
8. 矩阵成型后的关键动作是**叠加个人优先级标注**：数据可及性、兴趣、导师资源——这一步只有人能判断，AI 不做。

## 2. 可落地性判定

| 能力点 | 落地形态 | 依托的现有能力 | 优先级 |
| --- | --- | --- | --- |
| 二维问题矩阵 | 表 `01 问题矩阵`，一行 = 一个交叉点 | 单选（横轴/纵轴）、评分（饱和度/可及性）、视图两级分组 | P0 |
| 单元格事实项 | 多行文本字段（代表工作/数据集/指标/瓶颈） | 多行文本 | P0 |
| 「待核实」机制 | `核实状态` 单选 + 闸门视图 + 创建时自动置为待核实 | `record_created` 自动化、`set_field`、`add_comment` | P0 |
| 提示词三段式与版本管理 | 共享表 `提示词库` | 多行文本、多选、版本号 | P0 |
| 4×4 规模控制 | 视图内计数 + 仪表盘切片器 | 仪表盘 count 图 + 切片器 | P0 |
| 三条纠偏策略 | `是否冷门维度` 字段 + 智能体「反共识审查」+ 时间切片的提示词模板 | 智能体 `prompt` 模式、`提示词库` | P0 |
| 个人匹配度排序 | `个人匹配度` 单选 + 优先候选视图 | 单选、过滤、排序 | P0 |
| 定期清理待核实积压 | 定时巡检 + 飞书提醒 | `schedule daily:09:00` + `run_agent` + `feishu_bot` | P0 |
| AI 生成内容的核验留痕 | 逐条 `复核记录`（定义于第 04 讲） | 关联字段、`add_comment`（跨表建档由人补录，见第 04 讲） | P0 |

**不建议系统化的部分**：

- **坐标轴的选取与互斥性/穷尽性的判断**。这属于人的选题直觉与领域理解，系统只承载结果（两个单选字段），不为它设计「坐标轴质量评分」之类的伪量化。
- **「哪个交叉点与你的能力、资源、兴趣最匹配」**。原文明确说这只有你自己能判断。系统提供 `个人匹配度` 字段承载结论，但不提供推荐算法。
- **矩阵的完整度**。原文说矩阵的目的不是穷尽所有方向，而是把你从「到处看」变成「定点比」。系统不追求把矩阵填满，追求的是每一格都能被核实或被显式标记为待核实。

## 3. 数据模型设计

### 3.1 表结构

空间：`科研方法`。表：`01 问题矩阵`。

| 字段 | 类型 | 选项 / 说明 |
| --- | --- | --- |
| 交叉点 | 文本（标题字段） | 命名规范「横轴 × 纵轴」，如「微调 × 医疗」 |
| 横轴-技术路线 | 单选 | 提示工程 / SFT / RAG / Agent 工作流 / …（按课题即时增补） |
| 纵轴-应用场景 | 单选 | 自动驾驶 / 医疗影像 / 工业质检 / 金融合规 / 边缘场景 / … |
| 是否冷门维度 | 复选框 | 对应纠偏策略二；勾选者在视图中单独成群 |
| 代表工作 | 多行文本 | 每行一条，每条须能指回真实论文（作者 + 年份 + 出处） |
| 公开数据集 | 多行文本 | 每条给出可访问的获取方式 |
| 常用指标 | 多行文本 | —— |
| 研究饱和度 | 评分 1-5 | 5 = 已有大量工作、创新空间小 |
| 数据算力可及性 | 评分 1-5 | 5 = 公开可得、单卡可跑 |
| 一句话瓶颈 | 文本 | 不是感受，是「数据可及但指标不统一」这类精确描述 |
| 个人匹配度 | 单选 | 高 / 中 / 低（由人填） |
| 生成方式 | 单选 | AI 生成 / 人工补充 / 人工核验后修改 |
| 核实状态 | 单选 | 待核实 / 已核实 / 存疑 / 查无出处 |
| 核实人 | 成员 | —— |
| 核实时间 | 日期 | —— |
| 关联假设 | 关联 → `02 差异假设`（多值） | 从某格直接立案时建立 |
| 审定状态 | 单选 | 待审定 / 已审定 / 退回 |
| 审定人 | 成员 | —— |
| 审定时间 | 日期 | —— |

系统字段「创建人 / 创建时间 / 修改时间」自动保留，是本表「不可事后涂改」的证据来源。

**共享表 `提示词库`**（定义于此讲，全书共用）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 名称 | 文本（标题字段） | 如「问题矩阵生成提示词 v2」 |
| 用途 | 文本 | 一句话说明它解决什么 |
| 适用讲次 | 多选 01–24 | 便于按讲次取用 |
| 角色 | 多行文本 | 三段式的第一层 |
| 约束 | 多行文本 | 三段式的第二层（含时间切片、数量上限、允许「待核实」） |
| 输出格式 | 多行文本 | 三段式的第三层（表格列定义） |
| 完整提示词 | 多行文本 | 可直接复制粘贴的成品 |
| 版本 | 数字 | 每次修改递增 |
| 最近使用 | 日期 | —— |
| 状态 | 单选 | 可用 / 实验中 / 停用 |
| 关联记录 | 文本 | 记录用它的那条数据的编号 |

**建议视图**：见第 4 节。

**关系与公式**：

- `01 问题矩阵` → `02 差异假设`：单向关联（一个交叉点可以孵出多条假设）。
- `文献库` ← 反向关联：单元格中的「代表工作」在核验阶段可以建立与 `文献库` 的双向关联，让「核查过」这件事有据可查。P0 阶段允许先用多行文本承载，P1 建议改为关联（见第 8 节）。
- 本表**不使用跨表聚合公式**：饱和度的平均值一类统计交给仪表盘，避免在表内算比值。

### 3.2 记录样例

**样例 1（AI 生成、尚未核实——这是最需要被系统盯住的一类）**

| 字段 | 值 |
| --- | --- |
| 交叉点 | RAG × 金融合规 |
| 横轴 / 纵轴 | RAG ／ 金融合规 |
| 代表工作 | Zhang et al. 2024, *Retrieval-Augmented Compliance QA*（需核实是否存在） |
| 公开数据集 | FinQA（需核实版本与许可） |
| 常用指标 | Exact Match、引用准确率 |
| 研究饱和度 | 3 |
| 数据算力可及性 | 4 |
| 一句话瓶颈 | 监管文本时效性强，检索到的版本与生效日期容易错位 |
| 个人匹配度 | 中 |
| 生成方式 | AI 生成 |
| 核实状态 | 待核实 |

**样例 2（人核验后，进入优先候选）**

| 字段 | 值 |
| --- | --- |
| 交叉点 | Agent × 工业质检 |
| 代表工作 | Li et al. 2023（已读到原文第 4 节）；Wang et al. 2025（已下载 PDF） |
| 公开数据集 | MVTec-AD（已确认可公开下载）、自建缺陷库（需合作方授权） |
| 研究饱和度 | 2 |
| 数据算力可及性 | 5 |
| 一句话瓶颈 | 长尾故障覆盖不足，公开集里没有对应子类 |
| 个人匹配度 | 高 |
| 生成方式 | 人工核验后修改 |
| 核实状态 | 已核实 ｜ 核实人：本人 ｜ 核实时间：2026-10-20 |

两张样例的差别说明了什么算「填得好」：字段齐不齐是次要的，**核实状态是否诚实**是主要的。第二条的每一行都能被人追问到出处，第一条的三处标注了「需核实」。

## 4. 视图与交互设计

| 视图名 | 类型 | 配置要点 |
| --- | --- | --- |
| 矩阵总览 | grid | 按 `横轴-技术路线` → `纵轴-应用场景` 两级分组（系统上限 3 层）；行高紧凑；隐藏 `审定*` 三字段；列顺序：交叉点 / 代表工作 / 数据集 / 指标 / 饱和度 / 可及性 / 个人匹配度 / 核实状态 |
| 优先候选 | grid | 过滤：`研究饱和度 ≤ 2` 且 `数据算力可及性 ≥ 4` 且 `核实状态 = 已核实`；排序：可及性降序 → 饱和度升序。**这是本讲的主工作视图** |
| 待核实清单 | grid | 过滤：`核实状态 = 待核实`；排序：创建时间升序；行高紧凑。颜色规则：创建超过 7 天未核实 → 行标黄 |
| 反共识边角 | grid | 过滤：`是否冷门维度 = 勾选` 或（`研究饱和度 = 5` 且 `个人匹配度 = 高`）；用一个视图同时承接纠偏策略二与「饱和度高不代表没有细分切口」这条原文提醒 |
| 查无出处 | gallery | 过滤：`核实状态 = 查无出处`。用画册视图保留失败记录——它是下一轮提示词改进的输入 |

**仪表盘 `选题雷达`**：

- bar：各 `横轴-技术路线` 的平均研究饱和度（看哪条路线整体已拥挤）
- pie：`个人匹配度` 高/中/低占比
- count：`待核实` 数、`优先候选` 数、`查无出处` 数三个计数卡
- line：按周新增单元格数（看矩阵是在生长还是在积灰）
- 切片器：按 `纵轴-应用场景` 切片，用于向导师汇报时逐场景过一遍

**记录详情页布局**（分组样式，两列）：

- 分组 1「定位」：交叉点 / 横轴 / 纵轴 / 是否冷门维度 / 个人匹配度
- 分组 2「事实项」：代表工作 / 公开数据集 / 常用指标 / 一句话瓶颈（这一组的字段都是多行，单列排布）
- 分组 3「评分」：研究饱和度 / 数据算力可及性
- 分组 4「核实」：生成方式 / 核实状态 / 核实人 / 核实时间 / 审定三件套

**表单**：新增一个 `表单` 视图 `批量补格`，字段限定为 交叉点 / 横轴 / 纵轴 / 代表工作 / 数据集 / 指标 / 瓶颈 七项——用于把 AI 生成的表格逐条粘进来。核实类字段不进表单，强制走详情页（让「核实」这个动作有仪式感）。

**共享表 `提示词库` 的视图（与矩阵视图同批建）**：

- `按讲次取用`：按 `适用讲次` 分组——写哪一讲、该翻出哪套提示词，一屏看完。
- `本次在用`：过滤 `状态 = 可用`，按 `最近使用` 降序——正在用的那几版永远排在最前，停用的不占视野。

## 5. 自动化设计

| 名称 | 触发器 | 条件 | 动作 | 防的坑 |
| --- | --- | --- | --- | --- |
| 新增即待核实 | `record_created` on `01 问题矩阵` | `生成方式 = AI 生成` | `set_field`（核实状态 = 待核实）+ `add_comment`（“此单元格由 AI 生成，请核验至少 1 篇代表论文是否存在后再改状态”） | 把 AI 填的内容当事实采纳 |
| 待核实积压提醒 | `schedule daily:09:00`（绑定 `01 问题矩阵`） | —— | `run_agent`（查 `待核实清单` 视图，逐条 `add_comment`，并在汇总评论里报出条数）+ `feishu_bot`（一句固定提醒：“今日待核实清单见 `01 问题矩阵` 的 `待核实清单` 视图”） | 「待核实」标签长期挂着没人管 |
| 核验通过即建立证据链 | `field_equals`（`核实状态` = 已核实） | `代表工作` 非空 | `add_comment`（提示把代表工作登记进 `文献库`，分类第 5–6 讲） | 单元格与文献资产脱节 |

**关于 cron 的说明**：本讲只用到 `daily:HH:MM`，在现有能力内。`schedule` 触发的自动化没有「批量查询记录」这个动作，因此「巡检待核实清单」必须走 `run_agent`（智能体具备 `query_records`），不能指望 `field_equals` 覆盖。

**关于「≥5 条才推」的修正**：动作之间没有条件分支，也读不到智能体的输出，「按条数决定推不推」在现有能力内不可实现。落地方式是「每条固定推一次提醒 + 由智能体逐条留言并报数」——数字在表内看得见，推送只负责把你叫到视图前。

> 自动化的四条动作边界（动作作用范围限于触发记录或同库指定表、动作之间无分支、`notify` 须指定接收人、`field_equals` 会重复命中）见 `README.md` §3 与 `_系统能力现状.md` §2。

## 6. 智能体设计

### 站内智能体

**`问题地图纠偏员`（模式：`tools`）**

- 工具：`query_records`（读 `01 问题矩阵` 中 `核实状态 = 待核实` 或 `研究饱和度 ≥ 4` 的记录）、`add_comment`（逐条留言）。
- 系统提示词骨架（存进 `提示词库` 的 `完整提示词` 字段）：

```text
你是问题地图的纠偏审查员，服务于二维问题矩阵的质量控制。

【任务】对我给你的每个单元格，做三件事，逐条写成评论：
1. 反共识审查：给出 2 个与当前主流观点相反、但有文献支撑的研究角度；
2. 冷门维度补充：给出 1 个被主流叙事掩盖的相邻场景（如低资源、长尾、极端条件），
   并说明该场景的竞争密度为什么低；
3. 时间切片追问：指出这个方向上「近三个月可能已经出现」的新子方向名称与核心思路，
   并明确标注「我无法确认这些工作是否存在，需你到 arXiv 上核实」。

【硬约束】
- 你不允许修改任何字段，只允许写评论；
- 你不允许给出「推荐优先级」「哪个值得做」这类价值判断；
- 凡涉及具体论文、数据集、指标的陈述，一律追加一句「需人工核实出处」。
```

**`隐藏格探测员`（模式：`prompt`）**

- 用途：对某个 `横轴 × 纵轴` 组合，用一次生成判断「这格可能是空格还是错格」——输出五个问题：这一格近三年有没有真实工作？公开数据集是否存在？指标是否已被广泛接受？瓶颈是技术性的还是数据可及性的？如果没人做，是因为没想到还是因为做不出来？
- 输出写入评论，人判断后决定 `核实状态`。

### 外部 MCP 工作流

用 Cursor / Claude Code 等外部 Agent 通过 MCP 完成的部分（这些动作不适合进站内智能体，因为需要联网检索）：

1. `query_records` 拉出全部 `待核实` 单元格 → 外部 Agent 联网检索 → `update_record` 写回 `代表工作` 与 `核实状态`（同时把 `审定状态` 置回 `待审定`，等人工确认）。
2. 批量搜索近三个月的 arXiv 新子方向，`create_record` 追加为新单元格并标记 `是否冷门维度`。
3. 把核验通过的代表工作批量 `create_record` 进 `文献库`（第 06 讲）。

### 红线（AI 只能给草稿）

- **`个人匹配度` 只能由人填**。这是原文 1.1 节「人工标注优先级」的硬要求。
- **饱和度与可及性评分可以 AI 起稿，但必须标记 `审定状态 = 待审定`**，人工核验后改状态。
- **不允许 AI 直接改 `核实状态`**。核实这个动作的语义是「我，一个人，看过出处了」，AI 无权代表。

## 7. 与其他讲的接口

- **上游**：无。本讲是全书入口。
- **下游**：
  - 第 02 讲：一个高优先单元格 → 立案为一条 `02 差异假设`（`G-` 编号）。
  - 第 05 讲：`待核实` 单元格触发定向检索。
  - 第 06 讲：`已核实` 单元格的代表工作 → 登记进 `文献库`。
  - 第 24 讲：已发表论文回填到本表，检验「点集是否构成有向的簇」。
- **单一事实来源**：**问题空间的候选面**只在本表维护。研究计划书、组会 PPT 里的矩阵都从本表导出，不在别处另存一份可编辑副本。

## 8. 分期实施与验收

### P0（纯配置，零代码）

1. 建 `01 问题矩阵`（含上表全部字段）与 `提示词库`。
2. 建 `01 问题矩阵` 的五个视图：矩阵总览 / 优先候选 / 待核实清单 / 反共识边角 / 查无出处；再建 `提示词库` 的两个视图：按讲次取用 / 本次在用。
3. 建表单视图 `批量补格`。
4. 建三条自动化：新增即待核实 / 待核实积压提醒 / 核验通过即建立证据链。
5. 建仪表盘 `选题雷达`。
6. 建站内智能体 `问题地图纠偏员` 与 `隐藏格探测员`，提示词入 `提示词库`。
7. 把本讲的提示词模板（含 Listing 1.1 的三段式完整版）录入 `提示词库`，版本 1。

### P1（少量增强）

| 需求 | 说明 | 建议落点 |
| --- | --- | --- |
| 「代表工作」改为关联 `文献库` | P0 用多行文本，是为了先跑起来；一旦 `文献库` 建好，改为关联字段，让「核验过」有双向可查的证据 | 字段类型变更（`文本多行` → `关联`） |
| 坐标轴取值的受控词表 | 单选选项目前靠手工维护；建议支持空间级词表，避免「RAG」「检索增强生成」并存 | 字段选项配置 |
| 矩阵空缺的自动扫描 | 「4×4 应该有多少格、实际有多少格」需要计数能力；现有公式只能做 `TABLECOUNT`，不足以表达笛卡尔积缺口 | 仪表盘增强或脚本 |

### P2（可选）

- 把矩阵导出为便于向导师汇报的图形（系统目前只有 Zip 导出与 CSV，图形化需要外部脚本）。
- 单元格的「时间切片」自动巡检（需要联网，交给外部 MCP Agent）。

### 验收标准

1. 打开「矩阵总览」，能在 10 秒内说出「哪条技术路线整体已经拥挤」（看分组后的饱和度）。
2. 新建一条 AI 生成的单元格，**核实状态自动变为「待核实」，并自动出现一条提示评论**。
3. 「优先候选」视图里每一条都满足「高可及性 + 低饱和度 + 已核实」三个条件，且每条的 `代表工作` 都能被追问到出处。
4. 「查无出处」视图非空——说明确实发生过纠偏（一个永远为空的「查无出处」视图，说明核实动作在走过场）。
5. 仪表盘上能一眼看到「待核实数」随时间的下降趋势。
6. 在 `提示词库` 里能查到本讲的提示词模板，且有版本号与最近使用日期。

## 9. 与原文的偏差说明

| 偏差 | 原文做法 | 本设计做法 | 理由 |
| --- | --- | --- | --- |
| 优先级标注的粒度 | 用高/中/低三档标记每个单元格的「个人匹配度」 | 拆成三个正交字段：研究饱和度（AI 可起稿）、数据算力可及性（AI 可起稿）、个人匹配度（人必填） | 原文的「1–5 分推荐优先级」若交给 AI，等于让 AI 替你排序，与 1.3 节「防止 AI 只给热点」自相矛盾。拆成三个字段后，AI 只能给前两个，排序权回到人手里 |
| 矩阵的载体 | Excel / Notion / Markdown 表格 | base 中的表 | 统一进 base 才能与后续 23 讲建立关联；Excel 版矩阵是证据链的断点（无法与假设、实验、论文关联） |
| 「待核实」的强制性 | 提示词里要求 AI 标注 | 字段 + 自动化 + 闸门视图三件套 | 提示词是软的，字段与自动化是硬的。原文说「空格比错格更有价值」，本设计把这句话变成一个会被日常看到的视图 |
| 圆整度 | 未规定矩阵必须填满 | 明确不追求填满 | 原文说矩阵的目的是「定点比」；系统化过度会让用户把「填满」当成 KPI，那是另一种热点跟随 |
| 4×4 规模上限 | 经验建议 | 用仪表盘切片器与计数卡间接监控 | 系统无法阻止用户建出 6×6 的矩阵；本设计选择在仪表盘上把「格子数」显性化，让人自己看见规模，而不是硬性限制 |
