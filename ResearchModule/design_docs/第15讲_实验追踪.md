# 第 15 讲 实验追踪：系统落地设计

> 来源：`../design_principle/第15讲_实验追踪.pdf`
> 落地度：★★★★★（高） ｜ 依赖：第 10 / 12 讲 ｜ 主体分期：P0
> 主产物：共享表 `实验记录`（一行 = 一次运行，六字段是实验的最低档案）+ 表 `15 AI 复盘`（一行 = 一次每周复盘）

## 1. 本讲方法要点

1. **一次实验只有被记录了才算发生过**。没有追踪的实验，和没做过的实验，在证据意义上是等价的。
2. **六字段是实验的最小档案**：配置哈希（对全部超参数与配置文件计算哈希，一处改动即产生新值）、代码提交（运行时代码的版本号）、数据版本（哪份数据的哪个版本）、随机种子（所有随机源的种子）、指标（**预先声明**的主要与次要指标）、备注（一句话动机 + 一句话观察）。
3. **六字段各防一种灾难**：配置哈希防「忘了改了什么」，代码提交防「代码漂移」，数据版本防「数据静默更新」，种子防「把噪声当结论」，预声明指标防「事后摘樱桃」，备注防「看不懂自己的历史」。**少一个字段，就多一种三个月后无法解释的可能**。
4. **关键是「同时记全」而不是「选重要的记」**。六字段不是主从关系，是六条独立的证据链，缺失任何一条都会留下一个无法闭合的缺口。
5. **指标一栏特别强调「预声明」**：跑实验之前写下这次要看哪个指标、期望它朝哪个方向变化。事后从一堆指标里挑一个好看的来讲故事，是科研中最隐蔽也最普遍的自我欺骗。
6. **备注的价值在写作时才被真正看见**：一句话的动机，三个月后就是理解这次实验的唯一入口。
7. **指纹先于运行**。提交号与哈希必须在运行前固化，事后回忆的一律不可信。把取指纹做成运行脚本的入口步骤、失败就拒绝启动，是最可靠的约束方式。
8. **让实验表自己生成一行「待填」记录**：启动时先写入时间戳、提交号、配置哈希，指标与备注留空；跑完再补全。这样「忘了记」在技术上变得不可能——**空行本身就是一条醒目的提醒**。
9. **工具按痛点选档，秩序先于工具**：电子表格 → 轻量追踪库 → 实验平台，能力递增、复杂度也递增。选型原则是「当前痛点决定档位，而不是愿景决定档位」；工具的能力超过你的纪律时，多余的字段反而会成为不记录的新借口。升级判据是「当前的追踪方式有没有让你漏掉实验」——如果是「懒得记」，升级工具解决不了问题。
10. **迁移的正确顺序**：先选从今天起的实验统一记到新表，再把历史记录里最重要的几次补录进来，剩下的让它自然淘汰。**旧表只读，不删不改**——旧记录哪怕再乱，也是历史证据。
11. **AI 复盘三步**：① 脱敏与说明（喂给 AI 的表格去掉敏感信息，并附上每个字段的含义与单位）；② 提结构化问题（不要问「有什么发现」，而要问「按配置聚类，哪组配置指标显著更高」「找出指标与备注声称相反的实验」「哪些备注提到了掉点」）；③ **人来判因果**（AI 给出的相关性只是候选假设，是否成立要靠你设计下一轮消融来检验）。
12. **每周一次 AI 复盘**，请它输出三件事：最好的三个配置及其共性、最意外的三个结果、建议的下一轮实验——你逐条核对后再决定采纳与否。**AI 复盘是一面镜子：它暴露的不是 AI 的理解力，而是你平时记录的诚意**。
13. **复盘结论要回流进表格**：AI 发现的模式经你核对后写成一行新备注；AI 建议的消融，立项时引用这次复盘——实验表就不只是历史档案，而是一条持续生长的推理链。
14. **Achilles 之踵是「只记成功」**：缺失负结果的实验表会系统性高估方向的有效性，也让你重复踩坑。

## 2. 可落地性判定

| 能力点 | 落地形态 | 依托的现有能力 | 优先级 |
| --- | --- | --- | --- |
| 六字段 | 共享表 `实验记录` 的六个字段 | 文本、数字、多行、关联 | P0 |
| 六字段完整度检查 | 六个「缺 X」视图（或一个筛选组）+ `record_created` 触发 `run_agent` 逐项点名 | 过滤、`run_agent` | P0 |
| 指纹先于运行 | `状态 = 运行中` 时校验 `配置哈希` / `代码提交` 非空 | `field_equals` + `add_comment` | P0 |
| 指标预声明 | `指标预声明` 复选框 + `未预声明` 视图 | 复选框、过滤 | P0 |
| 负结果不丢 | `结论方向` 单选（支持假设/不支持/不确定/仅调试）+ `支持与不支持` 分组视图 | 单选、分组 | P0 |
| 异常现象池 | `异常现象` 多行 + `异常现象池` 视图——下一个选题的种子 | 多行、过滤 | P0 |
| 数据版本关联 | `数据版本` 关联 → `14 数据资产` 而不是手抄哈希 | 关联字段 | P0 |
| 运行→配置→假设链 | `配置` → `配置台账`；`关联假设` → `假设登记` | 关联字段 | P0 |
| 每周 AI 复盘 | `schedule weekly:5:17:00` → `run_agent` → 写 `15 AI 复盘` | `schedule` + `run_agent` + `create_record` | P0 |
| 复盘逐条核对 | `逐条核对` / `结论回流` 复选框 + 两个闸门视图 | 复选框、过滤 | P0 |
| 启动时自动生成待填行 | 训练脚本写一行 `状态=运行中` + 已有指纹 | 脚本 + MCP `create_record` | P1 |
| 训练日志自动落指标 | 从日志解析主/次指标回填 | MCP / 脚本 | P1 |

**不建议系统化的部分**：

- **追踪工具本身（WandB 类平台）不进系统**。系统承担的是原文所说「够用即可」档位的那张表，并预留 `配置哈希` / `代码提交` 字段以便将来对齐更高档工具。
- **「不自动读取训练日志写入本表」是刻意保留的**。原文强调纪律先于工具、运行结束当场登记不隔夜；全自动落盘会削弱「当场登记」这条纪律。它标为 P1 可做的增强，而不是默认。
- **工具档位的季度评估**属于判断，系统只提供 `实验记录` 的数据密度作为参考。

## 3. 数据模型设计

### 3.1 表结构

空间：`科研方法`。表：`实验记录`（共享表，第 10 / 12 / 14 / 16 / 17 / 18 / 22 讲共用）。

| 字段 | 类型 | 选项 / 说明 |
| --- | --- | --- |
| 运行编号 | 自动编号（前缀 `run-`） | —— |
| 配置 | 关联 → `配置台账`（单值） | 一次配置多次运行 |
| 配置哈希 | 文本 | 对配置文件算哈希，取前 12 位；一处改动即新值 |
| 代码提交 | 文本 | 短提交号，如 `a3f19c2` |
| 数据版本 | 关联 → `14 数据资产`（单值） | 唯一一处比原文更强的地方：用关联代替手抄哈希 |
| 随机种子 | 数字 | 与 `配置台账.seed` 口径一致 |
| 指标 | 多行文本 | 主指标与次指标一行一个，**写清数值与含义** |
| 备注 | 多行文本 | 一句话动机 + 一句话观察 |
| 指标预声明 | 复选框 | 本次运行前已声明看哪个指标、期望朝哪个方向变 |
| 状态 | 单选 | 运行中 / 完成 / 失败 / 中断 |
| 耗时（小时） | 数字 | —— |
| 开始时间 | 日期 | 日期时间型 |
| 结束时间 | 日期 | —— |
| 结论方向 | 单选 | 支持假设 / 不支持 / 不确定 / 仅调试——**失败与平庸的运行也要记** |
| 异常现象 | 多行文本 | 冲刺中发现的任何意外现象 |
| 关联假设 | 关联 → `假设登记`（多值） | —— |
| 关联图表 | 关联 → `18 图表台账`（多值） | —— |
| 审定三件套 | 单选 + 成员 + 时间 | 审定状态 / 审定人 / 审定时间 |

表：`15 AI 复盘`（一行 = 一次每周复盘）。

| 字段 | 类型 | 选项 / 说明 |
| --- | --- | --- |
| 周期 | 日期 | 周起日 |
| 输入范围 | 文本 | 本次复盘覆盖的运行编号区间，如 `run-031 ~ run-047` |
| 脱敏说明 | 复选框 | 已去掉敏感信息，并附字段含义与单位 |
| 最佳三配置及共性 | 多行文本 | AI 输出第 1 项 |
| 最意外三结果 | 多行文本 | AI 输出第 2 项 |
| 建议下轮实验 | 多行文本 | AI 输出第 3 项 |
| 逐条核对 | 复选框 | **每条结论已回原表核对**——「AI 擅长找模式，也擅长编造模式」 |
| 采纳结论 | 多行文本 | 核对后决定采纳的部分 |
| 结论回流 | 复选框 | 已把核对后的模式写成新备注或新立项 |
| 执行者 | 成员 | —— |
| 日期 | 日期 | —— |

**关系与公式**：

- `配置台账` → `实验记录` → `假设登记`：一次配置 N 次运行，每次运行挂到假设上。
- `实验记录.关联图表` ↔ `18 图表台账.数据来源`：论文里每个数字的往返追溯（第 18 讲定义反向字段）。
- **不使用跨表聚合**：本讲不涉及。六字段完整度用六个 `is_empty` 过滤表达，不需要算式。

### 3.2 记录样例

**样例 1（`实验记录` 的一行——六字段齐全，结论不支持假设，**它必须留在表里**）**

| 字段 | 值 |
| --- | --- |
| 运行编号 | run-033 |
| 配置 | exp-019 |
| 配置哈希 / 代码提交 | `7f2a91c4e0b8` ／ `b81d5f0` |
| 数据版本 | traffic-merged-v1.2（关联） |
| 随机种子 | 42 |
| 指标 | `f1: 0.842` ／ `rouge_l: 0.611` |
| 备注 | 动机：验证检索增强在长文档上是否仍有效；观察：长文档（>8k token）子集掉 2.4 个点，短文档持平——疑似检索噪声随长度累积 |
| 指标预声明 | ✅（预声明看 f1，期望上升） |
| 结论方向 | 不支持 |
| 异常现象 | 长文档子集的延迟比短文档高 3 倍，且随 batch 增大不是线性；怀疑与检索阶段的批处理有关 |

**样例 2（`实验记录` 的一行——指纹齐全但指标预声明缺失，一条真实存在的隐患）**

| 字段 | 值 |
| --- | --- |
| 运行编号 | run-034 |
| 配置哈希 / 代码提交 | `7f2a91c4e0b8` ／ `b81d5f0` |
| 随机种子 / 数据版本 | 42 ／ traffic-merged-v1.2 |
| 指标 | `f1: 0.861`（比 run-033 高 1.9 个点） |
| 指标预声明 | ☐（缺） |
| 备注 | 调了 `retrieval_top_k` 从 5 到 12，指标上去了——**但没有预声明，这个提升不能写进论文** |
| 结论方向 | 不确定 |

这一行展示本讲的核心纪律：**`指标预声明` 缺了，再好看的数字也只能当线索，不能当结论**。

**样例 3（`15 AI 复盘` 的一行——AI 提了三条，核对后只采纳了一条）**

| 字段 | 值 |
| --- | --- |
| 周期 | 2026-03-02（周一） |
| 输入范围 | run-028 ~ run-045 |
| 脱敏说明 | ✅ |
| 最佳三配置及共性 | 前三个 f1 都用了 `deterministic: true` + 相同数据版本 v1.2…… |
| 最意外三结果 | run-040 的 rouge_l 反而低于均值 4 个点，备注只写了「正常」 |
| 建议下轮实验 | ① 检索 top_k 的消融（5/8/12）；② 长文档子集的召回诊断；③ 换一个解码温度 |
| 逐条核对 | ✅ |
| 采纳结论 | 只采纳 ① 与 ②：「最佳三配置的共性」里 `deterministic: true` 是相关而不是原因（所有主结果实验都开了它）；③ 温度不属于本轮假设的范围 |
| 结论回流 | ✅（已把「长文档掉点」写成 run-033 的备注补充，并从 ① 立项 `ab-012`） |

这一行是「AI 提供线索、人来下结论」的活样本：AI 的三个「共性」里有一个是伪相关，被核对环节挡掉了。

## 4. 视图与交互设计

| 视图名 | 类型 | 配置要点 |
| --- | --- | --- |
| 六字段完整度（`实验记录`） | grid | **六个独立视图**（现有过滤只能 and/or，无法表达「任一为空」）：`缺配置哈希` / `缺提交号` / `缺数据版本` / `缺种子` / `缺指标` / `备注为空`。若要一个视图，用「最常缺的那个字段」做闸门 |
| 支持与不支持（`实验记录`） | grid | 按 `结论方向` 分组——**负结果不丢**，这是本讲最常见误区「只记成功」的对治 |
| 未预声明（`实验记录`） | grid | 过滤：`指标预声明` 未勾选——这些行的指标只能当线索 |
| 本周运行（`实验记录`） | grid | 过滤：`开始时间` 在本周内；按 `配置` 分组 |
| 异常现象池（`实验记录`） | grid | 过滤：`异常现象` 非空——**下一个选题的种子** |
| 运行档案（`实验记录`） | grid | 过滤：`状态 = 完成`；列取六字段 + `结论方向` + `关联假设`——一屏就是一份可辩护的档案 |
| 未核对（`15 AI 复盘`） | grid | 过滤：`逐条核对` 未勾选；颜色规则：红色 |
| 建议未跟进（`15 AI 复盘`） | grid | 过滤：`建议下轮实验` 非空 且 `结论回流` 未勾选 |

**记录详情页布局**：

- `实验记录`（分组样式，两列）：分组 1「指纹」：运行编号 / 配置 / 配置哈希 / 代码提交 / 数据版本 / 随机种子；分组 2「结果」：指标 / 指标预声明 / 结论方向 / 异常现象；分组 3「过程」：状态 / 开始时间 / 结束时间 / 耗时；分组 4「关联与备注」：备注 / 关联假设 / 关联图表 / 审定三件套。
- `15 AI 复盘`（分组样式，单列够用）：周期 / 输入范围 / 脱敏说明 / 三项 AI 输出 / 逐条核对 / 采纳结论 / 结论回流 / 执行者 / 日期。

**表单**：

- `登记一次运行`：字段限定为 配置 / 配置哈希 / 代码提交 / 随机种子 / 数据版本 / 指标预声明 / 备注 —— **跑之前先填这几个**，跑完再来补指标。
- `补指标与结论`：字段限定为 运行编号 / 指标 / 结论方向 / 异常现象 / 结束时间 —— 当场登记，不隔夜、不批量补记。

## 5. 自动化设计

| 名称 | 触发器 | 条件 | 动作 | 防的坑 |
| --- | --- | --- | --- | --- |
| 六字段缺失即提醒 | `record_created` on `实验记录` | —— | `run_agent`（检查该行六字段是否齐全，缺哪个就在评论里点名） | **这是 P0 里少数需要智能体的场景**：六字段的组合判断超出条件表达式的能力 |
| 运行前固化指纹 | `field_equals`（`状态` = 运行中） | `配置哈希` 或 `代码提交` 为空 | `add_comment`（“指纹先于运行：提交号与哈希应在实验开始前固化，事后回忆的一律不可信”） | 先跑完再补记 |
| 未预声明即提醒 | `field_equals`（`指标预声明` = 未勾选）且 `状态` = 完成 | —— | `add_comment`（“这次运行没有预声明指标：它的数字只能作为线索，不能作为结论；下次运行前先写清看哪个指标、期望朝哪个方向变”） | 事后从一堆指标里挑好看的那个讲故事 |
| 周五 AI 复盘 | `schedule weekly:5:17:00`（绑定 `15 AI 复盘`） | —— | `run_agent`（拉本周 `实验记录`，输出三件事：最佳三配置及共性、最意外三结果、建议下轮实验；用 `create_record` 写入 `15 AI 复盘`，`逐条核对` 留空即待审定）+ `notify`（固定文案：“本周复盘待逐条核对”，**指定接收人**） | 实验表积攒几十行后人眼看不出结构 |

**关于周五 17:00**：`weekly:5:17:00` 即每周五 17:00——复盘放在一周工作收尾时，结论正好带进下周排程。

**跨表写入走智能体**：智能体的 `create_record` 可以指定任意表，这是跨表写入的正规走法（自动化动作的 `create_record` 只能建在绑定表里）——所以「读 `实验记录` 写 `15 AI 复盘`」必须整条交给 `run_agent`，自动化只补一句固定提醒。

> 自动化的四条动作边界（动作作用范围限于触发记录或同库指定表、动作之间无分支、`notify` 须指定接收人、`field_equals` 会重复命中）见 `README.md` §3 与 `_系统能力现状.md` §2。

## 6. 智能体设计

### 站内智能体

**`每周复盘员`（模式：`tools`）**

- 工具：`query_records`（读本周 `实验记录`）+ `create_record`（写 `15 AI 复盘`）+ `add_comment`。
- 输入（用户提供）：复盘周期；以及字段含义与单位的说明（**没有它，AI 只能返回模糊与混乱**）。
- 输出：三件事，分别写入 `最佳三配置及共性` / `最意外三结果` / `建议下轮实验`。
- 系统提示词骨架（与原文 Listing 15.2 一致）：

```text
你是实验记录的复盘员。字段含义：cfg_hash（配置文件哈希前 12 位）、commit（代码短提交号）、
data_ver（数据版本标识）、seed（随机种子）、metric_main（主指标名与数值）、note（一句话动机 + 一句话观察）。

【任务】基于本周记录，输出三件事：
1. 按配置聚类，报告最好的三个配置及它们的共性；
2. 列出指标与备注声称相反的运行（备注说好、指标却没上去，或反之）；
3. 提出三条下周建议的消融/实验。

【硬约束】
- 你只做模式识别，不做因果判断：所有「共性」都要标注为「相关，非因果」；
- 指出每条结论依据的具体运行编号，便于我回表核对；
- 若某条结论的依据不足（样本少于 3 条），明确写「依据不足」；
- 不许给出「建议进一步研究」这类没有动作的建议。
```

### 外部 MCP 工作流

1. **启动时自动建待填行（P1）**：训练脚本入口取指纹（`git rev-parse --short HEAD`、配置文件 sha256 前 12 位、数据版本、seed），用 `create_record` 在 `实验记录` 写一行 `状态 = 运行中`，指标与备注留空——**空行本身就是一条醒目的提醒**。失败则拒绝启动。
2. **指标回填（P1）**：跑完后从日志解析主/次指标，`update_record` 补 `指标` 与 `结束时间`；人只写备注与结论。
3. **复盘数据准备**：周五前把本周记录导出为脱敏表格（去掉敏感路径与内部代号），附字段说明，作为 `每周复盘员` 的输入附件。

### 红线（AI 只能给草稿）

- **「六字段齐全」的判定由自动化点名、由人补齐**。AI 可以指出「缺哪一项」，但不能替人填数值。
- **`逐条核对` 必须由人勾选**。原文明确：AI 擅长找模式，也擅长编造模式，把 AI 的每周汇总直接写进周报是常见误区。
- **因果结论由人下**。AI 输出的「共性」一律标注为相关；是否成立要靠下一轮消融来检验。
- **`结论方向` 由人填**。

  - 第 18 讲：`18 图表台账.数据来源` 指向本表——图表数字的最终出处。

## 9. 与原文的偏差说明

| 偏差 | 原文做法 | 本设计做法 | 理由 |
| --- | --- | --- | --- |
| `数据版本` 的记法 | 手抄路径 + 哈希 | 直接关联到 `14 数据资产` | 这是**唯一一处自动化增强**，理由是数据版本最容易静默漂移，关联比手抄可靠。代价是必须先在第 14 讲建表 |
| 六字段完整度的检查 | 「同时记全」靠自律 | 六个「缺 X」闸门视图 + `record_created` 触发 `run_agent` 点名 | 原文说「少一个字段就多一种三个月后无法解释的可能」——那就需要一种机制能把「少了一个」当场照出来。用 `run_agent` 是因为六字段的组合判断超出条件表达式能力 |
| 「待填行」 | 工程细节（脚本先写一行待填） | P0 用手动表单「登记一次运行」（先填指纹、后补指标）模拟同一节奏；P1 才做自动建行 | 自动建行需要改训练脚本，属仓库侧工作；P0 先用表单把顺序钉死（指纹在前、指标在后），纪律的收益先兑现 |
| 工具选型的季度评估 | 一句纪律 | 不系统化，只在本文档第 2 节注明 | 「档位是否超配」是判断题，做成卡片会变成新的填表负担——这与原文的警告恰好相反 |
| AI 复盘的落点 | 「请它输出三件事」 | 独立成表 `15 AI 复盘`，`逐条核对` 与 `结论回流` 两个复选框做闸门 | 复盘的产出如果不落盘就消失了；两个复选框把「核对」与「回流」这两个动作从口头变成可检查的状态 |
| 迁移路径 | 三步法与「旧表只读」 | 不进系统，写入本文档 | 迁移是一次性事件，不是常态数据；把它做成表反而是「系统集邮」 |
