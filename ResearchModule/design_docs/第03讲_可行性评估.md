# 第 03 讲 可行性评估：系统落地设计

> 来源：`../design_principle/第03讲_可行性评估.pdf`
> 落地度：★★★★★（高） ｜ 依赖：第 02 讲 ｜ 主体分期：P0
> 主产物：表 `03 可行性冲刺`（把 72 小时时间盒变成结构约束）+ 表 `03 放弃备忘录`（让放弃转成资产）

## 1. 本讲方法要点

1. **72 小时冲刺三条纪律：时间盒、日志化、可展示**。到点就停，无论做到哪一步；每一天的结果写下来；三天结束时产出一份能从口头讲清的速报。
2. **顺序不可颠倒：先数据 → 再基线 → 后改动**。第一天只做数据探针（下载、加载、统计分布），第二天搭基线，第三天跑最小改动并判读。颠倒顺序的典型代价：先写代码，最后一天发现数据不可得。
3. **MVE（最小可行实验）三条标准**：一天能跑完；能证伪核心假设；不依赖完美实现。任何一条不满足，MVE 需要重新设计。
4. **预期先行**：先写「若假设为假，我期望看到什么」，再倒推实验该怎么做。这一步与第 10 讲的预期结果卡同源，是防止事后解释的第一步。
5. **资源四象限：数据、算力、时间、能力**。四个维度独立评估；**数据缺口不可用其他维度弥补**——算力再强也不能替代不存在的数据。任一维度落到最右选项，即为「红色缺口」，必须显式写下。
6. **四条硬止损线**：72 小时冲刺失败、MVE 证伪、资源缺口无法弥补、同行强负面信号。触线即停，不进入「再试一次」的循环。
7. **《可行性速报》不超过 2 页**，三段对三天：数据探针记录、基线参考指标、MVE 结果与结论。
8. **放弃备忘录三段结构**：已验证的事实、被证伪的假设、遗留线索。放弃不是失败，是把负结果转成下一个选题的资产——**遗留线索是唯一不允许删除的字段**。

## 2. 可落地性判定

| 能力点 | 落地形态 | 依托的现有能力 | 优先级 |
| --- | --- | --- | --- |
| 72 小时时间盒 | 甘特视图绑定 `开始时间` / `截止时间` | 甘特视图、日期字段、进度字段 | P0 |
| 三天三段记录 | 三个单选状态 + 三块多行记录 | 单选、多行文本 | P0 |
| 第一个卡壳点定位 | `第一个卡壳点` 单选（六类）+ 描述 | 单选、过滤 | P0 |
| MVE 设计与证伪条件 | 字段 + 智能体三问审查 | 多行文本、`prompt` 智能体 | P0 |
| 资源四象限 | 四个单选 + `红色缺口` 必填字段 | 单选、多行文本 | P0 |
| 止损线与终止 | `止损线` 多选 + `结论` 单选 | 多选、单选 | P0 |
| 放弃归档 | `结论 = 果断放弃` 触发提醒去建备忘录（跨表建档由人补录） | `field_equals` + `add_comment` + `notify` | P0 |
| 文献化速报与备忘录 | 文档挂靠（label：可行性速报 / 放弃备忘录） | 文档 ↔ 记录挂靠、文档模板 | P0 |
| 冲刺超时提醒 | 定时巡检未结项的冲刺 | `schedule daily:09:00` + `run_agent` + `notify` | P0 |

**不建议系统化的部分**：

- **「拿给导师看」的心理压力管理**。速报能不能交出去，属于个人节奏问题，不建字段、不设提醒等级。
- **放弃后的 24 小时冷静期**。这是人的节奏，系统只用 `归档时间` 字段间接体现——归档时间与决策时间之间的间隔就是冷静期，不做强制。
- **数据可及性的最终判断**。系统记录探针结果（下载耗时、样本规模），但「这个数据集算不算够用」由人下结论；AI 只给事实清单。

**建议视图**：见第 4 节。

**关系与公式**：

- `02 差异假设` → `03 可行性冲刺`：一条存活假设可以经历多轮冲刺（第一条失败后修订再冲），因此是单向一对多。
- `03 可行性冲刺` → `03 放弃备忘录`：一对一（结论 = 果断放弃时）。
- **不使用跨表聚合**：「三天完成度」用甘特视图的进度字段承担；不做「可及性平均分」这类表内比值。

### 3.2 记录样例

**样例 1（绿灯冲刺：数据可及，基线跑通）**

| 字段 | 值 |
| --- | --- |
| 选题 | G-07 生效日期感知的检索增强微调（见第 02 讲样例） |
| 冲刺编号 | fs-02 |
| 开始 / 截止 | 2026-11-02 ／ 2026-11-05 |
| 第 1 天·数据探针 | 完成 ｜ 记录：FinQA 与两个监管问答集可公开下载；监管文本许可证无限制；下载 1.2GB，含 3,400 条 Q&A |
| 第 2 天·基线 | 完成 ｜ 记录：BM25 检索 + 通用 LLM 直答，Exact Match 41.2；跑通耗时 3 小时（单卡） |
| 第 3 天·跑通与判读 | 完成 ｜ 第一个卡壳点：指标计算（生效日期错位样本需要人工标注口径） |

| MVE 时长（小时） | 6 |
| 证伪条件 | 若子集上 Exact Match 相对基线提升 < 2 个百分点，则「日期感知检索能改善时效性错答」不成立 |
| MVE 结果 | 支持核心假设（+7.4 个百分点，n=500） |
| 四象限 | 数据：已公开 ／ 算力：单卡可跑 ／ 时间：六周 ／ 能力：已掌握 |
| 结论 | 继续投入 |
| 速报文档 | 《fs-02 可行性速报》（2 页，挂靠本条记录） |

**样例 2（红灯冲刺：数据缺口，不可弥补）**

| 字段 | 值 |
| --- | --- |
| 第 1 天·数据探针 | 受阻 ｜ 记录：目标机构数据需伦理审查 + 数据使用协议，预计周期 6 个月，超出毕业时间预算 |
| 第一个卡壳点 | 数据不可得 |
| 可及性评分 | 1（自 3 下调，理由：访问周期 > 可用时间窗口） |
| 四象限·数据 | 需自建（协议 + 采集） |
| 红色缺口 | 「数据」落到最右选项，且此缺口不可用算力或时间弥补——数据不存在就是不存在 |
| 止损线 | 资源缺口无法弥补 |
| 结论 | 果断放弃 |
| 放弃备忘录 | 自动建立：已验证的事实 =2 家机构愿意在协议框架下合作；被证伪的假设 =「现有公开数据足以训练该任务」；遗留线索 = 协议周期问题可借道「合成数据预训练 + 少量真实数据校准」绕开 |

两张样例的差别说明什么算「填得好」：**红色缺口那一栏写的是因果（为什么不可弥补），不是复述选项**；遗留线索写的是**可以交给别人的线索**，不是懊悔。

## 5. 自动化设计

| 名称 | 触发器 | 条件 | 动作 | 防的坑 |
| --- | --- | --- | --- | --- |
| 冲刺超时提醒 | `schedule daily:09:00`（绑定 `03 可行性冲刺`） | —— | `run_agent`（查 `进行中` 视图里 `截止时间 < 今天` 且 `结论` 为空的记录，逐条 `add_comment`：“到点就停，无论做到哪一步，先写速报”）+ `notify`（固定文案，**指定接收人**） | 三天变成三周：时间盒失效是可行性评估最常见的死法 |
| 放弃即归档 | `field_equals`（`结论` = 果断放弃） | —— | `add_comment`（“请在 `03 放弃备忘录` 建一条记录并回填 `选题` 关联，然后写完三段结构与 `下次启用条件`”）+ `notify`（**指定接收人**） | 放弃只留在脑子里，负结果流失 |
| 红色缺口登记 | `record_updated`（`红色缺口` 被清空） | `四象限` 任一为最右选项 | `add_comment`（“任一维度落到最右选项时 `红色缺口` 必填——数据缺口不可用算力或时间弥补”） | 用「再努力一点」掩盖结构性缺口 |

**关于巡检的说明**：`schedule` 触发的自动化没有「批量查询记录」动作，因此超时巡检必须走 `run_agent`（智能体有 `query_records`），不能指望 `field_equals` 覆盖。

**关于「放弃即归档」的修正**：`create_record` 只能建在触发器绑定的表（这里是 `03 可行性冲刺`）里，建不进 `03 放弃备忘录`。P0 改为评论 + 通知引导人工补录；P1 可给动作加目标表参数（落点 `src/store.ts`）。`field_equals` 会在 `结论` 保持「果断放弃」期间重复命中，这里只配提醒类动作，重复一次无害。

> 自动化的四条动作边界（动作只作用于触发记录、动作之间无分支、`notify` 须指定接收人、`field_equals` 会重复命中）见 `README.md` §3 与 `_系统能力现状.md` §2。

## 6. 智能体设计

### 站内智能体

**`MVE 审问者`（模式：`prompt`）**

- 输入：MVE 设计 + 证伪条件（从记录复制进对话）。
- 输出三问：①这个实验能证伪核心假设吗？如果不能，缺哪个对照。②一天跑得完吗？若不能，最小砍到哪一步还能保留证伪能力。③失败时能定位到哪个变量？若定位不了，说明变量没有隔离。
- 输出写进记录的评论，不改字段。

```text
你是 MVE（最小可行实验）的审问者。对给定的实验设计与证伪条件，只回答三个问题，每问给出「通过 / 不通过 / 需要修改」三选一与一句理由：

1. 这个实验的结果，能否在「与预期相反」时推翻核心假设？如果不能，指出缺的是哪个对照或哪组数据；
2. 这个实验能否在 8 小时（单卡）内跑完？如果不能，给出最小削减方案，且削减后第一问的答案必须仍然成立；
3. 实验失败时，能否把原因定位到具体变量？如果不能，指出变量之间没有隔离的地方。

【硬约束】
- 不允许评价这个研究方向好不好；
- 不允许建议增加实验规模（除非第一问不通过）；
- 所有结论用「需要修改」而不是「建议考虑」，措辞必须能直接执行。
```

### 外部 MCP 工作流

1. **数据可及性初查**：外部 Agent 对 `第 1 天 = 未开始` 的冲刺，联网访问数据集主页，核对：页面是否存活、许可协议、体积、最近更新时间，用 `update_record` 写入 `数据探针记录` 草稿（标注「AI 初查，需人工下载验证」）。
2. **基线清单**：按假设关键词检索近两年的论文表格，提取常见基线设置，写入 `基线记录` 草稿。

### 红线（AI 只能给草稿）

- **`结论` 必须人填**。三天状态汇总成人判断，AI 无权写。
- **四象限评估由人下结论**。AI 可以给数据集页面事实，但不打「已公开 / 需申请 / 需自建」的分。
- **`遗留线索` 必须人写**。它要求的是「值得别人接着做什么」，是人的判断。

## 8. 分期实施与验收

### P0（纯配置，零代码）

1. 建 `03 可行性冲刺`（含字段表全部字段，自动编号前缀 `fs-`）与 `03 放弃备忘录`。
2. 建四个视图：72 小时冲刺（甘特）/ 进行中 / 红色缺口 / 止损清单；在 `03 放弃备忘录` 上建 `线索池`。
3. 建三条自动化：冲刺超时提醒 / 放弃即归档 / 红色缺口登记。
4. 建站内智能体 `MVE 审问者`，提示词入 `提示词库`。
5. 速报与备忘录模板：P0 用 `模板库`（第 23 讲）存全文 + 手动复制为挂靠文档；在两表上各建文档模板挂靠标签（可行性速报 / 放弃备忘录）。

| --- | --- | --- |
| `截止时间` 默认 = 开始 + 3 天 | 现在靠人工填写，可能被拖成「五天盒」 | 日期字段默认值支持「基于另一字段 + N 天」（`src/store.ts` 字段默认值） |
| 速报 / 放弃备忘录进系统文档模板 | 现在是 `模板库` 里的全文复制；进系统后可从记录一键生成挂靠文档 | 文档模板模块（内置 3 个模板的扩展位） |
| 甘特进度自动计算 | 三天完成数 / 3 现在手动设 | 甘特进度字段支持公式（`web/src/` 甘特视图） |

### P2（可选）

- 数据探针辅助脚本：给定数据集名，自动记录下载耗时与文件校验和，作为 `数据探针记录` 的事实底稿。
- 「红线周期报告」：每月汇总 `止损清单` 与 `红色缺口`，生成一页季报草稿。

### 验收标准

1. 每条进入冲刺的选题都有 `开始时间` 与 `截止时间`，甘特图上时间盒完整可见。
2. 三天三段记录字段在冲刺结束时都有内容；受阻的天也有记录（受阻记录比成功记录更有信息量）。
3. 每条已结束的冲刺都有 `结论`；`果断放弃` 的记录都自动生成了备忘录草稿，且 `遗留线索` 非空。
4. `红色缺口` 视图里的每一条都能回答「为什么这个缺口不可弥补」。
5. `MVE 审问者` 的三问评论出现在每条填写了 MVE 设计的记录上。
6. `线索池` 内容每季度被翻看过（有评论或 `下次启用条件` 的更新痕迹）。

## 9. 与原文的偏差说明

| 偏差 | 原文做法 | 本设计做法 | 理由 |
| --- | --- | --- | --- |
| 72 小时的载体 | 自然语言纪律（「给自己 72 小时」） | 甘特视图 + `开始/截止时间` + 超时提醒，把时间盒变成结构约束 | 纪律会被拖延吃掉；日期字段不会 |
| 放弃的动作 | 只在正文提到「可以放弃」 | `结论` 单选含「果断放弃」，触线自动建档 | 放弃需要一个显式动作，否则它会以「暂停」的名义无限期悬置 |
| 放弃备忘录的字段 | 三段结构 | 三段 + `下次启用条件` + `遗留线索` 禁空约束 | 「遗留线索」是放弃文档里唯一对未来有复利的字段，用必填保护它 |
| 四象限的判定 | 描述性的分类 | 四组单选 + 「落到最右选项 → `红色缺口` 必填」的可操作判据 | 让「数据缺口不可弥补」这条原文纪律有一个会被触发的条件 |
| 速报的产出方式 | 一份两份的两页纸 | P0 用模板库 + 挂靠文档；P1 进系统文档模板 | 遵循能力边界：系统文档模板目前是固定 3 个；先跑起来，再增强 |
