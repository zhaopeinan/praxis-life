# 第 04 讲 AI 辅助选题的边界：系统落地设计

> 来源：`../design_principle/第04讲_AI辅助选题的边界.pdf`
> 落地度：★★★☆☆（中） ｜ 依赖：第 01–03 讲 ｜ 主体分期：P0
> 主产物：表 `04 选题决策日志`（决策档案 + 判断力仪表）+ 共享表 `复核记录`（全书通用的人工核验台账）

## 1. 本讲方法要点

1. **AI 擅长收敛、不擅长开辟**。归纳、对比、聚类、找反例是它的强项；「我该研究什么」这类问题，它的回答系统性偏向主流——让它替你做选题，等于让它替你追热点。
2. **三种热点陷阱**：名词堆砌（把热词组合当创新）、指标通胀（把榜单数字提升当贡献）、时间盲区（不知道近三个月发生了什么）。每种陷阱都有对应的防御动作：非共识检验、三年之问、时间切片检索。
3. **三年之问**：这个问题三年后还值得做吗？**非共识检验**：如果你的答案与所有人一致，你的贡献在哪？**导师困惑度**：能让导师在听完五分钟内提出一个你答不上来的问题吗？三问的共同点是**都必须在真人对话里发生**。
4. **选题的四条责任原则**：AI 不做价值判断、不承担后果、不了解你的隐性资源（组里的数据、设备、合作方）、不理解学术共同体（谁在圈内、什么话不能在审稿人面前说）。四条责任决定了四类决策权只能留在人手里。
5. **导师–AI–学生三方分工**：AI 负责信息面（检索、归纳、反驳草稿），导师负责方向与资源判断，学生负责决策与留档。分工写进流程，避免「AI 说了算」的滑移。
6. **决策日志是判断力的测量仪**：每次关键决策记下「AI 输入了什么、我基于什么判断、我预期会发生什么、何时验证」。判断力看不见，但它的命中率可以被统计。
7. **方向锁定期（默认 8 周）**：一旦选定方向，锁定期内不重新评估方向——评估太频繁本身就是一种热点跟随。
8. **AI 输出复核清单**：AI 产出的一切（文献存在性、数字、分类、摘要）在用于决策前逐条核验。这份清单从本讲抽象为共享表 `复核记录`，供第 06 / 20 / 22 讲共用。

## 2. 可落地性判定

| 能力点 | 落地形态 | 依托的现有能力 | 优先级 |
| --- | --- | --- | --- |
| 决策留档 | 表 `04 选题决策日志`，一行 = 一次关键决策 | 关联、多行文本、自动编号 `D-` | P0 |
| 预期验证机制 | `预期验证点` 日期 + 到期巡检 + `验证结论` 回填 | `schedule` + `run_agent`、单选 | P0 |
| 判断力统计 | `失误类型` 单选 + `失误复盘` 视图 + 仪表盘 | 单选、分组、仪表盘 count | P0 |
| 方向锁定期 | `方向锁定期至` 日期 + `锁定期内` 视图 | 日期、过滤 | P0 |
| AI 产出核验台账 | 共享表 `复核记录` + 三视图 | 自动编号 `cf-`、关联、过滤 | P0 |
| AI 产出入库即挂复核 | 两条自动化联动 `文献库` 与 `01 问题矩阵` | `record_created` + `add_comment` + `notify` | P0 |
| 去热点化预审 | 站内智能体 `去热点化审查员` | `prompt` 模式 + 评论 | P0 |
| 三年之问的材料准备 | `prompt` 智能体给「两种回答」草稿，人拿去与导师对话 | `prompt` 模式 | P0 |
| 近三个月动向扫描 | 外部 MCP 联网检索（站内智能体无联网） | MCP 工具集 | P1 |

**不建议系统化的部分**：

- **非共识检验与导师困惑度**。它们只能在与真人的对话中发生；系统只留 `讨论对象` 字段记录「这次决策经过了谁」，不试图数字化「困惑度」。
- **「价值判断」本身**。原文的四条责任原则决定了：系统不产生「这个方向值不值得做」的信号，连提示都不给。
- **近三个月动向的自动追踪**。依赖联网，站内做不到；P1 交给外部 MCP 按需执行，不做常驻订阅。

## 3. 数据模型设计

### 3.1 表结构

空间：`科研方法`。表：`04 选题决策日志`。

| 字段 | 类型 | 选项 / 说明 |
| --- | --- | --- |
| 决策编号 | 自动编号（前缀 `D-`） | —— |
| 决策内容 | 文本（标题字段） | 一句话说清选了什么 / 弃了什么 |
| 决策类型 | 单选 | 选定方向 / 放弃方向 / 调整假设 / 改换坐标轴 / 模板修改 |
| 关联对象 | 关联 → `01 问题矩阵` / `02 差异假设`（多值） | 决策作用在哪些对象上 |
| AI 输入 | 多行文本 | AI 提供了哪些信息，逐条列出并标注来源与是否已核验 |
| 人工判断 | 多行文本 | 我基于什么做出决策（这是品味曲线的原料） |
| 被否决的选项 | 多行文本 | 当时考虑过但没选的路线，及否决理由 |
| 预期验证点 | 日期 | 何时回来看这个决策对不对 |
| 预期内容 | 多行文本 | 我预期会发生什么——写具体（如「三个月内至少看到 2 篇引用此思路的新工作」） |
| 验证结论 | 单选 | 未到验证期 / 判断正确 / 判断失误 / 部分正确 |
| 失误类型 | 单选 | 被热点带走 / 高估可及性 / 低估工程成本 / 文献盲区 / 其他（仅 `验证结论 = 判断失误` 时填） |
| 讨论对象 | 单选 | 独立决策 / 导师 / 同行 / 合作者 |
| 方向锁定期至 | 日期 | 仅 `决策类型 = 选定方向` 时必填；默认 = 决策日 + 8 周 |
| 审定状态 | 单选 | 待审定 / 已审定 / 退回 |
| 审定人 | 成员 | —— |
| 审定时间 | 日期 | —— |

共享表 `复核记录`（定义于此讲，全书共用；第 06 / 20 / 22 讲均引用本表）。

| 字段 | 类型 | 选项 / 说明 |
| --- | --- | --- |
| 编号 | 自动编号（前缀 `cf-`） | 与第 22 讲的 `ck-`（核查项）、第 20 讲的引用核验编号区分开 |
| 对象类型 | 单选 | 文献存在性 / 数据集可下载性 / 指标公认性 / 数字一致性 / 引用真实性 / 段落主张 / AI 摘要 |
| 对象描述 | 文本 | 被复核的东西是什么，一句话 |
| 关联记录 | 文本 | 被复核的编号（如 `H-03`、`D-12`），因为对象可能跨表，用文本而非关联 |
| 关联文献 | 关联 → `文献库`（多值） | 涉及文献时使用（第 06 讲建成后启用） |
| 结论 | 单选 | 通过 / 不通过 / 待查 |
| 证据 | 多行文本 | 检索到的出处、页码、DOI、复现命令 |
| 复核方式 | 单选 | 人工回原文 / AI 检索后人工确认 / 脚本机械比对 |
| 复核人 | 成员 | —— |
| 复核日期 | 日期 | —— |

**建议视图**：见第 4 节。

**关系与公式**：

- `01 问题矩阵` / `02 差异假设` → `04 选题决策日志`：多对一（一个对象可以被多次决策触碰）。
- `复核记录` 与各表的关联：`关联记录` 用文本编号，「挂了复核」这件事通过自动化创建，而不是每个表加一个关联字段——**复核是台账，不是从属字段**。
- 本表不使用跨表聚合公式：「失误率」「命中率」交给仪表盘。

**样例 1（选定方向 + 完整的预期记录）**

| 字段 | 值 |
| --- | --- |
| 决策编号 | D-05 |
| 决策内容 | 选定「检索增强的时效性约束」作为博二主方向，放弃「多智能体协作」分支 |
| 决策类型 | 选定方向 |
| 关联对象 | 01 问题矩阵：RAG × 金融合规；02 差异假设：G-07 |
| AI 输入 | ①两方向近两年论文量对比（AI 检索，已核验前 10 条）②多智能体方向的综述缺口清单（**其中 2 条经核验为幻觉，已在复核记录 cf-11 记不通过**） |
| 人工判断 | 多智能体分支的组内算力不可及；导师在该方向的合作资源为零；时效性方向有现成数据集（已跑通 fs-02） |
| 被否决的选项 | 多智能体协作（算力）、多模态检索（与组内积累无关） |
| 预期验证点 | 2027-02-01 |
| 预期内容 | 三个月内至少看到 2 篇直接讨论「监管文本时效性」的新工作；若为零，说明空白比预期更大或更小众，两者都需要重估 |
| 方向锁定期至 | 2027-01-01（决策日 + 8 周内的方向评估冻结期） |
| 讨论对象 | 导师 |
| 验证结论 | 未到验证期 |

**样例 2（回填失误——判断力仪表的原料）**

| 字段 | 值 |
| --- | --- |
| 决策编号 | D-02 |
| 决策内容 | 选定「联邦学习 + 医疗去标识化」为预研方向 |
| 验证结论 | 判断失误 |
| 失误类型 | 被热点带走 |
| 人工判断（事后补记） | 当时的判断有 80% 来自 AI 的热度统计；没有查过失败案例（这类线索其实在 `02 空白三问` 的负结果线索里有，但当时没建那张表） |
| 预期内容（原记录） | 六周内跑通第一个跨机构实验 |
| 实际 | 数据协议问题在第五周暴露，方向在 fs-01 红灯冲刺后放弃 |

两张样例的差别说明什么算「填得好」：**`被否决的选项` 与 `预期内容` 是决策日志区别于会议纪要的两个字段**——前者证明你真的比较过，后者让「判断对不对」在几个月后可以验证，而不是靠回忆重新解释。

## 4. 视图与交互设计

| 视图名 | 类型 | 配置要点 |
| --- | --- | --- |
| 待验证 | grid | 过滤：`验证结论 = 未到验证期`；排序：`预期验证点` 升序。这是本讲主工作视图 |
| 失误复盘 | grid | 过滤：`验证结论 = 判断失误`；按 `失误类型` 分组——看自己最常掉进哪种陷阱 |
| 锁定期内 | grid | 过滤：`方向锁定期至 ≥ 今天`；用于「想改方向时先看看锁」 |
| 待查（在 `复核记录` 上） | grid | 过滤：`结论 = 待查`；颜色规则：超过 14 天 → 行标红 |
| 不通过（在 `复核记录` 上） | gallery | 过滤：`结论 = 不通过`——保留失败核验，它是防幻觉的训练材料 |
| 按对象类型分组（在 `复核记录` 上） | grid | 按 `对象类型` 分组，看哪类 AI 产出最容易出问题 |

**仪表盘 `判断力刻度`**：

- pie：`失误类型` 分布（随时间看自己是否从「被热点带走」转向更诚实的失败模式）
- count：`待验证` 数、`锁定期内` 数、`复核记录·待查` 数
- line：按季度决策数（决策过密本身就是信号）
- bar：`决策类型` 分布

**记录详情页布局**（分组样式，两列）：

- 分组 1「决策」：决策编号 / 决策内容 / 决策类型 / 关联对象 / 讨论对象
- 分组 2「依据」：AI 输入 / 人工判断 / 被否决的选项（单列排布）
- 分组 3「验证」：预期验证点 / 预期内容 / 验证结论 / 失误类型
- 分组 4「锁定与审定」：方向锁定期至 / 审定三件套

**表单**：新增表单视图 `记决策`，字段限定为 决策内容 / 决策类型 / 关联对象 / 人工判断 四项——用于决策发生后 24 小时内快速留档。`预期内容` 与 `预期验证点` 不进表单，强制回详情页补写（这一步最容易被跳过，也最不能跳过）。

## 5. 自动化设计

| 名称 | 触发器 | 条件 | 动作 | 防的坑 |
| --- | --- | --- | --- | --- |
| 预期验证点到期提醒 | `schedule daily:09:00`（绑定 `04 选题决策日志`） | —— | `run_agent`（查 `待验证` 视图里 `预期验证点 ≤ 今天` 的记录，逐条 `add_comment`：“预期验证点到期：请回填验证结论，并与 `预期内容` 对照”）+ `notify`（固定文案，**指定接收人**） | 决策日志只记不验，退化成会议纪要 |
| AI 产出入库即挂复核 | `record_created` on `文献库` | `生成方式 = AI 生成` 或 `AI 起草栏位` 非空 | `add_comment`（“AI 产出未核验：请在 `复核记录` 建一条 `对象类型 = AI 摘要`、`结论 = 待查` 的条目，`对象描述` 填本条目标题”）+ `notify`（**指定接收人**） | AI 产出绕过核验直接进正式字段 |
| AI 产出入库即挂复核（问题矩阵） | `record_created` on `01 问题矩阵` | `生成方式 = AI 生成` | `add_comment`（“AI 产出未核验：请在 `复核记录` 建一条 `对象类型 = AI 摘要`、`结论 = 待查` 的条目”）+ `notify`（**指定接收人**） | 同上，覆盖选题面 |
| 决策未写预期 | `record_created` on `04 选题决策日志` | `预期内容` 为空 | `add_comment`（“请在 24 小时内补写预期内容与预期验证点——没有预期的决策无法被验证”） | 决策日志失去测量功能 |

**关于跨表建档的说明**：两条「入库即挂复核」自动化分别建在各自表上（`文献库` 一条、`01 问题矩阵` 一条，同一条规则两处绑定，故按两条自动化计）。`create_record` 自 2026-10-18 起支持 `tableId` 指定同库目标表，因此可以直接在 `复核记录` 建档（`对象类型` 写死、`对象描述` 用 `{标题}` 插值），「评论 + 通知引导人工补录」降级为兜底。

> 自动化的四条动作边界（动作作用范围限于触发记录或同库指定表、动作之间无分支、`notify` 须指定接收人、`field_equals` 会重复命中）见 `README.md` §3 与 `_系统能力现状.md` §2。

## 6. 智能体设计

### 站内智能体

**`去热点化审查员`（模式：`prompt`）**

- 输入：一个候选方向（一句话）+ 你已知的支撑文献列表。
- 输出四样：①过气信号：这个方向早期的热度高峰在何时，活跃度是否在降；②炒作风险：哪些表述像名词堆砌、哪些指标属于通胀；③三年之问的两种回答（「值得」与「不值得」的最强论证各一）；④非共识检验问题一条。
- 输出写进决策评论或 `AI 输入` 字段（保持 `待审定`）。

```text
你是研究方向的去热点化审查员。你的职责是替我听到「这个方向很热」这句话之下的真实情况。

【任务】对给定候选方向，输出四块内容：
1. 过气信号：该方向（或其母方向）热度高峰与当前状态的最可能判断，标注「我的时间线知识可能过时，需核验近三个月动向」；
2. 炒作风险：该方向的典型名词堆砌与指标通胀表现，各举一例；
3. 三年之问：「三年后仍值得做」与「三年后已无意义」两种回答的最强论证各一条；
4. 非共识检验：一个我应当能回答、但多数人会答错的问题。

【硬约束】
- 不允许给出「值得做 / 不值得做」的总结论；
- 所有涉及时间与热度的陈述标注核验要求；
- 你提供的任何文献事实都可能过时，必须标注「需人工核实」。
```

### 外部 MCP 工作流

1. **近三个月动向扫描**：外部 Agent 按 `01 问题矩阵` 的活跃单元格关键词，用 arXiv API 检索近三个月新工作，把命中的标题与日期写进对应决策日志的评论或 `AI 输入` 草稿。
2. **复核记录的批量核验**：`query_records` 拉出 `结论 = 待查` 且 `对象类型 = 文献存在性` 的条目 → DOI 批量解析（第 22 讲脚本）→ `update_record` 写回结论与证据，`复核方式 = 脚本机械比对`。

### 红线（AI 只能给草稿）

- **`决策内容` 与 `人工判断` 只能人写**。「人工判断」栏出现 AI 文字，仪表盘立刻失真。
- **`复核记录.结论` 必须人填或经人确认脚本结果**。自动化只负责建条目，不负责结案。
- **AI 不得参与 `失误类型` 的判定**。给自己归因是判断力训练的一部分。

## 7. 与其他讲的接口

- **上游**：第 01 讲的单元格（`关联对象`）、第 02 讲的假设、第 03 讲的冲刺结论——决策日志是它们在「人做了什么选择」这个维度上的公共出口。
- **下游**：
  - 第 24 讲：用本表算「品味命中率」（`验证结论 = 判断正确` 的比例）与「失误模式迁移」；`预期内容` 是品味曲线的测量点。
  - `复核记录` 被第 06 讲（文献存在性、幻觉隔离联动作业）、第 20 讲（引用核验的通用台账）、第 22 讲（核查清单的补充记录）引用。
- **单一事实来源**：**决策依据只在本表**。研究计划书、开题报告里的「选题依据」是本表的派生文本，不反向作为依据。

## 8. 分期实施与验收

### P0（纯配置，零代码）

1. 建 `04 选题决策日志`（含自动编号 `D-`）与 `复核记录`（含自动编号 `cf-`）。

### P2（可选）

### 验收标准

1. 每条 `决策类型 = 选定方向` 的记录都有 `方向锁定期至` 与 `预期内容`。
2. `待验证` 视图里的记录在验证点到期一周内都有回填动作（`验证结论` 被更新或有评论）。
3. `失误复盘` 视图非空，且 `失误类型` 分布能看到至少两类——只有一类说明归因在偷懒。
4. `复核记录` 中 `不通过` 的比例非零（一个从不记录 AI 幻觉的复核台账，说明它在走过场）。
5. 新建一条 AI 生成的 `文献库` 记录后，`复核记录` 自动出现对应待查条目。
6. `判断力刻度` 仪表盘能回答：我最常犯哪类失误、我有多少决策还在等验证。

## 9. 与原文的偏差说明

| 偏差 | 原文做法 | 本设计做法 | 理由 |
| --- | --- | --- | --- |
| 决策日志的字段数 | 四字段（决策内容 / AI 输入 / 人工判断 / 预期验证点） | 扩到 12 个字段，新增「被否决的选项」「预期内容」「失误类型」等 | 四个字段能存档，但无法测量判断力；新增字段是把日志从档案升级为仪表的最小改动 |
| AI 复核清单的形态 | 一张清单（随讲出现） | 抽象为共享表 `复核记录`，第 06 / 20 / 22 讲共用 | 同一份核验纪律浮现在四讲里，若各建各的清单会立刻出现四份口径不一的标准 |
| 方向锁定期 | 习惯性建议（「别频繁换方向」） | `方向锁定期至` 日期 + `锁定期内` 视图 | 把「忍住不评估」变成一条看得见的线 |
| 热点防御的执行 | 提示三种陷阱的存在 | 陷阱不建字段，防御动作建机制（时间切片检索、去热点化审查员、复核台账） | 「陷阱类型」本身无法被填写；能被执行的只有防御动作 |
| 三年之问的位置 | 与导师/同行对话中发生 | 只留 `讨论对象` 记录发生，不数字化 | 尊重边界：需要在真人对话中发生的事，系统只做记事本 |
