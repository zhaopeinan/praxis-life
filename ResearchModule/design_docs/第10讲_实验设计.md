# 第 10 讲 实验设计：系统落地设计

> 来源：`../design_principle/第10讲_实验设计.pdf`
> 落地度：★★★★★（高） ｜ 依赖：第 09 讲 ｜ 主体分期：P0
> 主产物：表 `10 实验矩阵`（一行 = 一个待跑实验单元，完整到能直接复制进论文结果表）+ 共享表 `10 预期结果卡`（先写预期、后跑实验的凭证）

## 1. 本讲方法要点

1. **三层对照：基线、消融、空白**。基线回答「有没有用」，消融回答「哪部分有用」，空白回答「不用方法行不行」。**空白对照最常被省略**，也最常是审稿人第一个问的问题。
2. **变量控制铁律「一次只动一个」**。一次改两处，结果变好变坏都无法归因——这条铁律在矩阵里表现为「每行一个单元」。
3. **四类混淆变量**：训练预算不对齐、数据预处理不一致、评测协议差异、硬件与精度差异。每一类都要在矩阵里有落点（同预算、同预处理、同协议、同精度）。
4. **实验矩阵四维度：数据集 × 方法 × 指标 × 种子**。矩阵之外跑出来的变体（临时起意的改动）**结果不直接使用**——要么补进行矩阵，要么承认它是探索性结果。
5. **先写预期结果，再跑实验**，且写在无法事后修改的地方。预期包含三件事：预期陈述、预期幅度 δ、失败时的备选解释。
6. **种子数 3 是底线，关键实验 5–10**。种子数不是越多越好，而是与噪声量级匹配。
7. **报告均值与标准差，而不是最好成绩**。最好成绩是运气，均值±std 才是结果。
8. **预声明指标防事后摘樱桃**：跑之前声明看哪个指标、期望朝哪个方向变；跑完之后再挑指标的，是给自己讲故事。
9. **判据要写死**：置信区间不重叠 / 配对检验 / Welch's 检验——选哪个在跑之前定，跑之后不做切换。

**不建议系统化的部分**：

- **统计检验的执行与置信区间的计算**。系统没有计算能力；系统登记 δ、判据与达成情况，「p 值是多少」在系统外算。
- **效应量与种子数的权衡**。属判断；系统只在字段说明里提示「关键实验 5–10」的经验值。
- **「这个指标算不算强」的判断**。预声明之后交给结果，系统不设自动阈值。

## 3. 数据模型设计

### 3.1 表结构

空间：`科研方法`。表：`10 实验矩阵`（一行 = 一个待跑的实验单元）。

| 字段 | 类型 | 选项 / 说明 |
| --- | --- | --- |
| 单元编号 | 自动编号（前缀 `m-`） | —— |
| 假设 | 关联 → `假设登记`（单值） | 每个单元服务一条假设 |
| 数据集 | 单选 / 文本 | —— |
| 方法 | 单选 | 基线 / 完整方法 / 消融变体 |
| 变体说明 | 文本 | 仅 `方法 = 消融变体`：如「−组件甲」 |

| 字段 | 类型 | 选项 / 说明 |
| --- | --- | --- |
| 编号 | 自动编号（前缀 `E-`） | —— |
| 假设 | 关联 → `假设登记`（单值） | —— |

| 实际幅度 | 数字 | —— |
| 结论 | 多行文本 | —— |
| 是否事后调整过 | 复选框 | **勾选即留痕**，防 HARKing 的最后一道闸 |

**建议视图**：见第 4 节。

**关系与公式**：

- `假设登记` → `10 实验矩阵`：一条假设配多个单元（多数据集 × 多方法）。
- `10 实验矩阵` → `10 预期结果卡`：一对一（每个单元一张卡）；`先卡后跑` 视图盯住缺失。
- `10 实验矩阵` → `配置台账`（第 12 讲）：一行矩阵可对应多份配置（多种子即多配置）。
- **不使用跨表聚合**：「达成率」交给仪表盘。

## 4. 视图与交互设计

| 视图名 | 类型 | 配置要点 |
| --- | --- | --- |
| 实验矩阵（在 `10 实验矩阵` 上） | grid | 按 `数据集` 分组、按 `方法` 排序；列取 主指标 / 种子数 / 状态——**要完整到能直接复制进论文结果表** |
| 三层对照缺口（同表） | grid | 过滤：`对照类型` 不含 空白对照——原文特别点出的、多数论文省略的那一层 |

| 待跑队列（同表） | grid | 过滤：`状态 = 已列入矩阵`；按假设优先级排序 |
| 先卡后跑（同表） | grid | 过滤：`预期结果卡` 为空 且 `状态 ≠ 计划中`——**跑之前就该补上** |
| 未达成清单（在 `10 预期结果卡` 上） | grid | 过滤：`达成情况 = 未达成`；看备选解释的命中率 |
| 事后调整过（同表） | grid | 过滤：`是否事后调整过` 勾选——这个视图的长期去向应该是「有少数几条、都有明确说明」 |

**仪表盘 `实验全景`**：count（待跑 / 运行中 / 完成）；bar（按 `对照类型` 的单元数——看空白对照的比例）；line（按周完成单元数）；pie（`达成情况` 分布）。

**记录详情页布局**：

- `10 实验矩阵`（分组样式，两列）：分组 1「单元定义」：单元编号 / 假设 / 数据集 / 方法 / 变体说明；分组 2「指标与种子」：主指标 / 辅助指标 / 种子数 / 种子依据；分组 3「对照与变量」：对照类型 / 冻结变量与放开变量 / 是否预先列入；分组 4「执行」：状态 / 预期结果卡 / 关联配置。
- `10 预期结果卡`（分组样式，两列）：分组 1「预期」：编号 / 假设 / 预期陈述 / 预期幅度 δ / 判据 / 失败时的备选解释；分组 2「结果」：写下时间 / 达成情况 / 实际幅度 / 结论；分组 3「调整留痕」：是否事后调整过 / 调整说明。

**表单**：新增表单视图 `补一行矩阵`，字段限定为 假设 / 数据集 / 方法 / 变体说明 / 主指标 / 种子数 六项——用于布置矩阵时快速铺行。预期结果卡不进表单。

## 5. 自动化设计

| 名称 | 触发器 | 条件 | 动作 | 防的坑 |
| --- | --- | --- | --- | --- |
| 无预期卡不放行 | `record_created` on `10 实验矩阵` | `预期结果卡` 为空 | `add_comment`（“先写预期结果，再跑实验：请补一张预期结果卡，写明幅度、判据、失败后的备选解释”）+ `notify` | 跑完再写预期 = 编故事 |
| 预期未达即回验 | `field_equals`（`达成情况` = 未达成） | —— | `add_comment`（“预期未达成：请对照『失败时的备选解释』逐条核查，不要直接调低预期幅度；若原因指向机制问题，去 `11 消融计划` 建一条待办，若指向实现问题，去 `16 调试记录` 建一条”） | 未达成被悄悄改低 δ 掩盖 |
| 种子数低于底线告警 | `field_equals`（`种子数` < 3） | —— | `notify`（“种子数低于底线 3；若确有理由（如确定性算法），写进 `种子依据`”） | 单种子跑出「最好成绩」 |
| 计划外变体提醒 | `field_equals`（`是否预先列入` 未勾选） | `状态 = 完成` | `add_comment`（“计划外变体：结果不直接进论文；要么把它补进行矩阵并补预期卡，要么标注为探索性观察”） | 顺手跑的结果混进正文 |

> **关于「预期未达即回验」的修正**：跨表建档不能用 `create_record`（它只能建在 `10 实验矩阵` 里），故以评论引导人工补录——**「由人选择去哪张表」本来就是这一步的判断内容**，交给自动化反而会把判断做掉。

> 自动化的四条动作边界（动作只作用于触发记录、动作之间无分支、`notify` 须指定接收人、`field_equals` 会重复命中）见 `README.md` §3 与 `_系统能力现状.md` §2。

## 6. 智能体设计

### 站内智能体

**`预期卡审问者`（模式：`prompt`）**

- 输入：假设（六要素）+ MVE/预实验结果 + 预期结果卡草稿。
- 输出三问：①这条预期能否被现有实验证伪？若不能，缺哪个对照；②δ 是否小于种子噪声量级？（把已有运行的标准差贴给它）③备选解释是否覆盖了最可能的混淆变量（训练预算/数据划分/评测协议）？
- 输出写入卡片评论，不改字段。
- 系统提示词骨架：

```text
你是预期结果卡的审问者。对给定的假设、已有预实验统计与预期卡草稿，只回答三个问题，每问给「通过 / 不通过 / 需修改」与一句理由：

1. 可证伪性：如果期望结果不出现，这张卡是否明确要求放弃或修订假设？若「不一定」，指出缺的对照；
2. 幅度合理性：给定的 δ 与已有种子间标准差相比是否落在噪声量级之外？用我给的标准差做判断，不要猜；
3. 备选解释覆盖度：最可能的混淆变量是训练预算、数据划分、评测协议——卡片现有的备选解释漏了哪一个？

【硬约束】
- 不允许建议提高 δ「以显得有信心」，也不允许建议降低 δ「以降低风险」；
- 所有判断引用我提供的数字，不允许引入外部数值；
- 你的输出是修改建议，状态变更由人执行。
```

### 外部 MCP 工作流

1. **矩阵铺行**：外部 Agent 读 `假设登记` 的待验证假设，按「数据集 × 方法」生成矩阵行草稿（`create_record`），人整理后定稿。
2. **基线协议采集**：近作对比表的训练预算与评测协议，写入 `冻结变量与放开变量` 草稿（防混淆变量：同预算同协议）。

### 红线（AI 只能给草稿）

- **`预期陈述` 与 `预期幅度 δ` 必须人写**。AI 可以审问，不能代替你下注。
- **`是否事后调整过` 只能由人勾选**，且勾选不丢人——丢人的是没勾。
- **`冻结变量与放开变量` 由人定**。放开变量的取值依据是实验设计的核心判断。

## 7. 与其他讲的接口

- **上游**：`假设登记`（第 09 讲）；`03 可行性冲刺`（MVE 是矩阵的第一行）。
- **下游**：
  - 第 11 讲：`方法 = 消融变体` 的行进入消融计划树；`关联实验单元` 反向链接。
  - 第 12 讲：一行矩阵 → N 份配置（多种子）。
  - 第 15 讲：一次配置 → N 条运行记录；`指标预声明` 与预期卡的 `判据` 对齐。
  - 第 18 讲：矩阵即主实验表的骨架。
  - 第 22 讲：核查清单的统计区对照预期卡查事后摘樱桃（`是否事后调整过` 是重点核查字段）。
- **单一事实来源**：**预期结果只在 `10 预期结果卡`**。论文里的「预期」「预注册」表述回填自它；不允许在正文草稿里另写一份。

## 8. 分期实施与验收

### P0（纯配置，零代码）

1. 建 `10 实验矩阵`（自动编号 `m-`）与 `10 预期结果卡`（自动编号 `E-`）。
2. 建七个视图：实验矩阵 / 三层对照缺口 / 计划外变体 / 待跑队列 / 先卡后跑 / 未达成清单 / 事后调整过。
3. 建表单视图 `补一行矩阵`。
4. 建四条自动化：无预期卡不放行 / 预期未达即回验 / 种子数低于底线告警 / 计划外变体提醒。
5. 建站内智能体 `预期卡审问者`，提示词入 `提示词库`。
6. 建仪表盘 `实验全景`。

### P1（少量增强）

| 需求 | 说明 | 建议落点 |
| --- | --- | --- |
| `δ 是否大于噪声` 的辅助计算 | 现在把标准差贴给智能体判断 | 脚本或外部工具 |
| 矩阵与配置的批量生成 | 一行矩阵 × 种子数 → N 份配置 | MCP 脚本（第 12 讲协同） |
| `预期结果卡` 锁定 | 原文要求「无法事后修改的地方」 | 记录锁定（`src/store.ts` 记录级写保护）——真正的防篡改，当前用历史留痕 + 显式字段替代 |

### P2（可选）

- 达成率趋势：`达成情况` 按月聚合——测的是自己写预期的校准度。
- 与第 15 讲的运行数据联动：`实际幅度` 从运行记录自动汇总（需脚本）。

### 验收标准

1. `先卡后跑` 视图为空：每条非「计划中」的矩阵行都有预期卡。
2. 每条矩阵行的 `种子依据` 非空，且种子数 ≥ 3。
3. `三层对照缺口` 视图逐步清零（空白对照被补上）。
4. `计划外变体` 里的结果没有直接进入任何 `17 段落卡` 的证据清单。
5. 预期未达成的卡里，`结论` 栏能逐条回应 `失败时的备选解释`。
6. `事后调整过` 视图里的条目都有 `调整说明`，且其时间线（写下时间 → 调整个数）可被历史记录验证。

## 9. 与原文的偏差说明

| 偏差 | 原文做法 | 本设计做法 | 理由 |
| --- | --- | --- | --- |
| 预期的存放 | 「写在无法事后修改的地方」（实验日志、版本控制、状态栏） | 表 `10 预期结果卡`：`写下时间` 为系统创建时间字段（不可改）+ `是否事后调整过` 显式字段 + 变更历史留痕 | 系统当前无法物理锁死记录；用「不可改的时间戳 + 调整留痕」逼近原文的防篡改意图，物理锁定标为 P1 |
| 矩阵与矩阵外 | 「矩阵外跑出来的结果不直接使用」 | `是否预先列入` 复选框 + `计划外变体` 视图 | 把「不直接使用」变成可审计的状态，而不是一句自觉 |
| 判据的选择 | 提到检验方法的选择 | `判据` 单选（跑前定死）+ 事后不得切换的纪律写入字段说明 | 切换判据 = 事后摘樱桃的变体；单选字段让切换必然留下痕迹 |
| 种子数的经验值 | 3 底线 / 关键 5–10 | `种子数` 数字 + `种子依据` 必填 + 告警 | 「底线」需要一个会被触发的条件 |
| 统计计算 | 未规定系统边界 | 明确标注：检验与 CI 在系统外算，系统只登记 | 能力边界（系统无计算能力）的诚实声明 |
