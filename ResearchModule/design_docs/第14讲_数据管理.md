# 第 14 讲 数据管理：系统落地设计

> 来源：`../design_principle/第14讲_数据管理.pdf`
> 落地度：★★★★★（高） ｜ 依赖：第 12 讲（数据版本进环境指纹） ｜ 主体分期：P0
> 主产物：表 `14 数据资产`（一行 = 一个数据集，承载数据卡五要素与冻结/可重建状态）+ 表 `14 泄漏检查`（一行 = 一次切分后的检查）

## 1. 本讲方法要点

1. **总原则一句**：把数据分成「证据」与「计算结果」两类分别对待——**原始数据是证据，只能冻结不能涂改；派生数据是计算结果，必须能由脚本一键重建**。
2. **两类数据的待遇相反**：原始数据的每一次触碰都要留痕；派生数据鼓励随时删除——它的存在只是为了省去重算的时间，一旦来源可疑应当毫不犹豫删掉重建。
3. **三层目录**：原始层（第一手文件，入库即只读并记录内容哈希）、中间层（清洗对齐等中间产物，由脚本生成、随时可删）、结果层（直接喂给模型或分析的终态，同样由脚本生成并附生成命令）。
4. **两个推论**：其一，派生数据不进版本库、生成它的脚本必须进——**库里有脚本加原始数据，就等于拥有一切派生数据**；其二，每次重新生成后与基线核对哈希或行数，防止「同名不同内容」的静默漂移。
5. **哈希清单还有两个用途**：检测数据在传输与备份中的损坏（从合作者收到数据、从云存储取回备份时先校哈希）；给数据版本号一个够用的实现（日期 + 内容哈希已经够用，不必上复杂系统）。
6. **命名要纪律化**：派生文件名应能反推出「用什么原始数据、经哪道工序、在什么时间生成」——带上日期与版本号的命名远比「最终版」「最终版 2」可靠。**文件名的信息量，决定了三个月后你还愿不愿意打开这个目录**。
7. **只读要从约定升级为权限**：多人共用数据目录时，依赖自觉的只读迟早会被某一次「临时改一下」打破；操作系统级的写保护，是唯一不依赖意志力的保护。
8. **数据卡五要素**：来源（从哪来、谁采集、采集时间与方式）、规模（样本量、字段数、体量）、分布（关键字段分布、类别比例、时间跨度）、已知偏差（覆盖不全的群体、采样偏差、标注噪声）、许可（使用授权、能否再分发、引用要求）。写入时机是**入库时写初稿、每次加工时更新**，而不是投稿前补写。
9. **数据卡的两个尺度**：粒度上一个数据集一张卡（而不是一个项目一张卡——同一项目里两个数据集的偏差与许可往往完全不同）；存放上「卡随数走」（同一目录、同名不同后缀，数据集一动数据卡必须跟着动）。
10. **「已知偏差」的检验标准**：这一条能否指导读者调整使用方式？「样本可能存在偏差」是废话；「周末样本稀疏，不宜用于周末行为推断」才是可用的话——**每条偏差都应当配一句「因此不要拿它做什么」**。
11. **三类高频泄漏**：时间泄漏（用未来的信息预测过去）、组泄漏（同一实体的样本被切到训练与测试两侧，模型记住的是人而不是规律）、预处理泄漏（切分之前做归一化/特征选择/过采样，测试集信息经由统计量渗入训练）。
12. **排查按固定顺序**：先问「每个样本属于哪个实体、哪个时间点」，据此决定按时间切还是按组切，**而不是默认随机切**；再确认所有预处理只在训练折上拟合；最后做诊断实验——训练一个只允许看切分标签的分类器，若它能轻易区分训练与测试样本，说明两侧分布已不该地不同，必须回头检查切分逻辑。
13. **交叉验证是泄漏的高发区**：每一折内部独立完成拟合与变换——「折内自足」。**把切分方式本身也当作实验产物记录下来**：切分依据、切点取值、随机种子；不记录切分方式，指标就失去了与他人比较的共同基准。
14. **直觉检验**：如果离线指标好得超出领域常识，先怀疑泄漏，再庆祝发现。

**不建议系统化的部分**：

- **数据存储、备份、版本控制的具体工具**（DVC / git-lfs / 对象存储）不进系统。系统只登记三件事：**哈希、只读状态、能否重建**。
- **清洗与切分的代码本体**。系统收的是「生成命令」与「切分方式」，代码留在仓库里。
- **诊断分类器的实现**。那几行代码属于脚本，系统收它的 AUC 与结论。
- **分布的具体统计量**。`分布` 字段写的是关键结论（如「峰值时段占 62%」「5 个区覆盖、2 个区欠采样」），不是完整的统计报告——统计报告放在数据卡文件里，字段是它的摘要。

## 3. 数据模型设计

### 3.1 表结构

空间：`科研方法`。表：`14 数据资产`（一行 = 一个数据集；一个项目里的两个数据集就是两行）。

| 字段 | 类型 | 选项 / 说明 |
| --- | --- | --- |
| 名称 | 文本（标题字段） | 如 `traffic-survey-2025` |
| 层级 | 单选 | 原始 raw / 中间 interim / 结果 processed |
| 路径 | 文本 | 如 `data/raw/traffic-survey-2025/` |
| 哈希 | 文本 | 原始层必填：`sha256` 摘要或 `SHA256SUMS` 附件路径 |
| 只读 | 复选框 | 原始层必填；由自动化在新建时自动勾选 |
| 生成脚本 | 超链接 | 派生层的生成脚本（如 `scripts/make_processed.py`） |
| 生成命令 | 多行文本 | 完整可复制执行的命令 |
| 可重建 | 复选框 | 派生层必填：删掉后能否一键重建 |
| 来源 | 多行文本 | 从哪来、谁采集、采集时间与方式 |
| 规模 | 多行文本 | 样本量、字段数、体量大小 |
| 分布 | 多行文本 | 关键字段分布、类别比例、时间跨度 |
| 已知偏差 | 多行文本 | **每条偏差配一句「因此不要拿它做什么」**；写「未知」也比空着强 |
| 许可 | 多行文本 | 使用授权、能否再分发、引用要求 |
| 数据卡初稿时间 | 日期 | 入库当天 |
| 最近更新 | 日期 | 每次加工时更新 |
| 既原始又改过 | 复选框 | 自查项——**这个字段长期应为空** |
| 版本标记 | 文本 | 如 `v1.2 (2025-06-01, dedup applied)`；日期 + 内容哈希已够用 |
| 涉及项目 | 关联 → `假设登记` / `稿件`（多值） | 本数据集服务于哪条假设、哪篇稿件 |
| 审定三件套 | 单选 + 成员 + 时间 | 审定状态 / 审定人 / 审定时间 |

表：`14 泄漏检查`（一行 = 一次切分后的一轮检查）。

| 字段 | 类型 | 选项 / 说明 |
| --- | --- | --- |
| 数据集 | 关联 → `14 数据资产`（单值） | —— |
| 切分方式 | 单选 | 按时间 / 按组 / 随机 |
| 实体定义 | 文本 | 每个样本属于哪个实体（如「一位受访者」「一辆车」） |
| 时间边界 | 日期 | 仅时间切分：切点取值 |
| 切分种子 | 数字 | 与第 12 讲的种子口径一致 |
| 检查轮次 | 单选 | 三查·时间泄漏 / 三查·组泄漏 / 三查·预处理泄漏 |
| 结论 | 单选 | 通过 / 失败 / 待办 |
| 说明 | 多行文本 | 失败现象与处置 |
| 诊断分类器 AUC | 数字 | 仅诊断实验：明显优于 0.5 说明两侧分布异常 |
| 预处理拟合位置 | 单选 | 仅训练折拟合 / 全量拟合——**后者即泄漏** |
| 检查人 | 成员 | —— |
| 检查日期 | 日期 | —— |

**关系与公式**：

- `14 数据资产` → `14 泄漏检查`：一个数据集可以有多次切分、每轮三查各一行。
- `14 数据资产.哈希` → `12 环境指纹.依赖清单`：数据版本进环境指纹，两处哈希互认（第 12 讲的「数据版本」字段指向本表）。
- `实验记录.数据版本` → `14 数据资产`（第 15 讲）：一次运行用的是哪个数据版本，直接关联而不是手抄哈希。
- **不使用跨表聚合**：`切分未查` 用「无 `14 泄漏检查` 关联」的过滤表达（关联为空），不需要聚合函数。

### 3.2 记录样例

**样例 1（`14 数据资产` 的一行——原始层，入库即冻结）**

| 字段 | 值 |
| --- | --- |
| 名称 / 层级 | `traffic-survey-2025` ／ 原始 raw |
| 路径 | `data/raw/traffic-survey-2025/` |
| 哈希 | `a41f…9c02`（附件 `SHA256SUMS`） |
| 只读 | ✅（新建时由自动化勾选；目录已 `chmod -R a-w`） |
| 来源 | 实地调研，2025-03 至 2025-05，城市 A，问卷 + 浮动车 GPS 两路 |
| 规模 | 12,400 条记录，18 个字段，96 MB |
| 分布 | 峰值时段占 62%；覆盖 5 个区，其中 2 个区欠采样 |
| 已知偏差 | ① 周末样本稀疏——**因此不要用于周末行为推断**；② 设备 B 在低速段系统性低报——**因此低速结论需按设备分层重算** |
| 许可 | 仅内部使用；引用需注明 TR-2025-11 |
| 数据卡初稿时间 / 最近更新 | 2025-06-01 ／ 2025-06-01 |
| 既原始又改过 | ☐（**它必须一直是空的**） |
| 涉及项目 | H-04（城市路网的速度-流量关系建模） |

**样例 2（`14 数据资产` 的一行——结果层，必须可重建）**

| 字段 | 值 |
| --- | --- |
| 名称 / 层级 | `traffic-merged-v1.2` ／ 结果 processed |
| 路径 | `data/processed/traffic-merged-2025-06-01-v1.2.parquet` |
| 生成脚本 / 生成命令 | `scripts/make_processed.py` ／ `python scripts/make_processed.py --src data/interim/link-2025-06-01 --out data/processed/traffic-merged-2025-06-01-v1.2.parquet --dedup` |
| 可重建 | ✅（重建后行数与哈希与基线一致：11,860 行 / `7d31…b88e`） |
| 版本标记 | `v1.2 (2025-06-01, dedup applied)` |
| 已知偏差 | 去重丢弃 540 条重复上报——**因此异常低流量事件的计数偏低，不适合用于稀疏事件频率分析** |

**样例 3（`14 泄漏检查` 的三行——同一个切分的三查，其中一行抓到了泄漏）**

| 检查轮次 | 结论 | 说明 | 关键字段 |
| --- | --- | --- | --- |
| 三查·时间泄漏 | 通过 | 切点 2025-04-30；所有归一化统计量只用切点之前的数据计算 | 切分方式=按时间；时间边界=2025-04-30 |
| 三查·组泄漏 | 失败 | 初版按行随机切，同一受访者的两次问卷被切到两侧——改按实体（受访者 ID）切分后重跑，指标下降 1.8 个点 | 实体定义=受访者 ID；切分方式改为 `按组` |
| 三查·预处理泄漏 | 通过 | 缩放与特征选择已封进 `Pipeline`，只在训练折 `fit`；交叉验证每一折内部独立完成拟合与变换 | 预处理拟合位置=仅训练折拟合 |

「组泄漏失败」这一行才是这张表存在的价值：**指标下降 1.8 个点不是坏消息，是泄漏被抓住了**。

## 4. 视图与交互设计

| 视图名 | 类型 | 配置要点 |
| --- | --- | --- |
| 数据卡补全度（`14 数据资产`） | grid | 按 `层级` 分组；列只取五要素字段——看哪些还空着，一屏扫完 |
| 派生可重建（`14 数据资产`） | grid | 过滤：`层级 ≠ 原始` 且 `可重建` 未勾选；颜色规则：红色——危险清单 |
| 原始未冻结（`14 数据资产`） | grid | 过滤：`层级 = 原始` 且（`哈希` 为空 或 `只读` 未勾选） |
| 就地清洗嫌疑（`14 数据资产`） | grid | 过滤：`既原始又改过` 勾选——**这个视图应该长期为空** |
| 按许可分组（`14 数据资产`） | grid | 按 `许可` 分组的变体：手动把许可归成几档文本再分组（如「内部使用」「可再分发」「引用受限」）；P1 建议改为单选字段 |
| 预处理泄漏嫌疑（`14 泄漏检查`） | grid | 过滤：`预处理拟合位置 = 全量拟合` |
| 诊断异常（`14 泄漏检查`） | grid | 过滤：`诊断分类器 AUC > 0.7` |
| 切分未查（`14 数据资产`） | grid | 过滤：无 `14 泄漏检查` 关联——「这个数据集到底怎么切的」还没有答案 |
| 未通过（`14 泄漏检查`） | grid | 过滤：`结论 ≠ 通过` |

**记录详情页布局**：

- `14 数据资产`（分组样式，两列）：分组 1「身份与层级」：名称 / 层级 / 路径 / 版本标记；分组 2「冻结与重建」：哈希 / 只读 / 生成脚本 / 生成命令 / 可重建 / 既原始又改过；分组 3「数据卡」：来源 / 规模 / 分布 / 已知偏差 / 许可 / 数据卡初稿时间 / 最近更新；分组 4「关联」：涉及项目 / 审定三件套。
- `14 泄漏检查`（分组样式，两列）：分组 1「切分」：数据集 / 切分方式 / 实体定义 / 时间边界 / 切分种子；分组 2「三查」：检查轮次 / 结论 / 说明 / 诊断分类器 AUC / 预处理拟合位置 / 检查人 / 检查日期。

**表单**：

- `登记一个数据集`：字段限定为 名称 / 层级 / 路径 / 哈希 / 只读 / 来源 / 规模 / 许可 —— 入库当天三分钟写完初稿（**允许粗糙：先把五要素占住位**）。
- `记一次泄漏检查`：字段限定为 数据集 / 切分方式 / 检查轮次 / 结论 / 说明 —— 切完就查，查完就记。

**仪表盘**（可选）：`数据健康度`——count（数据集数 / 未冻结数 / 不可重建数 / 泄漏未查数）、pie（按层级的分布）。比值类指标（数据卡完整率）由仪表盘算，不在表内算（见 `README` 第 3 节能力边界 3）。

## 5. 自动化设计

| 名称 | 触发器 | 条件 | 动作 | 防的坑 |
| --- | --- | --- | --- | --- |
| 原始即冻结 | `record_created` on `14 数据资产` | `层级 = 原始` | `set_field`（`只读` = 勾选）+ `add_comment`（“原始数据是证据，只冻结不涂改；请补齐内容哈希与数据卡初稿”） | 入库时忘了设只读，某天被人「顺手改一下」 |
| 派生必须可重建 | `field_equals`（`层级` = 中间 或 结果） | `可重建` 未勾选 | `notify`（“派生数据必须能由脚本一键重建，并附生成命令——留下的不是数据，是无法确认来源的文件”） | 中间产物越攒越多、来源越来越不可知 |
| 切分必查泄漏 | `record_created` on `14 泄漏检查` | `检查轮次 ≠ 三查·预处理泄漏` | `add_comment`（“三查要齐：时间、组、预处理，缺一不可；排查顺序是先定切分方式，再确认拟合位置，最后做诊断实验”） | 只做了一轮就宣布干净 |
| 就地清洗即告警 | `field_equals`（`既原始又改过` = 勾选） | —— | `notify` + `add_comment`（“原始层的一次『顺手』就永远失去回溯能力：请把改动回退到 `data/interim` 重做，并在 `处置` 里说明”） | 「既原始又被改过」的文件静默存在 |

> 自动化的四条动作边界（动作只作用于触发记录、动作之间无分支、`notify` 须指定接收人、`field_equals` 会重复命中）见 `README.md` §3 与 `_系统能力现状.md` §2。

## 6. 智能体设计

### 站内智能体

**`数据卡起草员`（模式：`prompt`）**

- 输入（用户提供）：目录结构、样例若干行、字段清单、已有的统计输出（如类别比例、时间跨度）。
- 输出：五要素初稿（来源 / 规模 / 分布 / 已知偏差 / 许可），并把每一项的来源标注清楚（来自统计输出 / 来自你告知 / 无法确定）。
- 系统提示词骨架：

```text
你是数据卡的起草员。输入是数据目录结构、样例行、字段清单与统计输出。

【任务】按五要素起草数据卡初稿：来源、规模、分布、已知偏差、许可。
每一项都要标注信息出处：［统计输出］/［用户告知］/［无法确定］。

【硬约束】
- 「已知偏差」一栏只允许写两种内容：从统计输出中直接读出的偏差（如类别比例失衡、时间覆盖不连续），或「未知」；
  禁止凭空猜测偏差——编造的偏差比空白更有害，它会误导后续的使用者；
- 每条偏差后面必须补一句「因此不要拿它做什么」；
- 许可一栏若输入里没有依据，一律写「未知，需人工确认」，不得推断。
```

### 外部 MCP 工作流

1. **目录扫描与哈希登记（P1）**：外部 Agent 扫描 `data/raw/` 下每个目录，计算 `sha256` 摘要与文件数/行数，用 `create_record` 批量写入 `14 数据资产`，并与已有记录比对，输出「新增 / 变更 / 消失」三张清单。**哈希变更的原始层记录必须人工确认**——它可能意味着证据被改过。
2. **数据卡 YAML 与表字段对账**：把每个数据集的 `datasheet.yaml` 与表字段比对，输出不一致清单（表里改了、文件没改，或反之）。
3. **备份/传输后的完整性校验**：从云存储取回备份或从合作者收到数据后，比对哈希，把结果写进 `说明` 字段或 `14 泄漏检查` 之外的独立检查记录（P1）。

### 红线（AI 只能给草稿）

- **`已知偏差` 必须经人确认**。这是数据卡里最容易流于空话、也最容易由 AI 编出来的一栏。AI 只允许搬运统计输出里的结论或写「未知」。
- **`泄漏检查.结论` 由人判**。诊断分类器 AUC 是证据，泄漏是否成立、是否影响结论，必须人看原始实验。
- **`许可` 由人确认**。授权范围涉及法律与机构规定，AI 一律不得推断。
- **数据处理代码不进系统**，也**不由 AI 直接改**已有清洗脚本——按第 13 讲，改动要走契约与三遍审查。

## 7. 与其他讲的接口

- **上游**：`假设登记`（数据服务于哪条假设，经 `涉及项目` 字段）。
- **下游**：
  - 第 12 讲：数据版本进环境指纹（`12 环境指纹` 的 `依赖清单` 与本表 `哈希` 互认）。
  - 第 15 讲：`实验记录.数据版本` 直接关联本表，而不是手抄哈希——这是第 15 讲唯一一处自动化增强，理由正来自本讲「数据版本最容易静默漂移」。
  - 第 18 讲：`18 图表台账.数据来源` 沿 `实验记录` 再往上追就是本表的数据集。
  - 第 22 讲：核查清单的合规区——数据可用性声明的原料来自本表的 `来源` 与 `许可`；统计区会看切分方式与泄漏检查。
- **单一事实来源**：**数据卡只在本表**；论文的 Data Availability 与伦理审查材料从本表成文。文件实体在目录里，**哈希与许可是系统口径**。

## 8. 分期实施与验收

### P0（纯配置，零代码）

1. 建 `14 数据资产` 与 `14 泄漏检查` 两张表。
2. 建视图：数据卡补全度 / 派生可重建 / 原始未冻结 / 就地清洗嫌疑 / 按许可分组 / 预处理泄漏嫌疑 / 诊断异常 / 切分未查 / 未通过。
3. 建两个表单视图：`登记一个数据集`、`记一次泄漏检查`。
4. 建四条自动化：原始即冻结 / 派生必须可重建 / 切分必查泄漏 / 就地清洗即告警。
5. 建站内智能体 `数据卡起草员`，提示词入 `提示词库`。
6. 打通与第 15 讲的接口：`实验记录.数据版本` → `14 数据资产`（该字段在本讲定义后，第 15 讲直接引用）。
7. 文档约定：三层目录与命名规范（`data/raw` / `data/interim` / `data/processed`，`chmod -R a-w`，`SHA256SUMS`）写进项目 README——**这是本讲唯一进系统外文档的部分**。

### P1（少量增强）

| 需求 | 说明 | 建议落点 |
| --- | --- | --- |
| 目录扫描与哈希自动登记 | 现在靠人手抄哈希 | MCP 工作流 + 脚本 |
| 数据卡 YAML ↔ 表字段对账 | 现在两份副本靠人同步 | 脚本 |
| 数据卡部分字段自动预填 | `规模` / `分布` 从统计输出自动抽取 | 脚本 |
| 许可做成单选 + 选项组 | 现在 `按许可分组` 只能按自由文本分组 | 视图分组能力足够，但字段改单选更稳；属微小改动 |

### P2（可选）

- 「数据血缘」视图：把一个 `结果` 层数据集沿 `生成脚本` → 中间层 → 原始层的链条画出来（需要跨表递归，现有能力不足，属长期设想）。
- 数据卡导出成 `datasheet.yaml`（与仓库里的副本双向同步）。
- 年度数据资产盘点：哪些数据集从未被任何 `实验记录` 引用过——僵尸数据的清单。

### 验收标准

1. `原始未冻结` 视图为空：每个原始数据集都有哈希且 `只读` 已勾选。
2. `就地清洗嫌疑` 视图长期为空。
3. `派生可重建` 视图为空，且每个派生数据集的 `生成命令` 能复制执行并复现相同的行数（或差异已说明）。
4. 每个数据集的五要素都已填写；`已知偏差` 的每一条都带一句「因此不要拿它做什么」。
5. `切分未查` 视图为空：每个用于实验的数据集都至少有一轮泄漏检查。
6. 主数据集的三查记录各一条，`预处理拟合位置 = 仅训练折拟合`。
7. 抽查一次运行的 `实验记录.数据版本`，能追到本表的哈希与版本标记。

## 9. 与原文的偏差说明

| 偏差 | 原文做法 | 本设计做法 | 理由 |
| --- | --- | --- | --- |
| 三层目录 | 本地文件系统约定 | 用 `层级` 字段把文件系统结构镜像进表 | 好处是**「哪些派生数据已不可重建」「哪些原始数据被改过」变成可筛选清单**——原文只能靠人记得。目录仍是执行层，表是审计层 |
| 数据卡存放 | 「卡随数走」：与数据集同目录、同名不同后缀 | 文件与表各一份：`datasheet.yaml` 管可携带，表管可查询与可关联 | 只在文件里，数据卡无法参与「哪条假设用了哪个数据集」「哪篇稿件引用了哪份许可」这两类关联；代价是两份副本，故 P1 加对账 |
| 已知偏差 | 提醒「写未知也比空着强」 | 加一条硬约束：每条偏差配一句「因此不要拿它做什么」，并禁止 AI 猜测偏差 | 原文给了检验标准（能否指导读者调整使用方式），本设计把它变成写作要求与 AI 红线 |
| 泄漏三查 | 三类泄漏与排查顺序 | 表 `14 泄漏检查`，一行一轮，`检查轮次` 单选 + `预处理拟合位置` 单选 | 三查拆成三行之后，「只做了两查」这件事才会显形；`预处理拟合位置` 是三类泄漏里唯一可控成开关的一类 |
| 切分方式 | 「当作实验产物记录下来：切分依据、切点取值、随机种子」 | 落成 `切分方式` / `实体定义` / `时间边界` / `切分种子` 四个字段 | 原文的「共同基准」要求他人能把你的切分复现出来，四个字段刚好构成最小可复现描述 |
| 数据版本号 | 「日期加内容哈希已经够用」 | `版本标记` 自由文本 + `哈希` 字段 | 不引入语义化版本号的强约束：数据版本的价值在于可核对，不在于可比较大小 |
| 诊断分类器 | 一段方法论（做一次诊断实验） | `诊断分类器 AUC` 数字字段 + `> 0.7` 的告警视图 | 阈值 0.7 是本设计的补充判断（原文只说「能轻易区分」）；之所以给定一个数，是因为给不出数的检查项永远会被跳过 |
