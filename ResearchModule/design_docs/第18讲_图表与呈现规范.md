# 第 18 讲 图表与呈现规范：系统落地设计

> 来源：`../design_principle/第18讲_图表与呈现规范.pdf`
> 落地度：★★★★☆（高） ｜ 依赖：第 15 / 17 讲 ｜ 主体分期：P0
> 主产物：表 `18 图表台账`（一行 = 一张图或表，承载三项一致性、消融表规范、格式红线与像素核对记录）

## 1. 本讲方法要点

1. **图表先行：先做表，再写文**。图表是论文的「数据结构」，正文只是「遍历函数」——数据结构定了，遍历代码自然清晰。顺序是：主实验表 → 消融表 → 分析图（误差分析、超参曲线、可视化案例）→ 排定后按表号顺序撰写实验节，**每段对应一张表/图，禁止跳号**。
2. **主实验表要让读者能在 10 秒内定位「谁最优、高多少、在哪个数据集」**：行是所有对比方法，列是数据集与评价指标。
3. **排版三个一致性**：方法列的命名统一（自洽缩写或全称）、评价指标的小数位数一致（建议保留三位有效数字）、最优结果用**粗体**、次优用**下划线**并在脚注或表注中说明。**基线方法需用特殊标记（如 †）区分**，避免读者误把你的方法当成基线。
4. **图注的自足性**：读者应当不翻正文就能看懂图表。图注需包含实验设置的关键参数（数据集、划分方式、指标定义）、误差棒的含义（标准差还是置信区间、来自几次独立运行）、显著性标记的说明。**审稿人翻阅论文的第一个动作往往是「先看图表和图注」**——图表不过关，正文很难获得被细读的机会。
5. **消融表必须让「代价」一目了然**：完整模型放第一行，下方逐行减去单一模块，**差值列单独列出。绝对禁止把完整模型藏在表格中间或末尾**。
6. **学习曲线图的关键是信息量密度**：一张图只应传递一个核心信息（要么收敛速度差异，要么超参敏感性，不要混排）；坐标轴必须标注**物理含义与单位**；图例位置不遮挡数据；曲线使用可区分的线型/标记组合而非仅靠颜色（考虑黑白打印）；误差棒应来自至少 3 次独立随机种子实验，并在图注中说明。
7. **灰度可区分测试**：把图打印成黑白，曲线仍应可区分——因此曲线用**线型（实线/虚线/点线）与标记（圆点/三角/方块）双重编码**，颜色只作辅助。约有一成男性读者存在不同程度的色觉异常，**红绿对照是最应避免的配色组合**。
8. **显著性信息不可省略**：若表中数字来自多次运行，应在表注说明均值与标准差（如 `85.6 ± 0.3`）；声称「优于基线」时，给出统计检验结果或至少多次运行的一致性证据。**只报单次最优运行的数字，在审稿中越来越难以通过**。
9. **格式铁律**：所有线图、示意图、流程图**一律使用矢量格式**（PDF/EPS/SVG），放大 400% 边缘仍应锐利；照片、热力图等栅格图必须使用 300 dpi 以上的 PNG，且生成时未经有损压缩。**绝对不能使用 JPG 保存含文字的线条图**——文字边缘会出现压缩伪影。
10. **提交前的自动化检查**：放大打印预览至 200%，若任何文字出现锯齿就返回源码重新导出；许多会议的投稿系统自动压缩 PDF，提交前用 PDF 优化工具检查嵌入图片的 dpi。
11. **三个常见格式陷阱**：从 Excel 截图贴入表格（分辨率极低且不可编辑）；从演示软件导出流程图时默认输出位图（应选择 PDF 或 EMF 等矢量格式）；绘图软件默认导出含宽大边框（需裁剪，否则图在版面上越排越小）。
12. **用 AI 生成图表代码、人工定稿**：人给出草图（手绘或文字描述布局），AI 生成 matplotlib / pgfplots / ggplot2 代码，**人执行并逐像素核对**。AI「不负责任」——它可能给纵轴标错单位、用错颜色映射、或在图例里丢一个字。
13. **定稿时的人工检查清单**：数字与正文完全一致、表注与脚注无遗漏、粗体/下划线逻辑正确、**跨页表格已用 longtable 或拆表处理**。AI 生成的代码通常需要人工调整字号、列宽和垂直间距才能融入正文的版式。

**不建议系统化的部分**：

- **绘图本体、配色审美、图形的视觉设计**不进系统。系统承担的是「版式规范能不能被检查」这件事。
- **图片文件本体**。`文件` 字段存附件，但图表的事实来源是**绘图代码与数据来源**——图片可以重画，代码与数据不能凭空长出。
- **「10 秒内能否定位最优值」这类读者体验判断**。它只能在人对着成品看的时候判断；系统提供 `读者应带走的结论` 这个字段来逼出答案，但不做自动判定。

## 3. 数据模型设计

### 3.1 表结构

空间：`科研方法`。表：`18 图表台账`（一行 = 一张图或表）。

| 字段 | 类型 | 选项 / 说明 |
| --- | --- | --- |
| 编号 | 文本（标题字段） | 如「图 2」「表 3」——**编号即排序键** |
| 稿件 | 关联 → `稿件`（单值） | 第 17 讲定义 |
| 类型 | 单选 | 主实验表 / 消融表 / 分析图·学习曲线 / 分析图·误差 / 分析图·案例可视化 / 示意图 / 流程图 / 照片 / 热力图 |
| 文件 | 附件 | 成品图（PDF/PNG 等） |
| 格式 | 单选 | 矢量 PDF / EPS / SVG / PNG ≥300dpi / JPG / 其他 |
| 源文件路径 | 文本 | 如 `figs/fig2_curve.py`、`tables/tab3.tex` |
| 绘图代码 | 超链接 | 或附件；代码与图必须能对上号 |
| 读者应带走的结论 | 文本 | **一句话**；写不出这一句的图表不该存在 |
| 核心信息数 | 单选 | 一个 / 多个——「单图单信息」，多个即需拆分 |
| 数据来源 | 关联 → `实验记录`（多值） | 图表数字的出处 |
| 三项一致性 | 多选 | 方法列命名统一 / 小数位一致 / 最优粗体次优下划线 / 基线已标 † |
| 消融表规范 | 多选（仅消融表） | 完整模型置顶 / 每行只改一处 / 含 ∆ 列 / 与主表同协议 |
| 坐标轴标注 | 复选框 | 标注物理含义与单位 |
| 误差棒说明 | 多行文本 | 误差棒代表什么、来自几次独立运行 |
| 图注自包含 | 复选框 | 样本量 / 误差棒含义 / 显著性标记规则全写明，脱离正文可读 |
| 灰度与色盲可辨 | 复选框 | 线型 + 标记双重编码；无红绿对照 |
| 显著性说明 | 多行文本 | 均值 ± 标准差，或统计检验结果 |
| 跨页处理 | 单选 | 不适用 / 已用 longtable / 已拆表 |
| 与正文数字一致 | 复选框 | 逐字核对过 |
| 放大 400% 无锯齿 | 复选框 | 矢量图的验收动作 |
| AI 生成代码 | 复选框 | —— |
| 逐像素核对 | 复选框 | **AI 生成代码后必须勾选这一项才算定稿** |
| 状态 | 单选 | 草稿 / 代码已生成待核对 / 人工定稿 / 已提交 |
| 审定三件套 | 单选 + 成员 + 时间 | 审定状态 / 审定人 / 审定时间 |

**关系与公式**：

- `稿件` → `18 图表台账`：一篇稿件的全部图表，按 `编号` 排序即版式顺序。
- `18 图表台账.数据来源` ↔ `实验记录.关联图表`：**图表数字的全链路追溯**（实验记录 → 配置台账 → 种子与环境）。
- `17 段落卡.关联图表` → 本表：段落卡用图表作为证据锚点。
- **不使用跨表聚合**：本讲不涉及。

- `18 图表台账`（分组样式，两列）：分组 1「身份」：编号 / 稿件 / 类型 / 状态；分组 2「结论与信息量」：读者应带走的结论 / 核心信息数；分组 3「文件与代码」：文件 / 格式 / 源文件路径 / 绘图代码 / AI 生成代码 / 逐像素核对；分组 4「规范核对」：三项一致性 / 消融表规范 / 坐标轴标注 / 误差棒说明 / 图注自包含 / 灰度与色盲可辨 / 显著性说明 / 跨页处理 / 放大 400% 无锯齿；分组 5「数字与来源」：数据来源 / 与正文数字一致 / 审定三件套。

- `排一张图表`：字段限定为 编号 / 稿件 / 类型 / 读者应带走的结论 / 核心信息数 / 数据来源 —— **动笔写正文之前先排定**。

## 5. 自动化设计

| 名称 | 触发器 | 条件 | 动作 | 防的坑 |
| --- | --- | --- | --- | --- |
| JPG 红线告警 | `field_equals`（`格式` = JPG） | —— | `notify`（“含文字的线条图禁止用 JPG：文字边缘会出现压缩伪影，审稿人放大阅读时直接判定为粗糙工作”）+ `add_comment` | 线图从绘图软件默认导出成 JPG |
| 消融表规范检查 | `field_equals`（`类型` = 消融表） | `消融表规范` 未含「完整模型置顶」 | `add_comment`（“绝对禁止把完整模型藏在表格中间或末尾”） | 读者必须翻到页底才知道完整性能 |
| 图表先行 | `record_created` on `18 图表台账` | `稿件.当前工序` 在「写方法」之后（即 ④–⑩） | `add_comment`（“图表应在正文之前排定：先做表，再写文——正文只是图表的遍历说明”） | 实验结果一出炉就急着写正文 |
| 单图单信息超载 | `field_equals`（`核心信息数` = 多个） | —— | `add_comment`（“一张图只应传递一个核心信息：要么收敛速度差异，要么超参敏感性，不要混排——请拆成两张图”） | 把两个故事塞进一张图 |
| 像素核对未做 | `field_equals`（`AI 生成代码` = 勾选）且 `逐像素核对` 未勾选 | —— | `add_comment`（“AI 会给纵轴标错单位、用错颜色映射、在图例里丢字——执行并逐像素核对后再定稿”） | AI 生成的图未经核对就进稿件 |

> 自动化的四条动作边界（动作作用范围限于触发记录或同库指定表、动作之间无分支、`notify` 须指定接收人、`field_equals` 会重复命中）见 `README.md` §3 与 `_系统能力现状.md` §2。

## 6. 智能体设计

### 站内智能体

**`图表代码员`（模式：`prompt`）**

- 输入（用户提供）：布局草图（手绘转成的文字描述）+ 数据来源（`实验记录` 里的数字或直接粘贴的表格）+ 目标格式（矢量 / 300dpi）。
- 输出：matplotlib / pgfplots / LaTeX 代码骨架，内含本讲的输出纪律（矢量优先、字体嵌入、单栏宽度）；**输出仅供执行，人逐像素核对后定稿，不得直接进稿件**。
- 系统提示词骨架：

```text
你是论文图表代码生成器。我会给你：布局草图（文字描述）、数据、目标格式。

【任务】输出可直接运行的代码骨架：
- 若是线图：matplotlib，含矢量优先与 300 dpi 双导出、字体嵌入（pdf.fonttype=42）、坐标轴标注物理含义与单位、
  曲线用线型 + 标记双重编码（不使用仅靠颜色的区分）、图例不遮挡数据；
- 若是表格：booktabs 风格的 LaTeX，行 = 方法、列 = 数据集(指标)，最优加粗、次优下划线、基线标 ${}^\dagger$、
  小数点对齐、表注放在表下方。

【硬约束】
- 数字一律引用我提供的值，不允许自己填任何数字，也不允许推算；
- 不确定单位时写 TODO 注释，不要猜；
- 不要加装饰性元素（阴影、渐变、三维效果）；
- 输出后列出你做的每一个假设（如「坐标轴范围取 0–1」），供我核对。
```

### 外部 MCP 工作流

1. **格式与分辨率扫描（P1）**：外部 Agent 扫描 `figs/` 目录，读每个文件的格式与 dpi 元数据，比对 `18 图表台账.格式` 与 `放大 400% 无锯齿`，输出不一致清单——把「提交前用 PDF 优化工具检查嵌入图片的 dpi」这一步落成可跑的检查。
2. **图表 ↔ 正文数字比对（P1）**：从 LaTeX 表格与正文中抽取数字做集合比对（与第 22 讲核查清单的「数字一致性区」共用脚本），异常逐条建记录。
3. **编号连续性检查**：比对 `稿件` 下所有图表的 `编号` 与正文里出现的引用编号，指出「正文引用了但台账里没有」和「台账里有但正文没引用」两类。

### 红线（AI 只能给草稿）

- **绘图代码由 AI 生成、人逐像素核对**。AI「不负责任」——纵轴单位、颜色映射、图例文字都可能出错。
- **一切数字来自 `实验记录`**，AI 不得新增或推算。
- **`读者应带走的结论` 由人写**。写不出这一句，说明这张图还没想清要讲什么——这正是本讲最锋利的一条纪律。
- **`状态 = 人工定稿` 由人推进**。AI 不能把图自己标成定稿。
- **格式与版式判断由人做**：字号、列宽、垂直间距的调整没有可自动化的标准。

## 7. 与其他讲的接口

- **上游**：`实验记录`（数字来源）；`11 消融计划`（消融表的行）；`稿件`（排定顺序与工序）。
- **下游**：
  - 第 17 讲：`17 段落卡.关联图表`——图表是段落的证据锚点，写作降格为看图说话。
  - 第 22 讲：核查清单的图像区（分辨率、篡改、图注自包含）与数字一致性区的判据来自本表。
  - 第 19 讲：投稿前的「48 小时检查」中「格式合规」与「数字一致性」两项以本表为准。
- **单一事实来源**：**图表编号与结论只在本表**；正文里的图表引用回填自它。同一张图不允许在正文里另起一个编号。

## 8. 分期实施与验收

### P0（纯配置，零代码）

1. 建 `18 图表台账`。
2. 建视图：未过格式检查 / 结论为空 / 一致性缺项 / 消融表合规 / 数字待核 / 图注不自足 / 按稿件排定顺序 / 待逐像素核对。
3. 建两个表单视图：`排一张图表`、`定稿核对`。
4. 建五条自动化：JPG 红线告警 / 消融表规范检查 / 图表先行 / 单图单信息超载 / 像素核对未做。
5. 建站内智能体 `图表代码员`，提示词入 `提示词库`。
6. 打通接口：`数据来源` → `实验记录`（多值）；`稿件` → `稿件`；`17 段落卡.关联图表` → 本表。
7. 文档约定：三个格式陷阱与跨页表格处理写进本文档的检查清单（不进系统）。

### P1（少量增强）

| 图表 ↔ 正文数字比对 | 与第 22 讲共用脚本 | 脚本 |

- 图表代码与成品的自动重建：给定 `源文件路径` 一键重跑生成 PDF（需要外部环境，属长期设想）。
- 灰度可辨的自动检查：把图转灰度后计算曲线间的像素差异——能自动发现「只靠颜色区分」的图。
- 图表台账导出为论文的图表清单（LaTeX `\listoffigures` 的替代）。

### 验收标准

1. `未过格式检查` 视图为空：没有 JPG 保存的线图，所有线图 `放大 400% 无锯齿` 已勾选。
2. `结论为空` 视图为空：每张图表都能用一句话说出读者应带走的结论。
3. 每张主实验表的 `三项一致性` 四项齐备；每张消融表的 `消融表规范` 四项齐备且**完整模型置顶**。
4. 每张分析图的 `核心信息数 = 一个`（多个的已拆分）。
5. 学习曲线图的 `误差棒说明` 写明「来自至少 3 次独立随机种子」；正文中声称「优于基线」处的表格有 `显著性说明`（均值 ± 标准差或检验结果）。
6. 所有 `AI 生成代码` 的图表都 `逐像素核对` 已勾选。
7. 提交前抽查一张表的数字与正文逐字一致（`与正文数字一致` 可复现）。

## 9. 与原文的偏差说明

| 偏差 | 原文做法 | 本设计做法 | 理由 |
| --- | --- | --- | --- |
| 提交前检查 | 一串人工动作（放大 200% 打印预览、dpi 检查、裁剪边框） | 拆成可勾选字段（`格式` / `放大 400% 无锯齿` / `与正文数字一致` / `逐像素核对`） | 一串人工动作的失败模式是「漏做一项」；拆成字段之后，「格式退回」这类事故在提交前就能被一个视图捞出来 |
| 消融表规范 | 表格版式规范（写作层） | 本表 `消融表规范` 多选 + 自动化；数字与机制解释的源头在第 11 讲 `11 消融计划` | 分工：**「表的版式」属图表规范，「数字与机制解释的质量」属消融设计**。两讲各管一头，避免同一事实两处维护 |
| 「读者应带走的结论」 | 隐含在「图注自足」的要求里 | 提成独立的一句话字段 + `结论为空` 视图 | 原文说「一张图只应传递一个核心信息」——写不出这一句话的图表，恰恰说明它信息数过多或根本没想清；用一个字段把这件事逼出来 |
| 单图单信息 | 一段要求 | `核心信息数` 单选 + 超载告警 | 「多个即需拆分」需要一个可判的开关；单选比自由文本更不容易自欺 |
| 灰度与色盲 | 「灰度可区分测试」+ 红绿禁忌 | 一个复选框 `灰度与色盲可辨` + 说明写进字段解释 | 自动化的灰度测试标为 P2；P0 先用一个复选框把这条纪律带上，避免它在写作现场被忘掉 |
| 表格的跨页处理 | 定稿检查清单里的一条 | `跨页处理` 单选（不适用 / longtable / 拆表） | 跨页表格是提交后的常见退回项；一个单选就能让它无法被忘掉 |
