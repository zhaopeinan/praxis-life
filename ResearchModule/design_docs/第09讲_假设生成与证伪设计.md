# 第 09 讲 假设生成与证伪设计：系统落地设计

> 来源：`../design_principle/第09讲_假设生成与证伪设计.pdf`
> 落地度：★★★★★（高） ｜ 依赖：第 02 / 03 讲 ｜ 主体分期：P0
> 主产物：共享表 `假设登记`（全书的假设唯一事实来源，第 10 / 11 / 12 / 15 / 17 讲共用）+ 表 `09 红队审查`（三轮对抗审查的记录）

## 1. 本讲方法要点

1. **可证伪性是准入门槛**。写不出「什么样的实验结果会让我放弃它」，这条假设就不算出生。不能失败的命题没有研究价值，只有修辞价值。
2. **六要素句式（条件–方法–基线–指标–幅度–机制）**：在什么条件下、用什么方法、相对什么基线、在什么指标上、预期多大改善、以及为什么（机制）。六要素齐全的假设天然可被实验直接检验。
3. **AI 是红队，不是枪手**。顺序纪律：人写草稿 → AI 攻击 → 人修订。反过来（AI 生成候选、人挑选）产出的假设大多是同义反复——原文对此有明确警告。
4. **三轮对抗审查**：第一轮可证伪性（能否被实验推翻）、第二轮机制攻击（列出至少两个替代解释，各配一个对照实验）、第三轮审稿人模拟（这条假设会被怎么攻击）。
5. **假设要排序**：优先级 = 信息量（假设成立与否对研究路线的影响）× 成本。排序依据写下来，几个月后才能复盘排序品味。
6. **登记表要带风险备注**：三轮审查的结论汇总进 `风险备注`，它是「带伤上阵」时的知情记录。
7. **已证伪的假设保留不删**。证伪档案有两个用途：防止重复提出同类假设；训练「什么样的假设容易死」的直觉。
8. **基线强度自查**：假设的对手是基线，不是空集。「基线偏弱」会让成立毫无意义——这一步必须在设计阶段自查。

**不建议系统化的部分**：

- **「先发散生成再逐条收紧」的灵感环节**。属人。原文明确：AI 生成的假设大多是同义反复——因此**本设计不为「AI 批量造假设」提供任何入口**，这是与其他讲不同的一个主动留白。
- **六要素句式的语言打磨**。一句话写得好不好没有结构可言；系统只检查六个字段有没有内容。
- **「这条假设值不值得做」的判断**。优先级排序是人填的；AI 只提供攻击材料。

**关系与公式**：

- `02 差异假设` / `03 可行性冲刺` → `假设登记`：多对多（一条冲刺可能立案多条假设；一条假设的修订史可能跨多次冲刺）。

**样例 1（一条走完三轮、进入待验证的假设——与 G-07 / fs-02 的故事线衔接）**

| 字段 | 值 |
| --- | --- |
| 编号 | H-03 |
| 假设陈述 | 在监管问答数据集上，将文档生效日期作为检索打分的时间衰减项，相对 BM25+通用 LLM 基线，Exact Match 提升 ≥5 个百分点，机制是版本错位样本的检索命中率上升 |
| 条件 / 方法 / 基线 / 指标 / 幅度 / 机制 | 监管问答集 A ／ 时间衰减打分 ／ BM25+通用 LLM ／ Exact Match ／ ≥5 个百分点 ／ 版本错位样本的检索命中率上升 |

| 优先级 / 排序依据 | 4 ／ 成立与否直接决定开题的主方法章节；成本已由 fs-02 证明（单卡 6 小时） |
| 基线强度自查 | 已核对是最强基线（BM25+通用 LLM 即 fs-02 的基线，另核对了两篇近作的最强基线设置） |
| 风险备注 | 第二轮攻击指出替代解释「提升来自数据集先验（时间词在问题里的分布）」——已加对照实验（等难度子集）；第三轮模拟审稿人质疑元数据缺失场景，见第 06 讲样例 1 的局限 |
| 状态 | 已收紧待验证 |

**样例 2（一条已证伪的假设——保留，不删）**

| 字段 | 值 |
| --- | --- |
| 编号 | H-01 |
| 假设陈述 | 在医疗去标识化任务上，联邦训练相对单机构训练 F1 提升 ≥8 个百分点 |
| 状态 | 已证伪 |
| 证伪记录 | 被 fs-01 的可行性探针证伪：跨机构数据不可出域的合规约束下，本轮无法构造任何真实联合训练配置；「提升幅度」不可测量——**证伪的是可测性，不是效果** |
| 基线强度自查 | 未核对（假设死亡于更早的阶段） |
| 处置备注 | 保留此条：未来任何「联邦 + 敏感数据」类假设提出时，先读此条与 `02 空白三问` 的负结果线索 |

两张样例说明什么算「填得好」：**`可证伪条件` 里出现了「对照组」字样**——它说明写的人已经在想实验了，而不是在写愿望；样例 2 的证伪记录写清了「证伪的是可测性」，这比「失败了」三个字多一层信息：它把失败模式归类了。

## 5. 自动化设计

| 名称 | 触发器 | 条件 | 动作 | 防的坑 |
| --- | --- | --- | --- | --- |
| 证伪即入档 | `field_equals`（`状态` = 已证伪） | —— | `add_comment`（“已证伪假设保留不删：请补齐证伪记录（被哪个实验、什么结果），它是防止重复提出同类假设的资产”）+ `set_field`（`优先级` = 1，让它在排序里沉底但仍在） | 失败被悄悄删除，重复踩坑 |
| 缺证伪条件不放行 | `record_created` on `假设登记` | `可证伪条件` 为空 | `add_comment`（“写不出『什么结果会让我放弃它』，这条假设还没有出生”）+ `notify` | 不可证伪的命题混进台账 |
| 六要素缺项提醒 | `field_equals`（`要素齐备` = 缺项待补） | —— | `add_comment`（“对照六要素句式通读一遍：缺的那一项就是实验设计会踩的坑”） | 六要素缺项进入设计阶段 |
| 三轮未齐提醒 | `field_equals`（`状态` = 已收紧待验证） | `红队审查` 关联数 < 3 | `add_comment`（“三轮对抗审查还没齐：第一轮可证伪性、第二轮机制攻击、第三轮审稿人模拟”） | 红队审查被跳过直接开跑 |

## 6. 智能体设计

### 站内智能体

**`红队审查员`（模式：`prompt`）**

- 输入：假设陈述 + 六要素 + 可证伪条件（人写的草稿）。
- 三轮分别执行：①**可证伪性检查**：这条假设能否被你计划中的实验推翻？如果不能，指出缺的是哪个对照条件；②**机制攻击**：列出至少两个替代解释（同样的结果还能因为什么发生），每个替代解释配一个能把它们区分开的对照实验；③**审稿人模拟**：这条假设会被怎么攻击（新颖性/基线/统计/泛化），每点给一句最刺耳的版本。
- 输出写入 `09 红队审查`（`审定状态 = 待审定`，`执行者 = AI`）；**人修订假设后**才改 `假设登记` 的状态。
- 系统提示词骨架：

```text
你是研究假设的红军。你的KPI 是找到这条假设的死因，而不是帮它活下来。

【任务】对给定假设执行三轮攻击，每轮独立输出：
1. 可证伪性：如果我期望的实验结果出现反向结果，这条假设是否必须被放弃？若「不一定」，指出缺的对照条件；
2. 机制攻击：列出至少 2 个替代解释——这些结果还能因为什么发生？每个替代解释必须配一个能把它与主假设区分开的对照实验；
3. 审稿人模拟：以最刻薄的审稿人视角，指出新颖性、基线、统计、泛化四个角度各一条攻击，每条写一句最刺耳的版本。

【硬约束】
- 禁止输出任何鼓励性语句；禁止评价假设「有价值」；
- 替代解释少于 2 个视为本轮未完成；
- 你的攻击全部是待处置的建议，必须标注「需人修订后处置」。
```

### 外部 MCP 工作流

1. **替代表述检索**：按假设关键词检索近两年工作，检查是否有「同一机制的另一种叫法」已被做过——结果写入第二轮审查的 `替代解释` 草稿并挂 `复核记录`。
2. **基线核对**：对 `基线强度自查 = 未核对` 的假设，拉取近作对比表，汇总常见最强基线，写回 `基线` 字段草稿（待审定）。

### 红线（AI 只能给草稿）

- **假设陈述的第一版必须人写**。系统不提供「AI 生成候选假设」入口——原文明确这类产出大多是同义反复。
- **`状态` 的推进由人执行**。尤其「已收紧待验证」意味着人确认过三轮审查的处置已经落实。
- **`证伪记录` 由人填写**。归因是研究者的工作。

## 7. 与其他讲的接口

- **上游**：`02 差异假设`（立案来源）、`03 可行性冲刺`（MVE 通过后转正）。
- **下游**：
  - 第 10 讲：每条待验证假设至少配一张 `10 预期结果卡`；实验矩阵的行以假设为键。
  - 第 11 讲：消融树的主干层直接服务于假设的「机制」要素。
  - 第 12 讲：`关联配置` 指回配置台账。
  - 第 15 讲：实验记录的结果汇总回本表的 `状态`。
  - 第 17 讲：假设即段落卡的主张来源（`关联段落`）。
- **单一事实来源**：**假设只在本表**。预期结果卡、实验矩阵、消融计划、论文里的假设陈述都通过关联或回填指向它，不复制假设原文。

## 8. 分期实施与验收

### P0（纯配置，零代码）

1. 建 `假设登记`（自动编号 `H-`）与 `09 红队审查`。
2. 建四个本表视图：假设看板 / 要素缺项 / 待验证 / 已证伪档案（只读）/ 基线自欺检查 / 三轮未齐；在 `09 红队审查` 上建 `未处置`。
3. 建表单视图 `立案`。
4. 建四条自动化：证伪即入档 / 缺证伪条件不放行 / 六要素缺项提醒 / 三轮未齐提醒。
5. 建站内智能体 `红队审查员`，提示词入 `提示词库`。
6. `关联配置` / `关联段落` 两个关联字段先建空关联（指向的表在第 12 / 17 讲建成后启用）。

### P1（少量增强）

| 需求 | 说明 | 建议落点 |

| 基线与文献库挂钩 | 现在 `基线` 是文本，理想是关联「提供了该基线的文献」 | `基线` 改为关联 `文献库` + 保留文本备注 |

### P2（可选）

- 证伪档案的「死因分类」统计：对 `证伪记录` 做文本聚类，输出「什么样的假设容易死」的年度报告（第 24 讲消费）。
- 与外部工具联动：把 `已收紧待验证` 的假设导出为实验计划模板。

### 验收标准

1. 每条 `假设登记` 记录的 `可证伪条件` 非空，且文本里能指出「什么结果 → 放弃」。
2. `要素缺项` 视图里的记录都在一周内被补齐或明确降级。
3. 每条 `状态 = 已收紧待验证` 的假设在 `09 红队审查` 里三个轮次都有记录，且每条「需修订」都有处置动作。
4. `已证伪档案` 视图只读有效（无法编辑），且每条都有证伪记录。
5. `基线自欺检查` 视图随着时间收缩（基线在立案阶段就被核对）。
6. 抽查一条假设的 `风险备注`，能回答「它带着什么伤上阵、为什么可以接受」。

## 9. 与原文的偏差说明

| 偏差 | 原文做法 | 本设计做法 | 理由 |
| --- | --- | --- | --- |
| 六要素的承载 | 一句话里的六个成分 | 一句话 + 六个拆解字段双轨 | 一句话给人读，六个字段给筛选与自查（`要素缺项` 视图）——把「通读检查无缺失」变成可筛选条件 |
| AI 的参与方式 | 红队，不生成候选 | 不建「AI 生成假设」入口；`红队审查员` 只攻击 | 原文明确 AI 生成的假设多为同义反复；用「没有入口」来保证这条纪律 |
| 三轮审查的载体 | 流程描述 | 表 `09 红队审查`（一轮一行，含处置与执行者） | 轮次是否齐、处置是否落实，需要可统计的记录；「执行者」字段保留 AI / 人的分工证据 |
| 已证伪的处理 | 保留不删（正文强调） | `已证伪档案` 只读视图 + `优先级 = 1` 沉底 + `证伪记录` 必填 | 「保留」需要一个防误删的机制与一个能被读到的位置 |
| 基线自查 | 设计阶段的提醒 | `基线强度自查` 单选 + `基线自欺检查` 视图 | 「对手是基线不是空集」这句话要有一个会被日常看到的落点 |
