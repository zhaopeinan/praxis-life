## 怎么跑

```bash
DUOWEI_BASE_URL=http://47.122.123.1 \
DUOWEI_TOKEN=dwa_xxx \
npx tsx ResearchModule/build/build-base.mts
```

| 参数 | 作用 |
| --- | --- |
| `--base <名称>` | 目标空间名（默认 `科研方法`） |
| `--create-base` | 空间不存在时新建；**仅管理员令牌可用**，`dwa_` Agent 令牌建库会被拒 |
| `--only k1,k2` | 只构建指定表，key：`prompts` / `matrix` / `hypotheses` / `library` / `runs` |
| `--dry-run` | 写请求只打印不落库；预演时字段/视图的读回走内存影子状态，因此能完整预演出整轮请求清单 |
| `--verify` | 只读回读校验：把线上落库与 spec 声明逐项比对（字段名、类型与属性，视图类型与全部声明配置，自动化，种子），不一致以退出码 1 结束 |

建完之后校验一句就够：

```bash
DUOWEI_BASE_URL=http://47.122.123.1 DUOWEI_TOKEN=dwa_xxx \
  npx tsx ResearchModule/build/build-base.mts --verify
```

校验口径来自构建器自身的 spec，不是另抄一份期望值表，所以加了新表/新字段以后这条命令自动跟着覆盖。

## 前置条件

1. 管理端先建好空空间（默认名 `科研方法`）——Agent 令牌不能建库。
2. 管理端「Agent 管理」注册并批准一个 Agent，给这个空间授 **editor**，把返回的 `dwa_…` 令牌配到 `DUOWEI_TOKEN`。
3. 五张表都在同一个库里：关联字段跨库会失效，所以不要拆成多个空间建。

### 本地实例（2026-10-19）

先在本机临时实例上验证过同一套结果，并借这次发现并修掉了「首视图非 grid 被建表接口写死成 grid」的缺陷。


## 四处实现约定

- **视图类型不可改**：`PATCH /api/views/:id` 只收 name 与 config，建表接口的默认视图写死 grid。
  所以建表用占位视图名，真实视图按声明类型另建后删占位；已存在但类型不符的视图按声明类型重建（新建 → 收敛配置 → 删旧），重建后视图排在最后一位（接口没有调整视图顺序的能力）。
- **字段名相同不代表属性落库**：服务端对不认识的字段属性是**静默忽略**，不报错。
  所以已存在的字段也会比对 `unique` / 选项 / 编号前缀 / 公式 / 关联目标，不一致就 PATCH 收敛（日志里打「字段属性收敛」）。
- **dry-run 用内存影子状态**：预演不落库，但后续步骤要读回刚建的表/字段/视图，拿假 id 查真实例只会 404。
  所以 `--dry-run` 下建表、建字段、建视图、删视图、建记录都在内存影子里同步变更，整轮预演能走完并打印出全部写请求。
- **建不了的半成品会报告，不静默降级**：`run_agent` 动作需要管理员先建站内智能体、`notify` 需要先指定接收人、OR 语义条件只能用 AND 近似，
  这类提醒每次都报（不只在首次创建时报），末尾「待人工/后续处理」列出的条数在重跑之间稳定。
