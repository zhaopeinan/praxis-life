## 2. 能力地图（按「是否真 Agent」分层）

飞书文档里「AI」混了三类东西，落地时应拆开：

### A. 智能体本体（真正的 Agent）

对应文章：搭建智能体、配置触发器、使用智能体、字段捷径中用智能体、工作流智能体节点、应用关联、仪表盘智能体组件。

**配置面（创建时要配齐的模块）：**

1. **基础信息**：名称、头像/描述、所属 base  
2. **任务指令**：系统提示词 / 角色目标（可带变量）  
3. **触发器**  
   - 即时消息（对标飞书消息；自托管可改为 Webhook / 内部聊天）  
   - 定时（复用现有 `schedule` cron）  
   - 评论触发  
   - 记录新增 / 修改 / 删除  
4. **工具（Tools）**：让 Agent 调表能力——查记录、写字段、建记录、跑汇总、发通知、调 HTTP 等（DuoWei 已有 MCP/REST 可直接挂）  
5. **知识库**：上传文档 / 选表数据作检索上下文（RAG）——主产品未做  
6. **记忆**：会话记忆 / 跨次记忆（短期 context + 可选长期 store）  
7. **运行与分享**：试跑、权限、分享给协作者 / 嵌入入口  

**消费面（用户从哪里用到 Agent）：**

| 入口 | 行为 |
|------|------|
| 多维表格内对话 | 对当前 base/表提问、改数 |
| 即时消息 / Bot | 会话触发 Agent |
| 应用模式 | 关联某个智能体，应用内聊天 |
| 仪表盘「智能体组件」 | 看板旁嵌对话或一键生成结论 |
| 字段捷径 | 单元格变更时调用指定智能体填值 |
| 工作流「智能体节点」 | 流程里跑一轮 Agent，输出进下游节点 |

### B. 工作流内嵌的 AI Agent 节点（Agent 子图）

对应：`使用工作流的 AI Agent 节点`。

结构不是「一个黑盒」，而是可编排子节点：

- **AI Agent 主节点**：编排循环（思考 → 调工具 → 再思考）  
- **大模型子节点**：选模型、温度、提示词  
- **记忆子节点**：读写会话/业务记忆  
- **工具子节点**：绑定表操作 / HTTP / 通知等  

案例文档给出的典型场景：项目进展查询、自动生成周报。

另有**轻量 AI 节点**（不一定是完整 Agent）：

- AI 生成文本  
- AI 分析节点  
- AI 分类节点  

### C. 「带 AI 的编辑能力」（多半是单次 LLM 调用，不是完整 Agent）

| 能力 | 文档要点 | 对 DuoWei 的含义 |
|------|----------|------------------|
| AI 字段捷径 | 分类 / 翻译 / 智能标签 / 信息提取 / 总结 / 自定义填充 / 第三方 / DeepSeek | 字段类型或「生成管道」：输入列 → LLM → 写回目标列 |
| 公式字段捷径 | 偏模板化公式生成 | 可弱化为「公式助手」提示，不必上 Agent |
| AI 侧边栏 | 表内常驻对话 | UI 壳 + 后端 LLM/工具循环 |
| AI 问数与分析 | NL → 查数/出图/结论 | 比现有规则问数更深：生成查询计划、图表建议 |
| AI 搭建业务系统 / 数据表 | 一句话生成多表结构 | Schema 生成器 |
| AI 配置高级权限 | NL → ACL 规则 | 规则草稿 + 人工确认 |
| AI 生成自定义页面 | NL → 页面/布局 | 应用模式页面生成 |
| 智能搭建工作流 / 仪表盘 | NL → 流程或图表配置 | 配置草稿 |
| 智能总结单条记录 | 详情页摘要 | 单记录 LLM |
| 仪表盘 AI 组件 | 特殊图表 + AI 总结类组件 | 部分是图表类型，部分是生成文案 |

## 3. 建议的 DuoWei「Agent 子系统」切分

单独摘出后，建议独立模块（甚至独立包/服务），主仓只留 hook：

```
duowei-agent/
  agents/          # 智能体 CRUD：指令、工具白名单、知识库引用、记忆策略
  runtime/         # 推理循环：LLM provider 适配 + tool calling
  triggers/        # 消息/定时/评论/记录事件 → 入队跑 Agent
  surfaces/        # 侧边栏、字段捷径、仪表盘组件、应用关联、工作流节点 的 API
  providers/       # OpenAI-compatible / 本地模型；密钥与配额（自管，非飞书付费）
```

主产品已有、可直接复用为 **Tools**：

- REST / MCP（数据面）：`get_table`、`query_records`、表/字段/记录/视图 CRUD、CSV、评论…  
- REST / MCP（控制面，已齐）：ACL、成员、自动化、工作流/审批/SLA/代理、仪表盘、公开/单记录分享、详情页、base 设置、通知、同步任务、插件市场、附件上传、记录关注…  
- 自动化动作：通知、HTTP、邮件、评论  
- 仪表盘聚合 API（问数出图时用）

主产品**缺失、Agent 专属**要新做：

1. Agent 配置实体与权限  
2. LLM Provider 抽象与密钥管理（租户自备 Key，不做飞书额度）  
3. Tool-calling 运行时与审计日志  
4. 知识库入库 / 检索（可先做「选表当知识」再做文档上传）  
5. 记忆存储  
6. 各 Surface 的 UI

## 4. 推荐落地分期（不含付费）

### P0 — Agent MVP（先证明「能配、能跑、能改表」）—— ✅ 已落地（2026-10-10）

- [x] Agent 实体：名称、指令、工具白名单、绑定 base  
- [x] Runtime：OpenAI-compatible Chat Completions + function/tools  
- [x] 工具集：只读查询 + 写记录/改字段（走现有 Store，带 ACL）  
- [x] 入口 ①：表内对话（替换/增强现有「智能问答」为真 LLM+tools）  
- [x] 入口 ②：定时触发（复用 schedule）  
- [x] 运行日志与失败重试  

**落地位置**

| 层 | 文件 / 接口 |
|----|-------------|
| 数据层 | `src/types.ts`（`LlmAgent` / `LlmAgentRun` / `LlmAgentToolId`）；Store 内置智能体与运行日志表 |
| 模型适配 | `src/llm.ts`（OpenAI 兼容 Chat Completions；provider 自配 baseUrl / model / apiKey） |
| 运行时 | `src/agent.ts`（工具循环、per-trigger 运行日志、工具白名单与绑定空间校验） |
| 装配 | `src/agent-runtime.ts`（`configureAgentRuntime`，自动化动作 `run_agent` 也走这里） |
| REST | `GET/POST /api/agents`、`PATCH/DELETE /api/agents/:agentId`、`POST /api/agents/:agentId/run`、`GET /api/agent-runs`、`POST /api/agent-runs/:runId/retry`、`GET /api/tables/:tableId/agents`、`POST /api/tables/:tableId/agent-chat` |
| 工具集 | `list_tables`、`get_table_schema`、`query_records`、`create_record`、`update_record`、`add_comment`——全部以触发者身份做空间角色与表级行列权限校验；智能体写入不触发自动化（避免互相触发） |
| 前端 | 「智能体管理」弹窗（配置/试跑/运行记录）+ 表内助手面板的 LLM 对话 |

**验收：** 「每日 9 点汇总状态为进行中的需求，写进日报表并评论」可配置跑通——定时自动化挂 `run_agent` 动作，智能体开 `query_records` + `create_record` + `add_comment` 即满足；试跑与定时两条路径共用同一运行时与运行日志。

## 6. 结论（给立项用）

1. **付费不做**；Agent 做的是「自备模型 + 工具循环 + 多入口」，不是飞书套餐。  
2. **「智能体」≠ 全部 AI**：真正 Agent = 指令 + 工具 +（可选）知识库/记忆 + 触发器 + 多 Surface；其余多为单次 LLM 或配置生成。  
3. **DuoWei 最大优势**：MCP/REST 工具面已经齐，P0 应优先接 Runtime，而不是先堆知识库。  
4. **建议物理隔离**：`docs/AGENT_SCOPE.md`（本文）+ 后续独立 `agent` 包，避免主产品 STATUS 再被 LLM 需求拖成 partial。  

若下一步开工，建议直接按 **P0 MVP** 开 `/goal`。
